### 四条实测结论
1. **交付轨迹 = 原始 RTK 的逐帧搬运。** 用固定解帧拟合"本机投影 ENU → 交付 ENU"相似变换得
   `scale=0.999996 / yaw=+0.0001° / t≈0`（同一坐标系），再比位置：**中位 1.0 mm、p95 2.3 mm**。
   ⇒ 位置通道零融合，只有姿态是 KISS-ICP。这直接解释评审为什么说"**rtk 轨迹**的置信度"。
2. **锯齿是真的。** `754.5–758.5 s` 交付逐帧步长 `0.250 0.574 0.116 0.605 0.115 0.593 0.078 0.602 …`，
   同段原始 RTK 是均匀 `−0.25 −0.29 −0.27 −0.27`。二阶差分沿航向分量的 **lag-1 自相关 = −0.864**
   （降级段 −0.899）；改用插值后 −0.142 / +0.036 ⇒ 锯齿消失。
   抖动 p99 **0.611 m**、最大隐含速度 **17.4 m/s**（RTK 自身 p99 只 5.31 m/s）。
3. **根因 = 最近邻赋值带走的时间未对齐。** `|Δt|` 中位 **29.9 ms** × 4.24 m/s ≈ **12.6 cm**，
   实测"偏离同一时刻 RTK 插值"**12.8 cm** —— 两个数字闭合。
   而 README §4 自己就写着"最近样本时差中位 42–48 ms"：**知道却没据此改成插值**。
4. **组委会图上那道"楔形"是基准自身的产物。** 复现图逐像素吻合；楔形斜率实测 0.30 == 指向
   `(lat 0, lon 0)` 的方向 `dN/dE = 0.2975`；把 3 帧零岛从基准去掉 → 楔形消失。
   那 3 帧 `status=-1`、`cov=0`、`alt=0.000`，是无解占位。

### 踩的坑（本轮新增）
- **rosbags API**：`Reader` 没有 `.deserialize`，要用 `get_typestore(Stores.ROS1_NOETIC).deserialize_ros1`。
- **`/qx/evk/heading` 是 `std_msgs/Float64`，无 `header`** → 必须 `getattr` 兜底，否则全条链崩在第 20 行。
- **托管 venv 无 scipy** → Savitzky-Golay 手写（`np.vander` 建 Vandermonde，取 `pinv(V)[0]` 作卷积核）。
- **`E:/software` 的 matplotlib 与 numpy 2.4.2 冲突**（`_multiarray_umath` ImportError）→ 用托管 venv。
- **比较保真度必须"同一时刻对齐"**：拿"交付帧 vs 最近的 RTK 样本"比会把时差算成误差（假 12.5 cm）；
  换成 `np.interp` 到同一时刻才干净。
- **别急着下"锯齿 = 最近邻 Δj 跳变"的结论**：实测 `Δj=+1` 占 **98.8%**，只有 0.6% 是 0 或 2，
  解释不了整条锯齿。真正的机理是**时差值本身**（取最近样本⇒位置被量化到 30 ms 前的状态）。

## 终审漏检归因（boss 问责"提交前为什么没查出来"）

**认账**：提交前那轮终审"全部 PASS"，但漏掉的是**整个判据类别**，不是某个数。
- 当时查的是 **合规性**（体积/命名/时长/schema/类别声明/点数）+ **自洽性**（成员逐字节对拍、
  stamp 单调、三份轨迹互一致）。**没有任何一条在问"轨迹本身合理吗"** —— 没有逐帧步长、
  没有隐含速度、没有 lag-1 自相关、没有"交付物 vs 原始 bag"的跨源对比。
- 有一条信号**看到了但放过了**：`README.md` §1.7 第 144 行写着"**不做低通平滑**，
  因为 RTK 逐帧位置比里程计平滑 20 倍"。读到后当成"作者有理由的决策"，**没当成待验证断言**。
  而那句话恰恰漏掉了"把 RTK 搬到 LiDAR 帧"这一步 —— 锯齿就是这步产生的。
- 元规则：**"交付物内部自洽" ≠ "交付物正确"**。终审必须至少有一条跨源判据（原始 bag → 交付物）。
