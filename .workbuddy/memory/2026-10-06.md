# 2026-10-06 — 第二十一轮：region-level starvation（判死，但挖出排序层的结构性缺陷）

## 做了什么

按 boss 规格做了 **region 级饥饿债务**最小原型（不做「前 N 个目标必须是房间」的硬编码）：

- **对象 = 地图上固定 2 m 的格**（`region_cell_m`），跑程内 id 不变。这是与
  §14 的 patch（每帧重切、无身份）、§23–25 的 candidate 唯一的、也是关键的区别。
- 每格状态：`unfin_m2` / `last_progress_t` / `last_enter_t` / `att_t` / `prog_m2`；
  四档 `never / brief / starved / done`。
- 两种量纲两个 arm：`mul`（`base×(1+λd̂)`，与 patch debt 同形）／`add`（boss 的 `U=U_base+λD`）。
- 参数：`region_lambda`(0) / `region_mode`("mul") / `region_min_m2`(0.60) / `region_done_m2`(0.40) /
  `region_brief_m2`(1.0) / `region_grace_s`(25) / `region_idle_cap_s`(120) / `region_cell_m`(2.0)。
- 仪器：`region_hist`（Gate A）、`region_switches`（Gate B/C）、`pick_stats` 的
  `r_*` / `n_region_*` / `rsw_*` 字段；`out/_region_gate.py`（**只读产物**的三关表）。

## 结果（cap_v19，1224 帧，10 个处理臂，全部 replay）

| 关 | 结果 |

| B 改写率 | **不过**：mul λ=1 **2/14=14%**、λ=3 **3/14=21%**；add λ=1 **0/14**（逐字节 no-op）；门限提到 2.0 m² 后跌到 **1/14=7%** |

## ★★ 本轮最重要的一条（跨轮有效）

`az_span_med = 157°`。

⇒ 任何**排序层**改动只要改变榜首，位移必然米级到十几米。**§23/§24/§25 与本轮是同一个原因**：

`az_span_med` 并写进记录**。

判死刑条件：这条线在 `sep_min_med ≲ 5 m` 之前不再重启。

## 自我纠错（记下来）

1. `mul` 模式我故意不乘未完成量（理由「未完成量已在 base 里」）—— **实测证伪**：

3. Gate B 的分母要用**逐帧目标序列**，不要用策略内部计数 —— 两者实测不一致。

# 第二十二轮（同日）：Region-first → point-second（§28 / 交接 §18）

## 做了什么

按 boss 规格做**两级决策**最小原型（**不做②显式分配**）：

- **第一级 = 候选点的 complete-linkage 簇**（`rfirst_link_m = 3.0 m`，簇内任意两点 ≤ link）。
  complete 而非 single：单链会把"一串相邻点"从屋这头牵到那头（= §23 那次 18.12 m 的机制）。
- **第二级 = 簇内用原来的点键**。两级接法只是一行前缀：`_ckey(crank, key)`。
- **区域分只用几何量**：`未完成面积(簇内各点 disc 的**并集**) / (1 + 簇到起点的最近距离)`。
  没有饥饿、没有时钟、没有新旋钮。`rfirst_score_mode="maxpoint"` 是聚类层自己的对照
  （必须复现基准 pick）。
- `rfirst = False` 默认，精确 no-op；`span max` = 点层位移的**硬上界**（构造保证）。

## 结果（三采集 × 四臂，目标落在房间框内的逐帧比例）

| 采集 | F0（现状 K=4） | F2（+local） | **R0（rfirst）** | R2（+local） |
|---|---|---|---|---|
| v19 | 11.0%（135/1224） | 10.2% | **4.4%（54）** | 16.4%（201） |
| v19r1 | 12.7%（146/1150） | 21.4% | **2.8%（32）** | 2.8%（32） |
| v19r2 | 35.1%（346/985） | 29.2% | **17.9%（176）** | 17.9%（176） |

- **Gate 4 结构三条全过**：`med #reg` 5.0–7.0（`P(≥2)=1.00`）、`span max` 2.9–3.0 ≤ 3.0、
  点级位移由构造 ≤ span ⇒ **跨区不可能**。
- **但区域层把目标推离房间，3/3 方向一致**（−6.7 / −9.9 / −17.2 个百分点）。
- **根因**：`fallthrough` = **0.25–0.50** —— 区域层排第一的簇 1/4~1/2 概率**走不到**，
  选择被 fallback 接管 = 把区域选择随机化了。
- **`local_u` 在真局部里仍然没用**：3 采集 = 1 好 / 1 改而无效 / 1 零作用（v19r2 的 R0 与 R2
  md5 相同）⇒ 按预先约定**整族封存**（默认值全 0，代码与 case 23–28 留作检验台）。

## ★★ 本轮最该记住的坑：对照臂有没有真的关掉？

`--arms "F0:rfirst=False"` 里的 `False` **被解析成字符串**（`_parse_arm` 的 `int→float→str` 链
生不出 bool）⇒ `bool("False") == True` ⇒ **本该当对照的那一臂开着新功能跑完整场**。
无报错、无警告。指纹：`F0/R0/R2` 三臂 md5 完全相同。

根因是**三个参数入口类型推断不一致**（`--explore-set`/`--set` 用 `literal_eval` ✓，`--arms` ✗）。
已统一到 **`r2slam/overrides.py`** + 五个布尔构造参数改走 `as_bool`。测试 **case 31** 钉住。

**新硬规则**：**任何 A/B 先看对照臂与基准的产物 md5 是否一致**（`out/_region_gate.py` 第 0 段）。

## 状态

- 默认 `rfirst=False`，出包未动（仍是 v6 那份）。测试 **31 项全过**（新增 case 30/31）。
- 判死与重开条件：这一版 `rfirst` 不再原样重启；重开前提是 **fallthrough 被消灭**，
  验收仍用「目标落在房间框内」，**三采集判方向、不看单跑**。

1. **给区域层加可达性**（唯一有仪器直接支撑）：把「簇内有没有可规划的点」作为区域分的必要条件，

2. **回到候选集本身**（§17.7 方向 1）。
3. `local_u` 整族：封存。

# 第二十三轮（同日）：region-level reachability gate（§29 / 交接 §19）

## boss 的纪律

**只做 reachability gate**；不碰 `local_u`（除 R2 作诊断）、不调 λ、不跑仿真。
每轮 A/B 第一项：**control arm md5 == baseline md5**。

## 做了什么

区域层加可达性门：每个 region 用**自己的头名**作代表，规划一次；**不可达的 region 排在
所有可达 region 之后**（剔除出竞争，不是扣分）；全不可达时退让并记录。
排序键 = `(0 if routable else 1, -score, ...)`。加**每帧清空的 `_plan_cache`**（gate 规划过的
代表点被 `_plan_first` 命中，免去重复 A\*）。gate 关闭时与 §28 bit-for-bit 相同。
**Gate 5 仪器**：`n_reg`/`n_ok`/`n_bad`/`ungated_head_bad`/`all_bad`。
**case 32** 用**只会拒绝特定点的 stub planner** 钉住四条断言（夹具两房连通，不 fake 造不出不可达）。

## 结果：**假设被自己的实验证伪**

| 采集 | `region_candidates` | `region_reachable` | **`region_unreachable`** | **`top rejected`** |
|---|---|---|---|---|
| v19 | 7.35 | 7.35 | **0.00** | **0.000** |
| v19r1 | 6.77 | 6.77 | **0.00** | **0.000** |
| v19r2 | 5.88 | 5.88 | **0.00** | **0.000** |

`gate_hist` 的 `n_bad` 取值集合 = **`{0}`**（从未非零）。**R0 与 R1 的 md5 三采集全相同**
⇒ gate 一次决策都没改，`fallthrough` 原封不动。
**区域层的簇代表点在这套地图上永远可达 —— 可达性从来不是失败的原因。**

## ★ 真凶：`survey` 过滤器改写了候选表的头名

`rfirst_picks` 新增 `path` 字段后：成功 pick **17** 次，**17/17 全部来自 `survey` 路径**；
`fallthrough` **6** 次，**6/6 也都在 survey 上**（rank 1,1,1,2,4,1）。

```text
gather(全部候选) ─► 算 region rank + 排序
      ↓
new_c = 按**候选点**过滤（离 survey_stop ≤2 m 的候选删掉）  ← 第一名 region 的候选可能整体被删
      ↓
_plan_first 走 new_c —— 头名已不是区域层排第一的（rank 没重算）
```

极端形态：`t=263 s` 那次 `n_cand=5` 而**头名 rank=4**（前四个 region 的候选全被过滤）。

⇒ **§18.2 的结论要修正一句**：不是"排第一的区域不可达"，而是"**区域排序的输入被下游的
`survey` 过滤器改写了**"。前者指向可达性（实测不存在），后者指向**排序与过滤的先后**。

## 下一步（待 boss 拍）

**把 `survey` 过滤挪到区域排序之前**（在最终候选集上算 rank）。
不改候选生成（`fresh`/`patch_points`/`sweep_cands_per_patch`/`sweep_stop_spread_m` 全不动），
只改"先过滤还是先排序"。预期 `fallthrough → 0` 由构造保证；要量的风险是 survey 落点分布
（§12 的两段式勘察）。备选：在 `new_c` 上重算一次 rank。

## 状态

默认 `rfirst_gate=False`，行为与 §28 之后一致，出包未动（v6）。测试 **32 项全过**。
本轮只跑 replay。`_note_pick_size` 的时间戳从 `_debt_t`（关掉时恒 0）改成**本帧 stamp** ——
同一类仪器坑第三次出现，已在代码里写明。

# 第二十四轮（同日）：`survey` 约束前移到 region ranking 之前（§30 / 交接 §20）

## boss 的边界（锁死）

只调整 **survey filter 与 region ranking 的先后**；不动 `fresh` / `patch_points` /
`sweep_cands_per_patch` / `sweep_stop_spread_m` / reachability gate / `rfirst` / `rfirst_gate` /
planner。**明确否决"过滤后重算 rank"**（那是"先决定谁赢、再删掉输的、再决定一次"）。
目标：`gather → survey 约束过滤 → region ranking → point ranking → planner`。

## 实现

`gather(labels, min_area, keep=None)`：`keep` 在**候选进 `rows` 之前**生效 ⇒ 聚类与排序
从一开始只看见有资格的候选。约束本身一个字节没改，只改应用时机。无 stops 时复用同一份表。

## ★ 被测试当场抓住的等价性错误

`sweep_survey=False` 时旧代码 `new_c=[]` ⇒ `survey_pick=False`；我第一版写 `bool(first_c)`
⇒ **True** ⇒ **丢掉 patch 锁**，第一个 patch 还有地板就开新的。**case 17** 抓住。
修：`survey_pick = bool(first_c) if self.sweep_survey else False`。
**教训：把"过滤"从后置步骤挪进生成函数时，"过滤后非空"这个谓词必须重新定义** ——
它原来隐含了"过滤有没有启用"这层信息。

## 验收（三采集，全部达成）

| 验收 | 读数 |
|---|---|
| **C 对照臂 md5** | `F0` 三采集与改动前**完全相同** ⇒ **只改了顺序，没改语义** |
| **A 机制** | `head rank != 0` = **0 次**；`first_head_rank_t = −1`（从未发生） |
| **B fallthrough** | `off-rank picks` = **0 次**、`fallthrough = 0.0`；18/14/7 次 pick **逐次**全 `(survey, rank 0)`。对照 §29：v19 原是 17 次里 **6 次 off-rank（0.353）**，一次 `n_cand=5` 头名 rank=4 |
| **D 不扩大** | 只跑短 + 全量 replay，**没跑仿真** |

**决策变化**：目标不同 439/1224、188/1150、629/985；首次分歧 t=157/192/71 s。
**逐帧「目标在房间框内」**：4.4%→**22.7%**、2.8%→**13.7%**、17.9%→**28.0%**（方向一致）。
**⚠️ 这不是覆盖率，不能读成效率提升**（影子重放测不了覆盖）。它只说明**区域层排序第一次
真正作用在最终候选表上**。
