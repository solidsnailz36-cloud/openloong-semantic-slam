# 第三十二轮：`V/(1+d)` vs NBV 式 `V·exp(-λd)` 的重排序 A/B（设计文档 §38 / 交接 §28）

**boss 拍板**：`1 > 3 > 2`。先做评分函数 A/B（本节），再补 fallback，`shadow` 升级押后。
并明确要求：A/B 只改评分函数、其他冻结；看三件事（top-1 是否改变 / 改变后是否选了更远但更大的 /
累计收益）；特别要抽"被拒绝的高价值远目标"的 case 出来看地图。

## 性质：重排序，不是重跑

不接 planner、不跑仿真 ⇒ **测不到覆盖率**。它测的是**评分函数能否在同一批候选上区分出
高价值远目标**；不能读成"改成 B 就会更好"。

两个候选池（都来自**实测到过的位姿**，不是几何模拟）：
- `self` = 该跑次未来 120 s 真的到过的位姿（严格些，但后期 V 会塌）
- `all`  = 8 次跑汇集的位姿库（210 格，带未来信息，是**上界**）

## 先修一个会让 λ 排序失真的缺陷

`V(c,t) = Σ_r w_r(t)·A_new(c,t,r)`。**第一版把 `A_new` 取成"该位姿被参观那一帧的实测新增"，
与 t 无关** ⇒ 同一个高价值格在每个决策点**全额付款** ⇒ "永远朝全场最高值格走"看起来最优：
λ=0.05 时 87 个决策点只选出 **3 个不同目标格**（塌缩），ΣV 只有 1.34 —— **塌缩被误读成差**。

修法：`_traverse_obs.py --dump-cells` 落盘**格级首见表**（每格首次被看到的帧号；两个 int 数组
总长 = `ground_ever` 格数 ≈ 2–3 万，等于免费），`V` 改由它按**决策点所在跑次自己的时间线**结算：
**看过的格此后记 0**。

校准不变（IoU `0.9855/0.8481/0.9866…`，与 §32 逐位相同）；修正生效的指纹：
**"改变但价值相同"的平局从常见变成 0.0%**（动态 V 是连续量，不再有并列格）。

## 结果

**改变率**（分母 = 决策点数）：λ=0.1 时 `all` **19.5%（17/87）**、`self` **24.7%（20/81）**。

**改变的性质 —— 单调分层（最硬的一条）**：

| λ | `self` 更好/平/更差 | `all` 更好/平/更差 |
|---|---|---|
| 0.05 | **100%** / 0 / 0 | **100%** / 0 / 0 |
| 0.10 | **100%** / 0 / 0 | **100%** / 0 / 0 |
| 0.15 | 79/0/21 | 69/0/31 |
| 0.20 | 50/0/50 | 36/0/64 |
| 0.30 | 25/0/75 | 5/0/95 |
| 0.50 | 0/0/**100** | 0/0/**100** |

**价值捕获率 `V/V*`（"看错 vs 走不动"的直接度量）**：

| 评分 | `all` 均值 | `<0.5` 占比 | 选中距离 | oracle 距离 |
|---|---|---|---|---|
| **A: V/(1+d)** | **0.857** | **18.4%** | 7.35 m | 8.52 m |
| B λ=0.05 | **0.995** | 0.0% | 8.12 | 8.52 |
| B λ=0.10 | **0.963** | 0.0% | 7.94 | 8.52 |
| B λ=0.15 | 0.894 | 10.3% | 6.80 | 8.52 |
| B λ=0.20 | **0.840** | 17.2% | 6.18 | 8.52 |
| B λ=0.50 | 0.404 | 67.8% | 1.71 | 8.52 |

**分水岭 λ ≈ 0.18**（B(0.2) 已比 A 略差）。A 的等效衰减 `λ_eff=ln(1+d)/d` 中位 **0.281**，
但 A 的捕获率（0.857）**高于** B(0.3)（0.708）⇒ **A 不是"λ 太大"，是另一种形状**：
`1/(1+d)` 在 d<1 m 极硬（d=1 只剩 0.50），远处反而比指数松（d=10 是 0.09 vs λ=0.3 的 0.05）。

**机制（不是普遍偏置，是 18% 决策点上的灾难性偏离）**：

| A 的 V/V* | 决策点 | A 选中距离 | oracle 距离 | 距倍 | 值倍 |
|---|---|---|---|---|---|
| **差 (<0.5)** | **16（18.4%）** | **0.80 m** | **7.68 m** | **0.10×** | **0.33×** |
| 中 (0.5-0.9) | 8 | 4.79 | 7.53 | 0.64× | 0.82× |
| 好 (>=0.9) | 63（72%） | 9.28 | 9.28 | 1.00× | 1.00× |

## ★ 一条修正 boss 预期的结论：**西侧不是评分造成的**

- `all` 位姿库 210 格，西侧（x<-5）只占 **28.6%（60 格）**；
- **A 的 top-1 有 48.3%（42/87）落在西侧** —— **高于基数**；
- **B(λ=0.1) 只把 A 从"非西"改成"西" 3 次（3%）**，反向 **0 次**；
- 被 B 反复选中的西侧格 = **`(-7.5,-2.2)`，38/87 次，V=8.044** —— 正是 §33 那个西侧走廊观察位。

⇒ **`V/(1+d)` 并不回避西侧。** "rf1 从没去西侧"**不能**归因于评分形式。
**与 §34 合起来瓶颈落在候选层**：在线候选是 patch 代表点，一个横跨东西的 111.8 m² patch
只给 1–4 个点且 `score` 全相同，只能用 `cd` 决定方向；而同一评分函数在 210 个候选里
能把 48% 指向西侧。

## 副产品：动态结算本身就把"近的赢"修掉一大半

静态 V（§33）下 A 选中距离中位 **2.24 m**（oracle 8.57）；动态 V 下 **7.35 m**（oracle 8.52）、
**72% 与 oracle 一致** ⇒ **`1/(1+d)` 之所以像"压倒价值"，很大程度上是因为在线那个 `V`
（= patch 未访问面积）从来不结算** —— 近处那个已看过很多遍的大 patch 一直全额计入。
**与 §35/§36 的"对象选错了"是同一件事的两面。**

## 局限（跟着数字一起读）

1. oracle re-ranking，候选带未来信息 ⇒ 不能说"改成 B 就会更好"。
2. `d` 是直线距离（路径长下界）⇒ **偏袒 NBV 式**。
3. **`self` 池后期 V 接近塌陷**（t>p75 时 max V 中位 **0.259 m²**、V>0 候选 **16 个**）⇒ 打折；
   `all` 池不塌（**2.19 m² / 166 个**），结论以 `all` 为准。
4. `A_new` 是实测下界，所有臂共用。
5. **ΣV 累加不可用**（已从输出删掉）：价值已在时间上结算，不同时刻相加无意义。
   改报**目标多样性**：A=13 个、λ=0.05 仅 6 个、λ=0.5 有 30 个 ⇒ **λ 小会让目标塌缩**。

## 状态

没改任何策略代码（只在只读分析工具 `out/_vantage_ab.py` + `_traverse_obs.py` 的新 dump 选项）。
默认 `rfirst=False`/`rfirst_gate=False`，出包未动（v6）。新增 `out/cells_*.npz`（8 份）。

## 先量 Gate（§29 的教训变成流程）

工具 `out/_fallback_probe.py`（只读 frames.csv + summary.json）。
8 次跑合计：**Gate ①（候选为空）`search_turns=67`，全部在 `rf1r3`**。
它在 **86.4 s** 进 search、原地转 66 帧、`60 sectors searched without a usable frontier`
判 done、**99.4 s 结束**（其余 199–278 s），`ground_ever` **202.8 m²** vs rf0r1 的 **282.3**
—— **少看了 80 m²**。

**Gate ② 大多误伤**：`W=30s/eps=0.5` 窗口 433 帧里 **312 帧 drive、|cmd_v| 中位 0.55**
（在开长途、走在已建图地面上）⇒ 按它降级会误伤。
**Gate ③ 才是失效形状**：`W=20s/X=1.0` 窗口 741 帧里 **332 帧 backoff、|cmd_v|=0**。

## 成因精确到一行（加了只增计数器，不改行为）

`rf1r3` t=134.3：`frontier=49 in_range=49 big=49 far=4 after_fu=4 after_bl=0 (bl_places=3)`

**`n_front=49` 而同一帧 `frontier_cells=1207`** —— `_choose_frontier_mask` 之后只剩 49 格
朝向房子内部，**那是最后一片内部边界**。而这 49 格**全部落在 3 个 `_barren_spots` 的
0.6 m 半径内**。黑名单**只追加、不过期、无时间戳**。

## 实现：逐级放宽（不是"降到 frontier"）

**结构性事实**：决策链本身已是降级链
`shadow → sweep → island → frontier → island(last resort) → search → done`，
**frontier 在 search 之前已被问过**（它就是返回 0 候选的那层）
⇒ **「候选为空 ⇒ 降到 frontier」在当前架构下是 no-op。**
新参数 `fb_relax`（默认 0）三级：`min_target_range→0`（偏好）→ `_denied→None`（几何启发式）
→ `_barren_spots→[]`（最强主张）。**只重问 `_pick_target`**（sweep 有 patch 承诺副作用）。

## 结果：机制 100%，价值 0

| | F0 | F3 |
|---|---|---|
| seen / saved / failed | 0/0/0 | **9 / 9 / 0** |
| **search_turns** | 7 | **0** |
| **arrivals** | 6 | **13** |
| F0 逐帧 md5 | **与改动前逐位相同** ✓ | — |

**但救回是假的**：9 次里 **7 次去同一个点 (5.35,3.34)**，`bl_places` **3→11**
—— 抵消了黑名单要防的"同一个角落被选八次"。
**且放宽的第 1、2 级都给 0 个候选**（`rungs=L1:0, L2:0, L3:49*`）
⇒ **那 49 个候选全在黑名单覆盖区内**，清掉后唯一能选的还是死点。

## 结论

那 49 格是最后一片内部边界、全部已被走过且无结果、island 也试过 12 次
⇒ **房子内部真探完了，判 done 是对的，缺陷只是"判得太慢"（60 帧转圈）。**

## 过程错误（要记）

**第一版把放宽顺序写反了**（先清黑名单）。改成"按主张强弱排序"后第 1、2 级给 0、
全部落到第 3 级 —— **结果一样**。（顺序不是原因，`far=4 vs after_bl=0` 才是。）
而我第一版的推理"45 个候选被 min_target_range 滤掉、是没被用过的资源"**是错的**：
它们同样在黑名单里（`L1:0` 就是证据）。
⇒ **"看起来该有资源"的余额，要验证它真的可用。**

## 状态

`fb_relax` 默认 0，F0 md5 逐位相同 ⇒ 精确 no-op。32 项测试全过。出包未动（v6）。
新增 `out/_fallback_probe.py`、`_pick_target` 的 `pick_empty`、replay 的 `fallback` 段。

# 第三十五轮：候选层责任归属实验（设计文档 §41 / 交接 §31）

## 实测：两个都不是

给 replay 加 `--dump-map` / `--dump-map-at PREFIX:SEC,SEC`（直接调策略自己的
`_free_unknown`/`_masks`/`_usable_frontier`，不重写实现）。

`rf1r3` 末帧：**`front 1207, inside 49, facing_out 0`** —— `facing_out` 是 0！
那 1207 格里 **1158 格是被 `acceptable = front & near_reach` 挡掉的（不可达）**。

对照 `rf1r1`：`front 994, inside 269, facing_out 170`。

| | rf1r3 | rf1r1 |
|---|---|---|
| ground 已知可通行 | 186.1 m² | 193.9 m² |
| **reach 机器人可达** | **12.8 m²** | **145.4 m²** |

⇒ 两跑建了同样的图，**可达面积差 11 倍**。而那 173 m² 不可达地面与机器人**属同一
`~obstacle` 分量** ⇒ 隔的是**未解析的门槛，不是墙**。

## `reach` 是一次性崩塌（新增逐帧 `reach_cells` 列）

```
t=58.8  ground=186.1  reach=143.3  pose(3.77,2.41)
t=67.2  ground=186.9  reach= 13.0  pose(5.01,5.84)   <- 走进右上房之后
```

## 那扇门（`--dump-map-at "…:60,63,66,69"`）

```
60s inside 785 | 63s 708 | 66s 661 | 69s 51   <- 塌
```

- `new_obs` **61 格（0.61 m²）**，外接框 **4.8 x 14.7 m** ⇒ **细长的一条，不是一团物体**
- **通路半径 p50 0.44 m / max 0.64 m**（机器人半径 0.19 m）⇒ 物理上能过
- 那些格 `obstacle_votes`：66 s 中位 **1.0**（27 格 0 票）-> 69 s 中位 **14.0**（全 >=2 票）

**有 13-19 票的格在 66 s 时 `obstacle = 0`** ⇒ `obstacle` 不是纯票数阈值，而是

`_on_path` 只豁免**机器人站过的那一格**，救不了 3 m 外的门。

## ★ 结论：归因**地图层**，修正 §40 的因果方向

**§40 里"候选在 1-2 m 尺度上生成、失去离开局部的能力"把因果说反了** ——
候选尺度小是 `reach` 塌缩的**结果**。**第一不可逆分叉是 t≈66-69 s 的障碍层事件**
（t≈58 s 的平台化是它的前兆），不是候选层。

**这也解释了 §29 为什么 `rfirst_gate` 是 no-op**：region 层的可达性由 `_plan_first` 判，
而 frontier 层确实有大规模不可达 —— 但**成因在地图层**，region 层的门永远命中不了。

**与 §24 同族**：当年撤回的口径被"累积障碍层封门口"打坏，判据写"别退回 `votes<12`"；
**现在的问题在另一端**（2 票 + release ⇒ 反复封门）。两端都失败 ⇒ 修的不是阈值。

## ★ 为什么"单格不够" —— 腐蚀核把它变成 5 格门槛

`free_space = ground → closing(5×5) → & ~dilate(obstacle,3×3) → erosion(k)`，
`k = round(2×0.19/0.1)|1 = 5` ⇒ **每边腐蚀 2 格**
⇒ **门内连续无障碍段必须 ≥ 5 格（0.5 m）才剩得下 1 格可走。**
**这是一条可直接监控的判据。**

## ★ 根因：2D 栅格分不出"地面"与"它正上方的悬空结构"

点云级：**61% 的障碍回波高度落在 [0.35,0.50)（`OBSTACLE_LO=0.35`）**，rng 1–4 m 段达 82%；
而 `h_obs_med` 中位 **0.989**、`h_obs_hi` 中位 **1.518** ⇒ 门那里**既有地面又有
0.35–2.0 m 高的竖直结构**（门框/门楣）。机器人从 4.5 m 外斜看，两者**投影到同一个 2D 格**。

**而 `wmap.add` 里 obstacle 证据会清零 `_ground_after`** ⇒ 悬空结构的回波不仅记一票障碍，
还**抹掉"刚看过地面"的记录**。`seen_mask` 只处理了**天花板**（h > 2.0），
**0.35–2.0 m 的悬空结构没处理**。
⇒ 这解释了**横跳形状**（位姿微动 ⇒ 射线在门楣与门内地面间切换 ⇒ 82 次翻转），
也解释了**棘轮**（release 判据 `_ground_after >= 0.3×votes` 随单调 votes 越来越难满足）。

**附带一条独立的结构性缺陷**：`ground = |h| < 0.10+0.035·rng` 与 `obstacle = 0.35 < h <= 2.0`
**在 rng = 7.14 m 处交叉** ⇒ 再远，"地面"的定义包含"障碍"的定义。
实测 **2%（50/3111）命中落在重叠窗口，100% 来自 rng > 7.14 m**。真缺陷，但不是主因。

**与 §24 同族（镜像）**：§24 撤回的是 `votes<12` 绝对上限永久封门；
这次是 **2 票门槛 + `0.3×votes` 比例释放**让门**先通后封**。
⇒ **两端都失败 ⇒ 要修的不是阈值，是"什么算障碍证据"的定义。**

## 本轮踩的坑（新硬规则）

**格表生成用 `round` + 错的 extent ⇒ 整个格表偏移一格，消融打在空地上（差异 0 格、无报错）。**
`cell_of` 是 `floor((x+ext)/res)`，格心是 `ix*res-ext+res/2` —— 格心落在**半整数**上，
`round` 的 banker's rounding 把一半的格送偏一格。第一次消融 `obstacle` 差异 0 格、
`inside` 一分没动，**没有任何报错**；是靠"消融必须改变点什么"这个守恒式发现的。
⇒ **凡是用"世界坐标 → 格索引"的表，必须用 floor + 真实 extent，并先验证表确实命中了目标格。**
