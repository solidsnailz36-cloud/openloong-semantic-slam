# 第二十九轮：patch 内代表点规则的离线对照（§35 / 交接 §25）

**boss 拍板**：做"代表点选择规则"的离线对照，**不接回 planner、不跑仿真**。
验收写死：**把所有已有 replay 的 patch 跑一遍**，统计有多少次跨到 patch 的不同空间端
—— **只看 frame 93 不算数**。

## 先修一处自己的账

§34 把 tiebreak 的字段写错了。`_rank_key` 签名 `(score, d, px, py, cx, cy, cd)`，
调用传 `(score_r, d0, ax, ay, px, py, cd)` ⇒ key = `(-score, d0, ax, ay, cd, px, py)`。
`d0 = d_start.min()` 与 `(ax, ay)` 都是 **patch 级**、同一 patch 的候选**共享**，
**不可能**区分它们。真正起作用的是 **`cd` = 候选点到机器人当前位姿的距离**。
两个量方向一致、数值相近（东 9.13/8.06、西 11.67/11.14），所以结论看着"对" ——
而**它没被任何仪器校验过，纯读代码读出来的**。
⇒ **解释也必须有一个可量的对象**（与"自检通过 ≠ 正确"同族）。已在 `19b0155` 统一改。

## 方法

`tools/replay_explore.py --dump-patches`：每 15 帧，**用 explorer 自己的零件**
（`_reach`/`_visited_mask`/`_fresh_depth`/`sweep_min_m2`/`sweep_min_dist`）
复现 `gather` 的 patch 划分（同连通性、同机器人半径挖洞、同 `min_depth` 门），
对每个 patch 记六个**离线**代表点：
`deepest`（= **K=1 会选的**）、`near_robot`（= **K=4 实际选的**，`cd` tiebreak）、
`far_robot`、`near_start`、`far_start`、`centroid`。分析 `out/_rep_rules.py`。
**只记账，不接回 planner。**

## 结果：不是 frame 93 的特殊情况

`cap_rf1r1`，900 帧，**163 个 patch**：`deepest` 与 `near_robot`
**从不是同一个格（0%）**；距离 **>2 m 占 87.7%**、>1 m 占 **100%**；
中位 3.83 m、p75 13.74 m、max 18.80 m。方位差 >90° 占 9.8%。

**跨采集 3/3 一致**：rf1r1 **87.7%** ｜ rf1r2 **98.2%** ｜ rf1r3 **93.3%**
（rf1r3 的方位差 >90° 占 33.3%）。

**按面积分层**：3.2–5.7 m² 时 >2 m 占 52%；**87–121 m² 的块上距离中位 15 m**、
方位差中位 32–62°。**大 patch 上 K=1 与 K=4 指的是相距 15 m 的两个目的地。**

**最大分歧的形状和 frame 93 一模一样**：`deepest` 全是 `(−12.25,−3.05)`（西），
`near_robot` 是 `(6.55,−2.95)`/`(5.45,−1.75)`/`(1.15,6.45)`。

## 结论

**要改的不是 tiebreak，是"一个大 patch 用极少代表点"这个前提。**
一个 100 m² 级的连通块被 1 个（K=1）或 4 个（K=4）点代表；K=4 的四个点
**共享同一个 patch 级 `score`**，只能用 `cd`（与价值无关）在它们之间挑。
⇒ **无论 K=1 还是 K=4，patch 内部的空间结构都没有进入评分。**
boss 的问题（"一个 patch 该暴露几个空间选择、如何代表它"）**被证实是独立的设计问题**。
