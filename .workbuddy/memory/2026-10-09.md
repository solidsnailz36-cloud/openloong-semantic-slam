### ★★ 而且"扣住"的语义是错的：它变成"可通行"

```python
np.logical_and(self.ground_ever, ~self.obstacle, out=self.ground)  # ground 是 obstacle 的纯函数
free = wmap.ground.copy()          # nav.free_space —— 规划器读的就是这个
def blocked(self): return self.obstacle | self.obstacle_now        # 安全层看的是这个（含当帧回波）
```

**被扣住的格 ⇒ `obstacle=False` ⇒ 变成 `ground` ⇒ 规划器当成"可开过去的地板"；
但 `obstacle_now` 里还有它 ⇒ `blocked()` 说"别撞"。一个语义，两个消费者，两个答案。**
⇒ 这正是 `wedge` ×4.7 / `blocked` ×3.1 的来源。上界扣住的是**任意格**（候选表尾部的），
不是机制自己判定的"门口幽灵格"，所以这 2000 多格当可通行地板 = 灾难。

诊断跑自身：traj **41.90**（ON 中位 82.4）、arrivals **0.79/1k**、wedge 235/1k、blocked 458/1k、
`ms_map` p50 91 —— **签名与 ON 臂一致**（这条本身偏坏，仅作签名校验）。
