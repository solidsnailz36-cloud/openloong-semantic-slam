### ④ ★★ 两个隐蔽坑
1. **`push -u <带 token 的 URL>` 会把 token 写进 `.git/config`**，位置是
   **`branch.master.remote`**（不是 `remote.origin.url`）⇒ **`git remote set-url origin` 改不到它**。
   实测：`remote.origin.url` 干净、`branch.master.remote` 是裸 token。已修 + `grep -c 'ghp_' .git/config` = 0。
2. **删库之后 5 分钟内，raw URL 仍然发旧货** —— 是 **Fastly CDN 边缘缓存**
   （指纹：`X-Cache: HIT` + `Cache-Control: max-age=300` + `Via: 1.1 varnish`），
   同一个 URL **200/404 交替**（不同边缘各自持有）。
   `?cb=random` 和 `Cache-Control: no-cache` **都绕不过**。
   ★ **别拿 raw URL 当验收判据** —— 那条 URL 是**我们自己**刚抓过的，缓存是我们自己喂的。

### ⑤ 真正的验收判据（走源站）
```
git fetch --no-tags origin <旧SHA>   => fatal: upload-pack: not our ref   ← 最硬的一条
github.com/<o>/<r>/raw/<旧SHA>/...   => 404
github.com/<o>/<r>/tree/<旧SHA>      => 404
codeload.github.com/.../tar.gz/<旧SHA> => 404
raw@旧SHA/<从未请求过的冷门文件>        => 404   ← 无缓存条目，最代表源站
raw@旧SHA/<我们抓过的那个文件>          => 8 连 404（等 max-age 过期后收敛）
```
★ `api.github.com/.../contents/...?ref=<旧SHA>` 返回 **403 是未认证限流**，不是证据。
