## 探索算法：架构 + **已判死的方向**（重开条件都写在这里）
**架构**：规划 = A\*（8 连通、按半径腐蚀 + 障碍膨胀）；跟随 = 三档油门 + **视线可达前视点**；
探索 = 前沿簇 + 角扇区 + `score = size/(1+d_start)`（**离起点**）+ `sweep`（去没到过的地板）+
`island`（门口探针）+ `shadow`（死角观察位姿）。**★ 目标 = "观测位姿"**（`target_standoff_m=0.80`）。
`progress_eps_m=0.02` 必须**远小于** `sweep_stuck_improve_m=0.5`。**`n_frozen_frames` 必须永远 0。**
- **★ 每个"什么都没发生"的判据都要说清盯的是哪个量**（帧数/直线/看到的地面都曾盯错）。

**仍然成立的跨轮结论（不要再重新发现一遍）**
1. **单跑不能当战果**：同构建 4 次跑逐房间极差 ≈ 跨构建极差 ⇒ **验收一律看 N≥3 的分布**。
2. **"抽签"的机理＝1e-7 m**：策略是输入的确定函数 ⇒ 不要去查 random seed，修法是**排序量化**。
3. **第一次分叉在第 0 帧**：首帧地图只有 11 m²，就在信息最少时定了 6 m 级目标。
4. **★ 候选集本身就是全屋尺度的**：基准臂 `sep_min_med = 6.33 m`、`az_span_med = 157°`
   ⇒ **排序层根本没有"局部"可言**，任何改变榜首的项必然长出米级位移。这是 §23–§29 的共同根因。
5. **覆盖 ≈ 停留 ⇔ 被选上**：corr(覆盖, 框内停留秒)=0.762；**"进去待很久却 0%"的反例 0 个**。
   Discover **已被排除**（看到 40/40、可达 39/40、进候选 39/40；13 个 0% 里"从未候选" 0 个）。
   40 个房间-跑次只有 22 个曾成为目标 ⇒ **瓶颈在"选谁"，不在"能不能"。**
6. **顺路可见性是真的且可加总**（§32）：patch-first 每跑 **59.9 m²（22.7%）**的首见地面落在
   非目标房间；**损失高度集中在"左上"**（19.0 → 0.5 m²）。⚠️ 但机制**不是"路过房间"**，是
   **走廊位姿的视距** —— 左上那 20 m² 是**站在走廊一眼看清**的（站进房内只首见 0.4 m²）。
   **更强的一条（§33）**：**所有房间的观测几乎全部来自"站在别处"**
   （站在本房内 vs 别处：右上 1.8/11.6、左下 1.9/15.5、左上 0.1/14.4、帘子 0.1/6.0）
   ⇒ **顺路可见性是主机制，不是附加收益。**
7. **★★ 距离的除法形式压倒了价值差异**（§33，本轮最重要的跨轮结论）：观察位价值
   `V_deficit` 能把西侧走廊认出来（**V=0.48，全场第 3**），但
   ①价值差只有 **1.55 倍**（0.48 vs rf1 自己到过的 0.28–0.34）；
   ②`score = V/(1+d)` 在 **3.9 m** 处就把它折成 0.098，输给脚下的 0.31 **3 倍**。
   ⇒ **远处的观察位必须比脚下的贵 3–4 倍才可能赢。** 排序一直在做"近的赢"，
   与 §27 的 `sep_min_med = 6.33 m` 是同一件事的两面。**改折算形式，而不是加 bonus。**
   附带：`A_visible_new` 是**增量**、天然单调递减 ⇒ 适合做**一次性目标**，不适合持续评分。
   分叉很早：rf1 在 **t≈13 s 距西侧观察位仅 3.89 m**，走开后再没接近
   （房子**同一连通分量** 243.7 m² ⇒ **路是通的，是没选**）。
8. **★ 不要用累积 `obstacle` 层算可视域**（§33）：360 条射线的首撞距离**中位 0.20 m**
   （机器人周围半径 1 m 内有 24 格散点）—— **它不是墙图**。要么用点云实测，要么先重建真墙层。
9. **★★ 让 rf1 丢掉西侧的是 `sweep_cands_per_patch=4`，不是 `rfirst`**（§34，同采集分离变量）：
   只加 `rfirst`（K=1）**完全无影响**（西侧目标 8→8）；只加 `K=4` 打到 **3**
   （跨 3 采集 8→3 / 9→3 / 3→1 一致；`sectors` 单独加**逐位相同** ⇒ 无关）。
   机制（frame 93）：`K=1` 时那个 **111.8 m² 的大 patch** 只给 **1 个代表点**且落在西端 ⇒ 往西；
   `K=4` 时同一 patch 给 4 个点、**`score` / `d0` / anchor 全部相同** ⇒ 排序落回
   **within-patch tiebreak 的 `cd`（候选点**到机器人**的距离）**：
   **东 8.06 m < 西 11.14 m ⇒ 东赢**。
   ⚠️ **这里我第一版写错了字段**（写成 `d0` = 到起点的距离）—— `d0` 是 **patch 级**、
   四个候选共享，**不可能**区分它们；真正起作用的是 `cd`（候选点自己到机器人）。
   两个量这次方向一致、数值相近，所以结论看着对，**而它没被任何仪器校验过**。
   ⇒ **解释也必须有一个可量的对象**（与"自检通过 ≠ 正确"同族）。
   ⇒ **`K=4` 把"这个 patch 往哪走"从"由代表点决定"改成了"由 `cd` tiebreak 决定"**，
   与 §33 是同一件事的两层（`cd` 到机器人 / `(1+d)` 折算，两次都不是因为价值）。
   **★ 由此修正 §31 的归因**：§31 判死的 `rf1` = `rfirst`+`K=4`+`sectors=12` 的**复合**，
   `K` 才是主因；**结论不变**（组合确实不行、不重启），但"区域层把机器人锁住"那段解释是错的。
10. **★★ patch 内代表点没有定义清楚 —— 量级是 87.7%，不是个例**（§35，三采集）：
   同一个 patch 上，六个自然规则给出**完全不同的点**：`deepest`（= **K=1 会选的**）
   与 `near_robot`（= **K=4 实际选的**）**从不是同一个格（0%）**，距离 **>2 m 占 87.7%
   / 98.2% / 93.3%**（三采集），中位 3.83 m、max 18.80 m。
   **按面积分层**：3–6 m² 的块上占 52%，**87–121 m² 的块上距离中位 15 m、方位差中位 32–62°**。
   ⇒ **要改的不是 tiebreak，是"一个大 patch 用极少代表点"这个前提**：
   100 m² 级的连通块被 1 个（K=1）或 4 个（K=4）点代表，而 K=4 的四个点**共享同一个
   patch 级 `score`**，只能用 `cd`（与价值无关）在它们之间挑 ——
   **无论 K=1 还是 K=4，patch 内部的空间结构都没进入评分。**
   工具：`replay_explore.py --dump-patches` + `out/_rep_rules.py`（**离线比较器，不接回 planner**）。
   下一步候选：①拆到候选点级再加总；②限制 patch 尺度；③先不动、保留 K=1。
   **★ 但 §36 已经把 ② 诊断完了**：**宽度峰切不开**（`same=1` 恒成立，24/24）、
   4 连通也不是对角伪连接（`nblob_4=1`）；而 **`deepest`/`near_robot` 腐蚀 2 格就消失
   （`same_e2=-1`，24/24）⇒ 这两个点自己就在窄处**，不是"区域中心"。
   ⇒ **限制尺度只让"选代表点"变小，不让它消失 —— 两个独立问题，"代表点语义"更根本。**
   （⚠️ 腐蚀会散开但分不清"自然分块 vs 碎片化"，要判需补"剩余面积占比"，**尚未做**。）
11. **★★ 成熟系统不拿"一坨未访问地板"当决策对象**（§37，源码级对标）：
    FUEL/ROS2 的对象是 **frontier（边界，`knownfree && isNeighborUnknown`）**、
    NBV 是 **RRT 球内均匀采样点**、ASE 是 **轨迹**。⇒ §35/§36 的"同一 patch 两个代表点
    相距 15 m（87.7%）"**不是代表点规则没选好，是对象选错了** —— frontier 天然薄、
    RRT 采样天然均匀、轨迹天然是序列，**都不存在"一个大区域一个代表点"这件事**。
    **我们的 `frontier` picker ≈ 成熟范式；`sweep`（patch）在四个系统里没有对应物，
    却是实跑主力** ⇒ §23–§36 的问题与泛化风险都集中在这一条腿上。
12. **★ "价值 ÷ 距离"这个形式只有我们在用**（§37）：FUEL 的 cost 矩阵是**纯移动代价（ATSP）**、
    NBV 是 `gain += gain(state)·exp(-λ·distance)` 后 **`argmax(gain)`**、
    ASE 用独立折扣、ROS2 用独立过滤。⇒ §33/§34 的"距离压倒价值"**是这个形式的性质**，
    改的方向是换成它们的形式，不是再调权重。
    （另：FUEL 早在做"限制 patch 尺度"——`cluster_size_xy_` + **沿 PCA 第一主轴二分**；
    视点 = 极坐标网格 + 6 个 yaw 取前 3；fallback = `dormant_frontiers_` + 近/中/远三级。）
13. **★ 一个 case 揪出来的问题，先问它在总体里占多少**（boss 2026-10-07 明确要求）：
   frame 93 看起来是个"tie-break 灾难"，量到总体才发现是 87.7% —— 同一个形状出现几十次。

14. **★★ 离线重排序实验里，`V` 必须按"决策点时刻"结算，不是"该位姿被参观那一帧"**（§38）：
   静态 `V` 会让**同一个高价值格在每个决策点全额付款** ⇒ "永远朝全场最高值格走"看起来最优
   （λ=0.05 时 87 个决策点只选出 **3 个不同目标格** = 塌缩），而 `ΣV` 累加又是个**假指标**（1.34）。
   **修法 = 格级首见表**（`_traverse_obs.py --dump-cells`，每格只记一次，总长 = `ground_ever`
   格数 ≈ 2–3 万，免费）；**修正生效的指纹是"改变但价值相同"的平局归零**（V 变连续量）。
15. **★★ `V/(1+d)` vs NBV `V·exp(-λd)` 的判定**（§38，`all` 池 = 210 个实测观察位）：
   **λ≤0.1 时 100% 的改写都是改善，λ≥0.3 几乎全恶化；分水岭 λ≈0.18**（B(0.2) 捕获率 0.840
   已低于 A 的 0.857）。A 的形态不是普遍偏置而是**两态**：**72% 决策点与 oracle 一致，
   18.4% 的点选了 0.10× 距离、只拿到 0.33× 价值**。
   **★ 但 `V/(1+d)` 不回避西侧**：`all` 池里 A 的 top-1 有 **48.3%** 落在西侧（西侧只占 28.6% 的格），

   ⚠️ 局限：oracle re-ranking（候选带未来信息）、`d` 是直线距离（偏袒 B）、

16. **★ 动态结算本身就修掉一半"近的赢"**（§38）：静态 V 下 A 选中的距离中位 **2.24 m**
