## 探索算法：架构 + **已判死的方向**（重开条件都写在这里）
**架构**：规划 = A\*（8 连通、按半径腐蚀 + 障碍膨胀）；跟随 = 三档油门 + **视线可达前视点**；
探索 = 前沿簇 + 角扇区 + `score = size/(1+d_start)`（**离起点**）+ `sweep`（去没到过的地板）+
`island`（门口探针）+ `shadow`（死角观察位姿）。**★ 目标 = "观测位姿"**（`target_standoff_m=0.80`）。
`progress_eps_m=0.02` 必须**远小于** `sweep_stuck_improve_m=0.5`。**`n_frozen_frames` 必须永远 0。**
- **★ 每个"什么都没发生"的判据都要说清盯的是哪个量**（帧数/直线/看到的地面都曾盯错）。

**仍然成立的跨轮结论（不要再重新发现一遍）**
1. **单跑不能当战果**：同构建 4 次跑的逐房间极差 ≈ 跨构建极差 ⇒ **验收一律看 N≥3 的分布**。
2. **"抽签"的机理＝1e-7 m**：策略是输入的确定函数 ⇒ 别查 random seed，修法是**排序量化**。
3. **第一次分叉在第 0 帧**：首帧地图只有 11 m²，就在信息最少时定了 6 m 级目标。
4. **★ 排序层根本没有"局部"可言**（§23–29 全族的根因）：基准候选集 `sep_min_med = 6.33 m`、
   `az_span_med = 157°` ⇒ 任何改变榜首的项必然长出米级位移。**先量这两个数，再动排序层。**
5. **覆盖 ≈ 停留 ⇔ 被选上**：corr = 0.762、**反例 0 个**；Discover 已排除（40/40 看到、39/40 进候选）
   而 40 个房间-跑次只有 22 个曾成为目标 ⇒ **瓶颈在"选谁"，不在"能不能"。**
6. **顺路可见性是主机制、不是附加收益**（§32/§33）：所有房间的观测几乎全来自"站在别处"；
   机制是**走廊位姿的视距**，不是"路过房间"。
7. **★★ 距离的除法形式压倒价值差异**（§33）：观察位价值能认出正确的那一侧，但 `V/(1+d)`
   在 3.9 m 处就把它折到输 3 倍 ⇒ **改折算形式，而不是加 bonus**。
   （§38 又发现：这多半是因为**在线那个 `V` 从来不结算** —— 动态结算下同一形式自己就修好一半。）
8. **★ 不要用累积 `obstacle` 层算可视域**（§33）：首撞距离中位 0.20 m，**它不是墙图**。
9. **★★ 分离变量**（§34）：`rfirst`+`K=4`+`sectors` 的复合里 **`K` 才是主因**，
   `sectors` 单独加逐位相同 ⇒ **A/B 之前先数清两臂差几个变量。**
10. **★★ "一个大 patch 用一个代表点"没有定义清楚**（§35/§36）：六个自然规则给出完全不同的点，
    `deepest` 与 `near_robot` **从不是同一个格**、>2 m 占 87.7%（三采集）；而**限制尺度不让它消失**。
11. **★★ 成熟系统不拿"一坨未访问地板"当决策对象**（§37）：FUEL/ROS2 用 **frontier（边界）**、
    NBV 用 **RRT 均匀采样点**、ASE 用 **轨迹**。**我们的 `frontier` picker ≈ 成熟范式，
    `sweep`（patch）无对应物却是实跑主力** ⇒ 问题与泛化风险都集中在这一条腿上。
12. **★ "价值 ÷ 距离"这个形式只有我们在用**（§37）：FUEL 是纯移动代价 + ATSP、NBV 是 `argmax(gain)`。
13. **★ 一个 case 先问它在总体里占多少**：只看单个 case 会把架构问题当噪声放过。
14. **★★ 离线 A/B 里"价值"必须按决策点时刻结算**（§38）：静态 `V` 让同一格反复付款
    ⇒ 塌缩看起来最优，而 `ΣV` 累加是假指标。修法 = **格级首见表**；指纹是"平局归零"。
15. **★★ `V/(1+d)` vs NBV 的判定**（§38）：**λ≤0.1 时 100% 更好、λ≥0.3 几乎全恶化，
    分水岭 λ≈0.18**。**但 `V/(1+d)` 不回避西侧**（top-1 有 48.3% 在西侧，高于基数 28.6%）
    ⇒ **瓶颈在候选层，不在评分形式。**
16. **★ 要"降级到 X"之前，先确认 X 不是已经失败的那一层**（§39）：决策链本身已是降级链，
    `frontier` 就在 `search` 之前 ⇒ 字面版的「候选为空 ⇒ 降到 frontier」**是 no-op**。
17. **★★ 救援机制"跑了" ≠ "有用"**（§39）：救回率 100% 但**落点去重率极低**（9 次里 7 次同一个死点）
    ⇒ 救的是行动能力，不是任务。**验收必须含"救回到哪里去"。**
18. **★ "地图不增长"不是失效判据，"原地不动"才是**（§39）：该 Gate 抓到的多是开长途
    （`drive`、`|cmd_v|`≈0.55）；真失效是 `backoff` + `|cmd_v|`=0。**Gate 先扫阈值 + 报窗口内状态。**
19. **★★ "少走了 N m²"先问是"走得差"还是"被提前停掉"**（§40）：`rf1r3` 在 t=60 s 的地图是
    rf1 组**最高**，只是 99.4 s 就判 done ⇒ **"少 N m²"是终止的结果、不是原因。
    比较跑次必须按各自起点做时间对齐曲线。**
20. **★ 判"候选层 vs 规划/感知"的指纹**（§40）：`err_xy_m`（定位）、`points`（点云量）、
    **换目标时离旧目标的距离**（= `reach_dist` ⇒ 真开到了 ⇒ 排除运动异常）；再加两个只有对照
    才看得出的量 —— **空手率**（到得了但没信息）与**到达耗时中位**（目标的空间尺度）。
21. **★★ 第一分叉点的形状**（§40）：平台化 → 候选反复给出 **1–2 m 外**的目标 → 连续 barren
    → 每次追一个黑名单点（0.6 m、**永不过期**）→ **黑名单覆盖掉唯一剩下的边界 → 候选池空
    → search → done**。**"末次增长之后的净位移 2.0 m"是原地打转的硬读数。**
22. **★ rfirst 抬高的是方差**（§40）：rf1 组空手率 31/18/**58**/38% vs rf0 组 31/0/30/14%
    ⇒ 与「平均↑但 `C_min` 塌」同源：**不是它造成某个失败，是它让极端 draw 更容易出现。**
