## 探索算法架构
规划 = **A\***（8 连通、按半径腐蚀 + 障碍膨胀）；跟随 = 三档油门（原地转 / ≤25° 直行 / 走弧）+
**视线可达前视点**；探索 = 前沿簇 + 角扇区 + `score = size/(1+d_start)`（**离起点**而非离机器人）+
`sweep`（去没到过的地板）+ `island`（门口探针）+ `shadow`（死角观察位姿）。
- **★ 目标 = "观测位姿"**（`target_standoff_m=0.80`）；**两段式到达必须**，否则每帧都算到达。
- ⚠️ 加"进度期限"实测更差；⚠️ 黑名单实测 **no-op**。
- **★ 每个"什么都没发生"的判据都要说清盯的是哪个量**（帧数/直线/看到的地面都曾盯错）。

## ★★ 硬门槛：Decision-effect gate（boss 要求写成项目硬规则）
**任何探索策略改动进入长时间仿真（N≥3 实跑）前，必须在同一份采集的 replay 上过门：**
0. **★ Gate −1（2026-10-06 加，最先做）：对照臂真的关掉了吗？**
   看**对照臂与基准的产物 md5 是否一致**（`out/_region_gate.py` 第 0 段）。
   不一致 ⇒ 对照臂带着那一项在跑，整场实验在回答另一个问题。
   实测：`--arms "F0:rfirst=False"` 的 `False` 被解析成**字符串**（`int→float→str` 生不出 bool）
   ⇒ `bool("False") == True`，三个臂跑成同一个东西、无报错无警告。
   三个参数入口（`--explore-set` / `--set` / `--arms`）的类型推断已统一到 `r2slam/overrides.py`。
1. **它作用的那一层有对象**：`p_ge2 ≥ 0.5` 且 `sep_min_med ≥ 0.5 m` 且 `az_span_med ≥ 45°`。
   排序类改动另加 **Gate 1**（极差 > 0）与 **Gate 2**（`need_*` 中位落在可用的 λ 范围内）。
2. **它确实改变了决策**：`swaps / decisions ≥ 10%`（`decisions` = 该项自己的第一选择**真的被采纳**的次数，
   排除"榜首不可规划"的虚报）；并报**第一次分歧的时刻与前后目标**。
3. **方向条件**：改写必须朝"该去的地方"去，`→ less` 必须为 0。
4. **★ Gate 3：空间局部性**。每次改写记 **位移 / 两侧旅行成本 / `Δu` / `Δu/Δd`**，
   报 `sw_dist_med/p90/max`。**`max switch distance > R`（或跨区域项 > 5 m）⇒ replay 直接失败。**
   **只报方向的仪器一律不合格** —— §23 就是被它骗过去的。
4b. **★ Gate 0（排序层专项，2026-10-06 加）：先量候选集自己的尺度。**
   改**任何**排序/打分项之前，先在**基准臂**上量 `sep_min_med` 与 `az_span_med`。
   实测（§27）：基准的就地候选 `sep_min_med = 6.33 m`、`az_span_med = 157°` ⇒
   **排序层根本没有"局部"可言，任何改变榜首的项都必然长出米级位移**。
   `sep_min_med ≳ 5 m` 时不要往排序层加项 —— 那是候选集的问题，不是权重的问题。
5. 任一不满足 ⇒ **先修候选集或换一层，不许跑仿真**。
6. **负结果也要落成规则**：被否决的方向 ⇒ 代码与用例保留（记录 + 检验台），并提前写下"什么情况下判死刑"。
**工具**：`tools/replay_explore.py --arms "name:k=v"`（**一次感知、N 臂逐帧交错**；分开重放只有 5e-7 m
可复现而**那足以翻转离散选择**）；`pick_stats()`；`vendor/sim_scripts/run_repeat.sh TAG N`；
`out/_discover_timeline.py`（逐帧阶梯 + `--summarize`）；`out/_room_cover2.py`（覆盖率）。
