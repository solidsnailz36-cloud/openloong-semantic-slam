## ★ 探索算法（架构与 5 条硬规则；详见 `探索算法…md`）
**架构**：规划 = **A\***（8 连通、只走已知可通行、按机器人半径腐蚀 + 障碍 3×3 膨胀、目标 snap ≤4 格）；
跟随 = **三档油门**（原地转 / ≤25° 直行 / 走弧）+ **1.2 m 视线可达前视点**；
探索 = 前沿簇 + 角扇区代表 + `score=簇大小/(1+距离)`，另有 `sweep`（去没到过的地板）与 `island`（门口探针）。
- **★ 目标 = "观测位姿"**（`target_standoff_m=0.80`，借鉴 explore_lite + FUEL/TARE viewpoint）；
  **★ 两段式到达必须**：到观测位姿先问前沿还在不在，还在就走完剩下那段。**没有第二段 ⇒ 每帧都算到达、
  净推进 0**（实测移动帧 41% → 79%）。**任何"提前停"的方案都会踩。**
- **★ 打分形状全项目统一**：`size/(1+d_start)`（距离用**离起点**而非离机器人，防行驶中乒乓）。
- **5 条硬规则**：①候选只按距离排⇒极限环 ⇒ 用**簇连通分量**+大小分；②可达性是**连通分量**不是直线射线；
  ③地面掩码是"一层点"⇒闭运算但**不能穿已知障碍**；④**航向差不是停车理由——该画弧**；
  ⑤大视场下 frontier 不够 ⇒ 加 `sweep`。⚠️ 加"进度期限"实测更差；⚠️ 黑名单实测 **no-op**。
- **★ 每个"什么都没发生"的判据都要说清盯的是哪个量**（帧数/直线/看到的地面都曾盯错）；
  第二次修法是 `_closing_on_target()`（赶路不算停滞）。

## ★★ 第十三–十七轮结论（按时间，重点是与直觉相反的）
1. **`(0,0)` 是一个没有出口的状态**（第十三轮）。控制器可能输出"既不前进也不转向" ⇒ 停在那儿**什么都不报**。
   根因＝`not ahead → turn, v=0` 撞上 `w=1.6*err`（航向已对 ⇒ err≈0），而航向"已对"是因为前视点取到
   **弯的另一侧（架子里面）**。→ 前视点改**视线可达**（`los_grid="floor"`；`walk` 腐蚀栅格**过严**）+
   `wedge` 独立命名 + 立刻 backoff + **按目标累计**的被挡预算（`goal_blocked_frames=30`，距离创新低就补满）。
   ★ `progress_eps_m=0.02` 必须**远小于** `sweep_stuck_improve_m=0.5`。**`n_frozen_frames` 必须永远是 0。**
2. **"抽签"的机理＝1e-7 m**：输入微扰 → 首帧评分/排序改变 → 长期轨迹完全不同。**策略是输入的确定函数**
   （每次跑自己的采集重放都能复现自己那一次的首帧决策），所以**不要去查 random seed**。
   → 排序量化（`_rank_key`, `score_quantum_m2=0.25`）。
3. **★ 第一次分叉出现在第 0 帧**（§19）：首帧地图只有 **11 m²**（12 s 后 136 m²，最终 230 m²），
   就在"信息最少的那一刻"定了 6 m 级目标。输入差是 7.6 mm 的**每束固定抖动**（去不掉）。
4. **★ 单跑不能当战果**：同一构建 v19 跑 4 次，"三房最小覆盖率" = **0/0/0/18%**，逐房间极差
   **83/60/51/73 个百分点 ≈ 跨构建极差**（§18）⇒ **前十二轮所有"某间房做上去了"都不成立**。
   **唯一站得住的只有「冻结帧」**（同构建 4/4 都是 0）。**验收从此看同构建 N≥3 的分布。**
5. **★ 欠覆盖债务（第十四轮）＝否定结论**：`debt_gain_m2` 从 1 加到 9 **决策一字不差**；
   **根因是形状不是强度** —— 候选按定义都在没走过的地板上 ⇒ 该项**整体抵消**。
   它回答"这块最近被照顾过没有"，**不是**"哪片长期被忽略的区域最该回去"。
6. **★ 八臂全平，且根因不在债务身上（第十五轮）**：41/43 次决策**桌上只有 1 个候选**（`n=0` 22 次）
   ⇒ **排序层没有对象**。**真正的约束是候选集，不是权重形状。**
7. **★ 候选生成（第十六轮）＝排序第一次通电**：一个斑块给多个**方位分离**的地点
   （`sweep_cands_per_patch` / `sweep_cand_sep_m` / `sweep_cand_sectors`，**默认全是现状 K=1**）。
   只按距离抑制时**张角只有 7.4°**（"同一方向挂几个标签"）⇒ **扇区＝方向分辨率**，
   **`sectors ≈ 3K`**；推荐 **K=4 / sectors=12**（中位 3.5 个、P≥2 0.79、1.08 m、113°）。
   `kind="stable"` 的 argsort 必须（距离场沿墙大量并列）。**①没解决跨房间**（那是 Discover）。
8. **★ 候选级局部效用（第十七轮，§23）＝三道门全过**：`local_u` = 候选点周围 1 m 内"可达 ∧ 未走近"的
   地板面积；`score = base + λ·local_u/(1+d0)`；**不含时间/历史**、**`λ=0` 时按位等于旧 key**。
   Gate 1（有差别）**过**：极差中位 0.55 m²、只有 1/19 次是平的（债务同一位置恒为 0）。
   Gate 2 **过但有边界**：19 次里 14 次"没有 λ 能翻"、4 次 λ=0（同 patch）、1 次 λ≈12（跨 patch
   ⇒ **跨 patch 不是这一项该干的活，不许靠加大 λ 去够**）。
   决策级扫描（同候选表同帧）：λ=0.1/0.5 → **1 次（5%，不过 10% 线）**；**λ=1 → 3 次（16%，过线）**；
   λ=2 → 4 次（21%）。**每一次都改向"门前剩得更多"的点，`→ less` 恒为 0。**
   第一次改写在第 33 秒（4 个候选），**就这一次**让之后 **69% 的帧**都不同 ⇒ 早期一次离散选择杠杆极大。
   ⚠️ **63% 的决策里现行规则已经挑中了 u 最大的点** ⇒ 这一项是**很小的修正**，不是新策略。
   **实跑结果见第 9 条（失败）**。

9. **★ 候选级局部项 λ=0 vs λ=1 实跑（第十八轮，§24）＝验收指标上失败**，N=3 各，

   它针对的失败模式（「≥100 s 没推进且剩 ≥40%」）**基本没动**（3.33 → 3.00 条/跑）；

## ★★ 硬门槛：Decision-effect gate（boss 要求写成项目硬规则）
**任何探索策略改动进入长时间仿真（N≥3 实跑）前，必须在同一份采集的 replay 上过门：**
1. **它作用的那一层有对象**：`p_ge2 ≥ 0.5` **且** `sep_min_med ≥ 0.5 m` **且** `az_span_med ≥ 45°`
   （多但挤在一个方向＝没多）。排序类改动另加 **Gate 1**（那一个量在候选之间极差 > 0：
   `u_flat_frac` 要低）与 **Gate 2**（`need_*` 的中位要落在可用的 λ 范围内）。
2. **它确实改变了决策**：`swaps / decisions ≥ 10%`，其中 **`decisions` = 该项自己的第一选择真的被采纳的
   次数**（排除"榜首不可规划、走了 fall-through"的虚报）；并报**第一次分歧的时刻与前后目标**。
3. **方向条件**：改写必须朝"该去的地方"去（局部项 = 改向门前剩得更多的点），`→ less` 必须为 0。
4. 任一不满足 ⇒ **先修候选集或换一层，不许跑仿真**（实测拦下过：债务 8 臂改 0%）。
**工具**：`tools/replay_explore.py --arms "name:k=v"`（**一次感知、N 臂逐帧交错**；分开重放只有 5e-7 m
可复现而**那足以翻转离散选择**）；`pick_stats()`；`vendor/sim_scripts/run_repeat.sh TAG N`。
