# 根因史 v4–v8（从 `MEMORY.md` 拆出；细节在 `docs/交接_*` 与 `docs/_bak/`）

> 只记**会重复踩的机制**。数字与推导在交接文档里。

**v4**：①"标到墙上"**不是深度错**（LiDAR 对真人准到 0.97–1.01× 真距），错的是 **2D 框比实物高约 1.6 倍**；②房间进不去**不是探索问题**（绿 230.7 m²，机器人只够得着 115.1 m²）⇒ **别再改探索参数**；③真实侧"检出人没标记"是**框没融合成物体**；真实数据集是**健身房**，被认成人的其实是**白色训练器械**。
**v5**：①真实侧把点云**按里程计航向反向旋转**再投影（`yaw` 补偿只该给仿真用）⇒ `yaw_proj = 0 if rotates_with_base else yaw`，localised 46.9%→95.3%（**藏一轮，因为 `frames.csv` 的 yaw 列被门控成空列** ⇒ **空列让 bug 隐身**）；②融合把**平地板**当目标 ⇒ 融合前 `is_floor` 剔地面点；③ `min_height` 1.00→**0.40**（虚多的簇是墙，本来就高）；④"标在墙上"靠**相对**判据压住（⚠️ **一次跑的分隔度不能当跨跑阈值**）；⑤**规划层绝不能用"当帧回波"**（规划图逐帧闪变⇒原地打转）；⑥障碍层"一帧定死" ⇒ `OBSTACLE_MIN_VOTES=2`，但**安全单独走 `blocked()=obstacle|obstacle_now`**；`seen` 不再被天花板污染（`seen_mask`）。
**v6**：① **`box_h_px` 在 ~32 px 触底**（检测器 stride 下限）⇒ `box_height_m = depth*box_h/f` 在远处失效，旧门限在 5–9 m 外拒掉真人（258 个真人框杀 118）；②修法：两条判据取 **`or`**（各为充分条件），且 `width_lat` **必须是相机系横向跨度**；③灰 = `seen & ~ground`、绿 = `ground`、黑 = 无回波（**只有"有回波落进去"才算看过**，射线穿过不算）；④门口是**实体回波**，客厅到房间**瓶颈净宽 0.00 m**（拓扑问题，**不是**膨胀参数问题）；⑤真实侧灰斑机制 = **针孔 283/300 是障碍格**；⑥三个"看起来在跑"的坑：同步自检索引被清空的表⇒`KeyError`、`| tail` 吞退出码 + `pipefail`⇒脚本打印完就中止（症状只有"输出目录没变"）、`sim_up.sh >/dev/null` 藏了 `gzserver` 僵死 ⇒ **绝不静音一个允许失败的步骤；链条里别用管道接脚本**。
**v7**：①"人标到墙上"真根因 ＝ **检测器把墙面帧当成人**（同一采集 1227 个人框只有 **214** 落在真人身上；**置信度与横向宽度都不分离** —— 扫 conf 0.35→0.75 精度恒 44–46%，虚多的 `width_lat` 反而更窄；**只有框推高分离**：真人 p10 1.74 / 虚多 p10 0.87）⇒ **v6 的 `or` 门限把 `LABEL_BOX_HEIGHT` 架空了**（它的拒绝计数从 562 掉到 1，就是信号）。修法 ＝ 加**必要条件** `LABEL_BOX_HEIGHT_MUST={PERSON:(1.40,3.50)}`（AND）。A/B：仿真 person 实例 16→7、确认虚多 5→1、三位真人保住 ~90% 观测；真实侧绿地 382.2→382.1 **不变**，掉的是**一个激光实测 0.61 m 高的假人**（被拒 max 1.29 / 接受 min 1.42，间隔干净）。
②③④ ★ **仪器是本轮最值钱的发现**：`diagnose_ground.py` **没去斜**（采集存的是**未去斜**原始点云，管线会 `deskewer.apply`）⇒ 补上后绿 429.6→422.2；仍差 ⇒ 与**交付栅格**逐格比 **`seen` IoU 0.981 / `obstacle` 0.946 / `ground` 0.858**（差 51 m²）⇒ **重放只能用 (x,y,yaw) 拼位姿、那一跑用完整 SE(3)**，差 ≈0.07 m 与地面容差 ≈0.20 m **同量级** ⇒ **重放不可能复刻 `ground`**。⇒ **"针孔"是不稳定统计量（格子差 10%、读数差 4 倍）**，旧结论"300 vs 1388"作废；改用**拓扑口径 `pockets`**（被绿完全包住的灰连通块）。`dump_grids` 补写 **`ground_ever`/`obstacle_votes`/`obstacle_now`** ⇒ **交付产物自己就是仪器**。
⑤ `real_grey_before_after.png` **是错的**（右图是被否决的实验当作 AFTER、用了已废弃的 2×2 偶数核、两边都是重放）⇒ 重画成 `real_grey_abc.png`。那圈"外围灰"＝ **只看得到天花板（>2 m）的格子**（旧规则任何回波都算看过；新规则 92.4→5.7 m²）。
**v8**：①"只取框中心附近的点"**实测更差**（＝现成的 `points_in_box(pad=负数)`；pad 2→12→24 精度 **44%→32%→24%**，位置误差不动）。原因：框小⇒簇小⇒`width_lat` 小⇒**而那正是尺寸门限的充分条件**⇒墙上虚多更容易过。另：中心先验假设"目标居中且凸"，而**墙也是填满中心的**，对最大失败模式零鉴别力。
② 检测器最新是 **YOLO26**（2026-01，官方称 CPU 快 43%）。`yolo26n.onnx` **9.4 MB**、输出 `[1,84,8400]` 与 11n **同形**（解码器不改；`check_onnx_parity` 偏差 ≤1.26 px / 0 漏 / 0 类错）。仿真（有真值）：精度 62% vs 61%、真人框 182 vs 178、**65.7 vs 77.4 ms**；真实鱼眼：**实例级无差别（同样 8 个位置）但观测 −17% 且全类别均匀** ⇒ **维持 11n**（感知占 50% 分，**漏真物比多虚多更贵**）。换＝一条 `--model` 命令。
③a 门口**不是"透明实体反射"**：读 Gazebo world 文件，`house` ＝ `Wall_0..Wall_14` 方盒，**墙厚 0.150 m**、**无任何门扇/玻璃**；3 面墙分段，**净开口 1.671 / 1.459 / 1.219 m**；每个门洞**上方**有**门楣**（`z 2.0–2.5 m`）。**门楣致灰已量化否决**（门洞内障碍带回波 h>1.8 m 只占 2%/8%/5%，中位 **0.88/1.09/0.94 m** ＝ 人的身高）。⚠️ **具体是什么未定** —— 地图系与 Gazebo 系差 ~0.3 m，而门洞厚度只有 0.15 m（**偏差比窗口还大**），手算坐标不可靠（第一版还漏了 `Wall_11` 的 180°、`Wall_14` 的 −90° 偏航）⇒ **下一步要用地图自己的拓扑定位封路格**。
③b ★★**"人走过的灰迹"＝真 bug，已修**：`_obs_votes` **单调只增**，`votes>=2` 永久算障碍，而 object mask 只覆盖"被成功检测并融合"的少数帧 ⇒ 一个人走过就留下**永久灰带**并把那块地板从规划可走域永久拿掉。修法：`_ground_after`（自上次障碍证据以来**看到地板的帧数**）+ `released = (_ground_after>=2) & (votes<12)`；**强证据(≥12 帧)永不解封**，墙/椅子/门框的计数器恒 0 走不到这条路径；**`blocked()` 安全层不动**。两源 A/B（轨迹逐位相同 ⇒ 干净对照）：真实 绿 **382.1→408.4 m²**、释放 2707 格、规划可走 **205.2→229.2 m²(+11.7%)**、两块大区域 26.5→53.5 / 21.7→38.9 **合并**；仿真一个小房间并进主区。⚠️ `--npz` 复算**没有驱动器**⇒轨迹不随地图变（干净对照的前提），**"机器人会不会真的走进去"要实机跑**。⚠️ 仿真剩下的封堵格 **92% 是强证据、`floor_after` 中位 0** ⇒ **仿真的堵门是结构性的**，这条规则救不了 ⇒ **③a 与 ③b 是两个不同机制**。
