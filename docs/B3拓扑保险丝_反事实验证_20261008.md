## 2. 第三步：真正的 B3 replay

三臂，唯一差别是阈值 K（`--obstacle-topo-fuse`）；逻辑完全相同：

```text
每一次 `add` 之后：
  base      = 把本帧所有候选（新晋升的 + 正在暂缓的）拿掉
  Δreach(c) = reach(base) − reach(base + {c})
  Δreach(c) > K  ->  暂缓（留在 removable，不进 obstacle），下一帧重测
  否则           ->  照原规则晋升
```

### 3.2 安全带宽（这是"K 到底能取多少"的直接答案）

在**观测跑**上按逐格最大 Δreach 统计（与 §1.1 同一份数据）：

| 0.15 | 44 | 9 | 35 |
| 0.10 | 77 | **14** | 63 |
| 0.05 | 273 | 38 | 235 |
| 0.01 | 564 | 78 | 486 |

⇒ **安全带 = K ∈ [0.5, ∞)**（在这一份数据上；门是 136–149 m²）。

所以判据是"**自带 200 倍空档**"，不是"我们挑了个好数"：**只要不往 0.3 以下走，选多少都一样。**

> 这一条必须写死进验收：**报 B3 的成绩时，必须同时报"被拦格数 / 其中真障碍数"。**

### 3.0 ★ 第一次 K=1 是 FAIL，原因是仪表自己的 bug（必须留档）

第一版保险丝把"重测"写成了：base 里已经把这格拿掉，`_eval` 里又把它拿掉一次 ⇒ **两侧量的是同一张图**。

```
第一版 K=1.0 的日志：
  f1092  cell(213,297)  dreach = 0.0000 m²  (before 16983, after 16983)
  f1091  cell(213,297)  dreach = 136.3000 m²   <- 检测是对的
  ...整跑 "4 frames with a cell pulled back"，"4 distinct cells exceeded"
  结果：门在 strand 1091（比基线晚整整 1 帧）照样关掉，时长仍 26.5 s，最大跌仍 136.29 m²
```

**症状与诊断一一对应**：检测到的当帧被扣，下一帧重测读到 0，于是放行 → 门晚一帧关。
修法就是 §1 里那条定义：**base 必须排除"本次要审的全部候选"，两侧用同一个 base 量。**

**纪律上的教训**：这一版如果只跑一次、只看"机制有没有跑"（答案是跑了，确实 defer 过），
会得出"B3 无效"的**错误结论**；而如果只看检测那一行（136.30 m²），会得出"B3 有效"的**错误结论**。
只有"整跑 reach 序列"这个下游量能分辨这两种错。**所以 §2 的表格里必须同时有检测和下游两栏。**

## 5. 第五步：正式落地

**机制进了 `worldmap.py`，是唯一的实现**（replay 里那份原型已删除，避免"两个保险丝"）。

```python
# r2slam/r2slam/worldmap.py
OBSTACLE_TOPO_FUSE_M2 = 0.0        # 0 = 关；关的时候 add() 与 B3 之前的构建逐位相同

class WorldMap:
    reach_cells = None             # 由拥有 planner 的驱动装上的钩子：(wmap, pose) -> 可达格数
    _topo_defer  = set()           # 跨帧保留：obstacle 每帧重建，暂缓状态必须自己记
    topo_fuse_log = None           # 只读行日志（replay 的 --b3-log 用）

    def add(...):
        ...
        np.logical_and(self.ground_ever, ~self.obstacle, out=self.ground)
        if OBSTACLE_TOPO_FUSE_M2 > 0.0 and self.reach_cells is not None:
            self._topo_fuse(pose_xy)
```

三个驱动侧改动：
* `explore.py`：新增 `FrontierExplorer.reach_cells(wmap, pose)`。
  **故意不用 `_masks`** —— `_masks` 缓存 `_reach/_exterior` 并且喂探索预算，
  保险丝会临时改 `obstacle` 再还原，用 `_masks` 会把"反事实的 reach"写进缓存。
  同时手动失效 `planner.free_space` 的缓存键（两个候选图可能撞同一个 key）。
* `replay_explore.py`：`--obstacle-topo-fuse M2`、`--b3-log FILE`。
* `online_pipeline.py`：`--obstacle-topo-fuse M2`，进 summary。

**默认值 = 0（关）**，理由与项目里每个机制一致：先落地，再用一次单独的 A/B 决定要不要开。
开它需要下一次仿真跑（replay 里轨迹是录制的，测不了"它是不是真的开进去了"）。

### 5.2 ★ 落地过程中抓到的第二个 bug：保险丝与行驶共用 planner 的缓存

第一版生产实现里 `reach_cells` 用的是 **`self.planner`**（探索器自己驱动用的那个）。结果：

```
决策列：0 处不同（到 probe f1236 为止）
但 strand 的 reach 序列：99 帧不同，而且门在 strand 1192 / 1196 / 1200 / 1202-1204 / 1206-1207 /
                        1237 / 1239 / 1240… 上「闪关」一帧又弹回
p f1237 首次决策分叉：state arc -> turn,  v 0.22 -> 0.0,  heading_err 46.9 -> 93.2
```

**根因**：`PathPlanner.free_space` 把整张 walk 掩码缓存在
`(ground.sum, seen.sum, robot_radius, close_px)` 这个**内容寻址键**上。
保险丝要故意在"错的图"上调它（每个候选都要试装一次），
于是它最后一次调用留下的缓存键指向一张**被截断的图**；
一旦最终图的键与之相等，`_masks` 就会拿到**那张反事实掩码** —— 策略在一张自己没建过的图上做决策。

**修法**：`FrontierExplorer` 里给保险丝**单独一个 `fuse_planner`**，与 `self.planner` 彻底分家。
修后：决策列 **0/1489 不同**，reach 序列 **0 帧不同**，闪关消失。

**这条比第一个 bug 更值得记**：它是"**只读仪器必须在物理上不可能写到被测对象的状态里**"的又一次实例 ——
保险丝只是**读**，但它读的那个对象带着**可写缓存**。凡是"内容寻址缓存 + 反事实查询"的组合都有这个形状。

## 附录 B：一次真错的教训（写给下一个会话）

1. **`--b3-delta-m2 1e9` 的"观测跑"必须与基线逐位相同** —— 它是"仪器是只读的"的证明。

3. **△ 两侧必须用同一个 base**，否则会得到 0.0000 m² 这种"看起来很干净"的假读数。
4. **`--dump-map-at` 的浮点坑**（§68）：请求 `stamp_k - t_first` 会少一个 ulp，
   静默晚采一帧；补采提前 0.02 s（帧间隔 0.2 s）即命中。
5. **`docker exec ... cmd &` 的子孙会被 SIGHUP 杀掉**；后台跑必须 `nohup` + 把脚本 `docker cp` 进容器。
6. ⚠️ **`kill $(pgrep -f replay_explore.py)` 会把执行它的 shell 自己杀掉**（命令行里含同样的字符串）——
   本轮又踩了一次。要先 `ps -eo pid,args` 拿 PID，再 `kill -9 <pid>`。
