## 0. 结论（先行）

**K=2 暂停，不上线。**

- **8/8 个 run 都至少违反一条主判据**；其中 **P2（开道穿墙）、P3（真值物体被削）、
  P4（真值上的高票释放）三条在 8/8 个 run 上全部成立**。
- 副作用不是 rf1r3 的特例：**每一个 run 都释放 15.9% – 29.5% 的障碍层**
  （中位 ≈ 20.9%）。§43 的"24%"是**普遍值**，不是离群值。
- **收益是真的**：8 个 run 里 A 共出现 5 次 `reach` 塌陷，**B 保住了 4 次**
  （rf0r1 ×2、rf1r2 第 1 次、rf1r3 ×1）。**其中 rf1r3 的末 `reach` 12.8 → 150.6。**
  但 rf1r2 的第 2 次塌陷 B 也没保住（B 同时刻 10.2 vs A 峰值 130）——
  **K=2 不是万能钥匙。**
- **严格按 boss 的原话"真实墙"**：8 个 run 合计只有
  **墙内洞 2 格 + 墙开道 6 格 = 8 格（0.08 m²）**，规模极小但**不为零**。
- **真正被成片抹掉的是家具**：8 个 run 合计 **家具开道 81 格**；
  `kitchen_table` 在 **6/8 个 run** 里被释放 61% – 100%（其中 4 个 run ≥ 94%）；
  家具层整体释放率 **22.4% – 87.1%（中位 64.4%）**，而墙只有 **1.6% – 9.9%（中位 4.3%）**。

**一句话**：K=2 用的量是"**每帧回波点数**"，它区分的是**回波密度**，不是**真实性**。
真墙每帧中位 12 个点（§43），受影响很小；而**桌椅沙发在远处/掠射角本来就只有
每帧 1 个点**，于是被当作擦边成片释放。

## 6. 根因：K=2 分的是"回波密度"，不是"真实性"

| | 每帧每格回波点（§43 实测） | K=2 是否保留 | 真值释放率 |
|---|---|---|---|
| 真墙 | p25 6 / **中位 12** / p75 26 | 保留 | **1.6% – 9.9%** |
| 门内擦边 | **91.8% 单点** | 释放（**正确**） | — |
| 桌椅沙发（远处/掠射角） | **每帧 1 点** | 释放（**错误**） | **22.4% – 87.1%** |

`OBSTACLE_MIN_VOTES=2` 数的是**帧数**；K=2 把它换成"**每帧至少 2 个点**"。
这一换修好了门（门内是**贴 `OBSTACLE_HI` 下沿的稀疏单点**），
但把"**远处家具的稀疏但真实回波**"一起当成了擦边。

### 6.1 一条减轻后果的事实（读代码得到，不是推测）

```python
# r2slam/worldmap.py:500
def blocked(self): return self.obstacle | self.obstacle_now
```

- `obstacle_now` 在 `OBSTACLE_MIN_POINTS` 过滤**之前**就写好 ⇒ **K=2 不影响安全层**。
- `nav.py:482` 与 `explore.py:3999/4001/3985/3910` 的前视/直行检查走 `blocked()`
  ⇒ **被释放的格在被观测到的那一帧仍然会挡住车**。
- 但**路由/候选评估**用的是 `ground` + `obstacle`（记忆层）
  ⇒ K=2 丢的是**记忆**，不是**当帧检测**。
- **结论**：危害是"**规划以为能走 / 覆盖率评估失真 / 白跑一趟**"，
  不是"直接撞上去"。K=2 即便上线也不是安全事故 —— 但它**污染地图**，
  而"地图是否可信"正是下一步所有工作的地基。

### 6.2 下一步的建议方向（不实施，等 boss 拍）

K=2 的问题不在阈值，在**判别器选错了量**。真值取证给了两个现成的分离维度：

1. **高度带**（§43 已有实测）：门内擦边的 `h` 中位 **1.95 – 1.99**（紧贴 `OBSTACLE_HI=2.00`），
   真墙是 **0.43 → 1.55** 的立面。⇒ 判别器从"每帧 ≥ 2 点"换成
   "**贴 `OBSTACLE_HI` 下沿的稀疏单点才算擦边**"（例如 `n==1 且 h ≥ 1.9`）。
   桌椅在 0.4 – 0.8 m，天然落在这个带之外。
2. **邻域支持**：单点格若 8 邻域内有 ≥ 3 点的格，说明它**贴着真实结构**，不该释放。

只做**监控**而不改默认行为，也是一种选择：
把"门内最长连续自由段 ≥ 5 格"（§42 已给出的可监控量）做成运行时告警，
在真出问题时再降级处理。

## 7. 局限（必须一起读）

1. **真值栅格只有"碰撞几何投影"**，不是 LiDAR 会打到的东西本身。
   0.15 m 容差下 67% – 81% 的真值格能在 0.20 m 内找到地图障碍；
   剩下 20% – 33% 是"未观测 + 残余对齐误差"，所以**真值命中是保守证据**。
2. **对齐残差**：p90 ≈ 0.60 – 1.56 m。用于"该物体被削多少"（分母是客观测部分）
   是稳健的；用于"这一格是不是墙"则有 ±1 格的模糊。
3. **释放面积的分母是末帧 `obs_A`**，不是"曾出现过的最大障碍集"。
4. K=2 只做了地图层 A/B。**尚未做探索性能的完整基线对照**
   （探索时间 / 面积 / barren target / candidate exhaustion / 是否提前 done）——
   按 boss 的顺序，那一步只在 8 个 run 全通过后才做，**这次不通过，所以没做**。

# 0) 同步代码进容器（replay_explore.py 不在 sync 白名单里，要单独拷）
