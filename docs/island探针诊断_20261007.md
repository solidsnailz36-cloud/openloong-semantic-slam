## 0. 结论

**四个候选桶（`no_probe` / `no_patch` / `plan_fail`）在 4 次跑里全部是 0。**
真正的答案是第五种，而且是一个**计数器的语义错误**：

> **`n_island_probes` 记的是"`_pick_island_probe` 成功返回目标的帧数"，不是"一次探针"。
> 于是 `island_probe_limit = 12` 这个"最多跑 12 次门口"的保护，
> 实际变成了"最多跑 12 帧"（≈ 2.2 秒）。**

**证据**：3/4 次跑的 `ok` 全部落在 **2.2 秒**内、**相邻间隔恰好 0.2 s（= 一帧）**，
且这 2.2 秒**正好就是目标段的长度**。

**并且这 2.2 秒恰好花在"起步转向"上**（`turn`/`arc`，`v = 0–0.22 m/s`，机器人位移 **0.23 m**）——
**探针在机器人还没开始走的时候就把预算用完了**，之后整场（约 250 s）再也不发探针。

**另外 1/4 次（r4）连一次都没发**：`_stranded_fresh` 始终 `< island_trigger_m2 (4.0 m²)`
⇒ 两条调用路径都没进入。这与 §53 里 A0_r4 的 `other = 0` 是同一现象的两次独立观测。

**⇒ 第二瓶颈由两个互相独立的机制缺陷构成，都不是尺度问题。**
**⇒ 不要改 `island_min_m2`（0.5）。** 它一次都没有触发过。

## 1. 四桶答案（boss 要的那张表）

| 桶 | 含义 | 4 次跑实测 |
|---|---|---|
| **`no_probe`** | 滩头总量 < `island_min_m2` | **0 / 0 / 0 / 0** |
| **`no_patch`** | 逐 patch 都 < `island_min_m2` | **0 / 0 / 0 / 0** |
| **`plan_fail`** | 有 patch，但 `plan()` 全失败 | **0 / 0 / 0 / 0** |
| **`ok`** | 成功返回一个目标 | **12 / 12 / 12 / 0** |

**⇒ "滩头被 0.5 m² 逐 patch 门槛切碎"这个假设被直接证伪**（`no_probe` 与 `no_patch` 都是 0）。
实测探针点的 patch 面积是 **2.7–2.9 m²**（`ok` 记录里的 `patch_m2`），**是门槛的 5 倍以上**。
**⇒ "`plan()` 到不了"也被证伪**（`plan_fail = 0`）。

## 2. 另外四个桶（`_pick_island_probe` 的其余早退 + 调用点闸门）

`_pick_island_probe` 一共有 6 个早退，调用点另有 2 个上游闸门。四桶之外的六个：

| 桶 | 含义 | r1 | r2 | r3 | r4 |
|---|---|---|---|---|---|
| `no_linked` | `_linked` / `_probe` 还没算出来 | 0 | 0 | 0 | 0 |
| **`capped`** | **`n_island_probes >= limit` ⇒ 永久失效** | **6** | **3** | **31** | 0 |
| `all_visited` | 探针点全在已访问区 | 0 | 0 | 0 | 0 |
| `path1_no_sweep` | 路径 1：当帧没有 sweep 目标 | 1 | 1 | 31 | 1 |
| `path1_stranded_small` | 路径 1：`_stranded_fresh < 4.0 m²` | 5 | 12 | 14 | **14** |
| `path1_stranded_ge_trigger` | 路径 1 真正进入 | 18 | 15 | 13 | **0** |
| `path2_called` | 路径 2（最后手段）被调用 | 0 | 0 | 30 | 0 |

**账目对平**：`_pick_island_probe` 总调用 = `path1_stranded_ge_trigger` + `path2_called`
= 18/15/43/0，而 `ok + capped` = 18/15/43/0。**逐次全部对上，没有一次因其它原因返回 None。**

> ⚠️ **`capped` 只有 3–31 次，看着"影响不大"——这是错读。**
> `capped` 只在**函数被调用到**的时候才计数；12 次烧光后，只要 sweep 有目标、
> 或 `_stranded_fresh` 不到 4 m²，两条路径都不会再调用它，于是**连计数都没有**。
> **真正的代价是"剩下约 250 秒里门口探针完全消失"，而不是那 3–31 次。**

## 3. ★★★ 决定性证据：`ok` 的时间戳间隔 = 一帧

| run | `island_probes` | `ok` 时刻 | 跨度 | 相邻间隔 |
|---|---|---|---|---|
| r1 | 12（= 上限） | 77.1 → 79.3 | **2.2 s** | 全 0.2 s |
| r2 | 12（= 上限） | 150.1 → 152.3 | **2.2 s** | 全 0.2 s |
| r3 | 12（= 上限） | 264.5 → 266.7 | **2.2 s** | 0.2 ×10，含一对 0.3/0.1 |
| r4 | **0** | — | — | — |

而同一批跑的 `frames.csv` 里，`target_kind == "island"` 的目标段长度是：

| run | 目标段 | 长度 |
|---|---|---|
| r1 | t=60.4 → 62.6 | **2.2 s / 12 帧** |
| r2 | t=133.2 → 135.4 | **2.2 s / 12 帧** |
| r3 | t=247.4 → 249.6 | **2.2 s / 12 帧** |
| r4 | 无 | — |

**⇒ `ok` 的跨度（2.2 s / 12 次）与目标段的长度（2.2 s / 12 帧）逐位重合。**
`12` 不是"12 次探针"，是"12 帧"。

> **★ 帧率核对**：0.2 s/帧 ≈ 5.4 Hz，与 §52 那 12 次 live 跑的帧数/时长一致
> （1440 帧 / 288 s ≈ 5.0 Hz）。
>
> ⚠️ **这也解释了 §53 我给出的解释是错的。** 我当时写"探针 2.2 秒后被 sweep 换掉"，
> 把它读成**仲裁问题**。真相是**预算已经用完**（`capped`），根本没有再被选择的可能。
> 修正：**"2.2 秒"不是执行窗口，是预算耗尽时间。**

## 4. 这 2.2 秒花在哪：起步转向（逐帧）

A0I_r1 的探针段，逐帧：

```
      t   pose              target              d   cmd_v   cmd_w  state
   60.4  ( 6.01,-6.76)  ( 5.35,-2.95)      3.86   0.000   0.900  turn
   60.6  ( 6.04,-6.78)  ( 5.35,-2.95)      3.89   0.000   0.900  turn
   60.8  ( 6.07,-6.79)  ( 5.45,-2.95)      3.89   0.000   0.900  turn
   61.0  ( 6.08,-6.78)  ( 4.55, 1.05)      7.98   0.000   0.900  turn   ← 目标换了一次
   61.4  ( 6.07,-6.79)  ( 4.55, 1.05)      7.98   0.220   0.900  arc
   62.0  ( 6.12,-6.75)  ( 4.55, 1.05)      7.96   0.220   0.900  arc
   62.6  ( 6.21,-6.65)  ( 4.55, 1.05)      7.88   0.550   0.550  drive  ← 开始走，预算已尽
   --- 之后 target_kind = sweep ×7 ---
```

**12 帧内：机器人位移 0.23 m，离目标 3.86 → 7.88 m。**

⇒ **预算被消耗在"原地转向 + 慢弧"阶段**，`drive` 只出现在**最后一帧**。

## 5. r4 型：机制根本不启动（第二个独立缺陷）

r4 的账：`path1_stranded_small = 14`、`path1_stranded_ge_trigger = 0`、`path2_called = 0`、`ok = 0`。

⇒ **`_stranded_fresh(wmap)` 在整场里一次都没有达到 `island_trigger_m2 = 4.0 m²`**
⇒ **路径 1 从未进入**（它的第一道条件是 `stranded >= 4.0`），而路径 2 也没被调用过
⇒ **这一场里 `island` 机制完全没有启动过。**

这与 §53 的 A0_r4 完全呼应：那一场 `other = 0`（房间与机器人**跨了已知障碍**），
`linked = reach`，`_stranded_fresh` 也就恒为 0。

**⇒ 两次独立实验（§53 的离线复算 + 本次 live 计数）都指向同一个 r4 型地图。**

⚠️ 注意 `path1_stranded_small` 在 r1/r2/r3 也是 5/12/14 —— **门槛 4.0 m² 经常不满足**，
说明路径 1（"门口优先于 sweep"，即设计上那条更激进的路）**本来就很少生效**；
真正供探针的是路径 2（最后手段）。

## 7. 下一刀（**两个独立缺陷，各自修法，未实施，等 boss 拍**）

### 缺陷 A：计数语义（主要）

**`n_island_probes` 应该在"换了一个探针目标"时 +1，而不是每帧 +1。**

* 最直接的形态：在 `_pick_island_probe` 成功返回时，**先与上一次返回的目标格比较**，
  同一格（或同一 patch）就不计数。
* 等价形态：把 `island_probe_limit` 语义改成"最多投入 N 秒"（例如 12 s），
  用时间而不是次数做预算 —— 这与 `commit_frames` 的语言更一致。
* **验证（全部零成本）**：修好后在**冻结 replay** 上先看 `ok` 的跨度是否从 2.2 s 变成
  12 s（约 60 帧），再看 `capped` 是否出现在**探针真的走完之后**。
  **不需要跑仿真就能判断这一刀对不对。**

### 缺陷 B：门槛让机制压根不启动（次要，但决定 r4 型）

`_stranded_fresh >= 4.0` 在 r1/r2/r3 也是 5/12/14 次不满足、r4 是 14/14 全不满足。
**`island_trigger_m2 = 4.0` 与 `other` 的实际大小（§53 实测 14–24 m²，r4 为 0）是两个尺度。**
⇒ 与缺陷 A **分开做**，否则又会回到"改一个参数看数字"。

### 不要做

* **不要改 `island_min_m2`（0.5）** —— 它一次都没触发过（`no_probe = no_patch = 0`）。
* 不要改 `link_m` / `d0` / 价值函数 / 对象切分（boss 已冻结）。
