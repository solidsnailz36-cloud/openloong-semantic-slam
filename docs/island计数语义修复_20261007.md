## 2. 新语义的实现，以及实现里踩的一个坑

**语义**（boss 的定义）：
```
探针目标 A → 连续执行 → 目标完成 / 失败 / 被替换 → 计数 +1
```
**实现**：`n_island_probes` 只在"**本帧的探针目标与上一次不同**（距离 > `island_probe_same_m`，默认 0.50 m）
**或上一次探针已经结束**"时 +1。它从两个调用点搬进了 `_pick_island_probe` 内部，
所以"一次 probe"只在一个地方定义。

**★ 坑（第一次实现是错的，而且症状会骗人）**：
"上一次探针是否结束"我本来读 `self._target_kind != "island"`。**错**——
`_target_kind` 在 `_pick_island_probe` 被调用**之前**就已经被本帧的 sweep/frontier 阶段写过了：

```
本帧：sweep 阶段 → _target_kind = "sweep"      ← 已写
      → 路径 2 调 _pick_island_probe → 读 _target_kind ⇒ "sweep" ⇒ 每帧都判"上次已结束"
      → 探针成功 → _target_kind = "island"      ← 又写
```
实测 `goal_reset = 44`（44 次调用 44 次清空），`counted` 全 True。

**症状**：`T0` 与 `A0` 的决策 CSV **md5 逐位相同**，第一眼会读成"改了没有效果"。
**真相**：改动没生效。**修法**：在 `command()` 开头（任何改写之前）存一份上一帧的最终值
`self._prev_kind`，判据改读它。修完后 `T0` 立刻分叉。

> **★ 可搬运**：**"处理臂与基准逐位相同"有两种解释——改动无效，或改动没生效。**
> 先用一个自报字段（这里是 `count_mode`）把它区分开，再下结论。
> 这与 Gate −1 的另一半（对照臂真的关掉了吗）是同一件事的两面。

## 3. ★ 诚实读法：执行时间翻倍，位移几乎没变

逐段对比（全量 283 s）：

| | `A0`（frame） | `T0`（target） |
|---|---|---|
| 段 1 | t=99.8，13 帧 / 2.4 s，目标 (−1.55,5.95)，**0.96 → 0.70 m**，位移 0.38 m | 同（逐位相同） |
| 段 2 | t=107.6，**33 帧 / 6.4 s**，目标 (−1.45,5.95)，**1.35 → 0.38 m**，位移 **1.13 m** | t=107.6，**65 帧 / 12.8 s**，**1.35 → 0.46 m**，位移 **1.16 m** |
| 段 3 | 无 | **t=276.8，33 帧 / 6.4 s**，目标 (1.65,2.15)，12.89 → 12.66 m，位移 1.35 m |

**段 2 的时间翻倍（6.4 → 12.8 s），位移只从 1.13 → 1.16 m。**

⇒ **多出来的那 6.4 秒，机器人不是在走，是在 `turn`/`arc`。**
这与 §54 探针段逐帧看到的形态同族（12 帧里 `turn`→`arc`→最后 1 帧才 `drive`），
也与 §53 记的"目标换到身后后原地 55 s"同族。
**⇒ 这是第三层瓶颈，不是 A 没修好。**

**所以本轮的结论只能是**：
* **A 修好了**（计数语义、`capped` 归零、探针总执行时间 +130%、多出第 3 段）——**这是实锤**；
* **"探针执行时间"变长 ≠ "探针走到了"** —— 位移没变。**别把前者当后者报。**

**另外注意段 3**：目标在 **12.89 m 外**，33 帧只走 1.35 m，且**段结束时仍是 `island`**。
它是新语义带来的新增尝试，但它离目标很远就开始计时 —— **"一次 probe"的边界是否该包含"还没走到"，
值得下一轮单独想**（不在本轮改）。

### 3.1 第三层读数（零成本，用同一批 CSV 算的）：多出来的时间花在 `turn`/`arc`/`backoff`

| 段 2 的逐帧状态 | `A0`（frame） | `T0`（target） |
|---|---|---|
| 总帧数 | 33 | **65** |
| `drive` | 19 | 26 |
| `turn` + `arc` | 14 | **29** |
| **`backoff`** | **0** | **10** |
| `\|v\| > 0.1` 的帧 | 27 | 44 |
| **从选中到第一次 `drive`** | **第 14 帧** | **第 14 帧** |

**★ 两条读数合起来才完整**：

1. **"起步要 14 帧（≈2.8 s）"是稳定形态** —— 第 1 段也是第 8 帧、第 3 段也是第 14 帧。
   **而旧语义的 `island_probe_limit = 12` 比它还短** ⇒ **旧语义下探针永远走不完起步就被 capped**。
   这正好把 §54 的结论量化了：*12 < 14*。
2. **走过起步之后，仍有 29 帧 `turn`/`arc` + 10 帧 `backoff`** ⇒
   **第三层瓶颈 = "到了附近转不进去"**，不是"没被允许执行"。
