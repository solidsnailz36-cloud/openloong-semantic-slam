| 项 | 值 |
|---|---|
| 采集 | `cap_rf0r1 / rf1r1 / rf1r3 / rf1r2`（与 §49/§50 同一批，可逐数对照） |
| 臂 | `A0`（原始基线）｜`V1`（只换价值，不切分）｜`S1`（只切分，价值=area）｜**`SV1`（切分+价值）**｜`SV4`（切分+价值+K4） |

| 工具 | `tools/replay_explore.py --arms`，**一次感知、5 个策略实例逐帧交错**，零方差 |

**被换掉的那一个量**（`sweep_value_mode`）：

```
"area"（默认）  value = ncell × cell              ← 对象自己的地板面积（§49 以来一直是它）
"view"          value = 锚点周围 sweep_view_r_m 内的 fresh 面积
```

**半径是事前定死的、不是调出来的。** 同形的量项目里早就有了：`local_unfinished`
（`cand_local_radius_m = 1.00`，逐 place 的"1 m 内未访问地板"）。它自己的记录说它有区分度——
切分臂上 `u_spread_med` = **1.74 / 2.17 / 2.27 / 2.21 m²**、`u_flat_frac = 0.0`（**从不全同**）。
半径取 **1.00 m** 而不是更大：`r ≥ 1.5 m` 的圆盘就是 7.07 m²，正好吞掉一整片 3 m 的切分片，
价值会塌回"面积"——**那正是这一条臂可能"看起来惰性"的唯一原因**。

**一个刻意的实现约束**：价值读在 **patch 锚点**上，**不是**每个 place 上。
保持"每个 patch 一个价值"才能让 `sweep_cands_per_patch = 4` 继续是一个变量（§49 的不变量）：
"这几个 places 我该去哪个"必须始终是**关于它们在哪**的问题，不能变成关于它们值多少的问题。

## 4. ★★ 新事实：价值项**离开切分就不起作用**（这条是本轮最大的产出）

| 采集 | `V1` vs `A0` | `flat frac`（A0 / V1） |
|---|---|---|
| rf0r1 | 改写率 56.0% | 0.667 / 0.20 |
| rf1r1 | **逐位无差** | 0.95 / 0.95 |
| rf1r3 | **逐位无差** | 1.0 / 1.0 |
| rf1r2 | **逐位无差** | 1.0 / 1.0 |

**3/4 采集上，"只换价值、不切分"与基线逐位相同。** 原因在 `flat frac` 上写得很直白：
**基线桌上有 95%–100% 的决策只有 1 个对象**（`#obj med = 1.0`）。
**换一个价值定义，只能改变"谁排第一"；桌上只有一个对象时，"谁排第一"是恒等函数。**

⇒ **"先给对象加尺度、再谈它的价值"不是实验顺序上的偏好，是逻辑前提。**
价值层能表达的任何偏好，都要求桌上先有 ≥2 个可以比较的对象。

（对照：§49 里 `K4` 之所以能动，是因为 `sweep_cands_per_patch` 在**同一个对象内部**造出了多个
候选；而本轮换的是**跨对象**的排序，所以它必须先有多个对象。）

**顺带一条推论**：这也解释了为什么 §47–§49 那一串"评分项消融"（`debt_lambda`、`cand_local_lambda`、
`region_lambda`、`disc_lambda`）**全都测出 no-op 或轻微**——它们全都在一个**通常只有一个对象**的
桌上做排序。§35 的"41/43 次决策桌上只有 1 个候选"一直就是这件事，只是当时被读成"候选太少"，
而**准确的读法是"可比对象太少，排序层没有被咨询"**。

## 6. ★★ 分母陷阱：大跳跃的**次数**降了 4/4，**率没有**

`≥5 m` 跳跃的**次数**：SV4 = 13 / 8 / 1 / 9，对 A0 的 13 / 16 / 5 / 15 —— **4/4 下降**，看着很漂亮。
但 `switches`（分母：目标变更次数）同期也在降。**把分母补上再算一次**：

**每决策的大跳跃率 = `#位移≥5m / #目标变更`**

| 采集 | **A0（基线）** | S1 | V1 | SV1 | **SV4** |
|---|---|---|---|---|---|
| rf0r1 | 52.0% (25) | 62.5% (24) | 93.3% (15) | 81.2% (16) | **76.5%** (17) |
| rf1r1 | 42.1% (38) | 52.6% (19) | 42.1% (38) | 58.8% (17) | 44.4% (18) |
| rf1r3 | 27.8% (18) | 15.4% (13) | 27.8% (18) | 20.0% (10) | **10.0%** (10) |
| rf1r2 | 55.6% (27) | 60.0% (20) | 55.6% (27) | 68.8% (16) | **42.9%** (21) |
| **中位** | **52.0%** | 60.0% | 55.6% | 68.8% | **44.4%** |
| **最差** | **55.6%** | 62.5% | 93.3% | 81.2% | **76.5%** |

**⇒ 这是本轮差点写出去的假阳性。**

* `SV4` 的中位（44.4%）确实低于基线（52.0%），**但它的最差是 76.5%，基线的最差是 55.6%**。
* 逐采集：**2/4 更好**（rf1r3 27.8→10.0、rf1r2 55.6→42.9），**2/4 更差**（rf0r1 52.0→76.5、
  rf1r1 42.1→44.4）。
* `SV1`（本轮的主测试臂）**中位 68.8% 比基线还高**。

⇒ **"次数降 4/4" 是分母效应**：`switches` 变少，跳跃自然变少。
**在唯一有每决策率可算的病态上，这批改动没有一致改善，最差那一次比基线更糟。**

> **★ 与项目既有的两条规则完全同族**（"比率型必须先查分母"、"少走了 N m² 先问是走得差还是被提前停掉"）。
> 这次它救了一次**假阳性**：如果我按次数报，会写成"`SV4` 4/4 改善"。

## 7. 局限（必须一起读）

1. **影子重放测决策、不测覆盖**。`reach`/覆盖率/每米收益在这一层跨臂恒等 ⇒ 本轮**没有能力**
   回答"哪个更好"。能回答的只有：有没有区分度、改了多少、搬了多远、大跳跃的率是多少。
2. **`arrivals` 是弱指标**：影子重放里"到达"看的是**录制轨迹**是否经过策略给的目标，
   而策略换目标并不会改变轨迹 ⇒ 它只能读成"落点变了"，不能读成跑得好坏。`SV1` 的 3/12/6/2
   与 A0 的 13/18/7/5 之间的差**不应该**被当成"更差"。
3. **`switches` 变少有两个方向**：可能是"更稳定"，也可能是"更早收敛到少数目标 ⇒ 探索更少"。
   这一层分不出来。
4. **`V1` 的惰性（§4）是结论也是限制**：它意味着"换价值"这一类改动的所有证据都必须在
   **切分打开**的配置上取得——而切分本身（§50）还没被接受落地。
5. **`sweep_view_r_m = 1.00` 是事前定的、有据的，但仍是一个选择**：换半径会换掉整个实验的强度。
   §50.7 ② 的 `link_m` 剂量响应做完之前，两个尺度都还是悬的。

## 8. 建议的下一步

**不落地 `sweep_value_mode`**（保持默认 `"area"`，作为已验证的开关留着）。

本轮把状态推到了这一步：

```
对象尺度     ✅ 已解决且可证（§50：≤ link_m，4/4 实测 + 守恒）
对象价值的"形状"  ✅ 可换、有区分度、能改决策（本轮）
对象价值的"收益"  ❌ 未证明 —— 每决策率 2/4 好 2/4 坏，最差比基线差
```

**三个候选，按我的偏好排序**（**未实施，等 boss 拍**）：

* **① 收口：不再堆改动，把 `S1` 与 `SV4` 这一对送进仿真。**
  理由：影子重放的边界已经到了——决策侧的所有量都读了，**收益只能在覆盖率/`reach`/每米收益上判**，
  而那三项**这一层结构上测不了**。继续在 replay 上叠改动，只是在同一个测不了的量上换姿势。
  代价：一次仿真预算。
* **② 补齐 `link_m` 剂量响应**（1.5 / 3.0 / 6.0），同时报 `≥3 m² 对象数` 与 `P(≥1 合格)`。
  这是 §50.7 ② 的遗留项，而且现在有了新理由：**`sweep_view_r_m` 与 `link_m` 是一对尺度**
  （`r ≥ link_m/2` 会让价值塌回面积），两个数字应该一起定。
* **③ 换掉的是分母而不是分子**：`d0` 现在是 `min(对象所有格到起点距离)`——
  这正是 §50 里"20 m 对象吃到两个便宜"的另一半。本轮按 boss 的"一次只改一边"没动它。
  它的改动是一行，且**同样是"一次一个变量"**。

**我更倾向 ①。** ②③ 都是"把参数调得更对"，但本轮已经证明：**这一层判断不了"更对"**。

**边界不变**：不接 planner、不跑仿真、不碰 frontier/sweep/Region-first/fallback/blacklist。
