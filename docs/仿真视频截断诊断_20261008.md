# 仿真侧"进不去房间"诊断：不是改差了，是**视频被墙钟上限掐断**（2026-10-08）

> Boss 问题："为什么现在仿真侧小车进不去房间了？越改越差了怎么？之前是可以的。"
> **结论：没有回退这件事。代码没有变差，反而更快更完整；交付包里那版仿真视频是"录短了"。**
> 三条独立证据见 §2，处置见 §5。

---

## 1. 结论（一屏）

```
交付包仿真跑： wall 402.5 s  →  只换来仿真时间 219.4 s  （RTF 0.545）
              最后一帧仍在 drive / v=0.55 / frontier 还剩 1659 格  ⇒ 被截断，不是卡住
              0/4 房间进过；到各房间中心最近 2.87 / 3.58 / 4.41 / 4.74 m

同一套代码今天在容器里： wall 390.1 s  →  仿真时间 291.2 s  （RTF 0.747）
              干净收尾："no reachable frontier left and no unvisited floor"
              3/4 房间进过；进房间时刻 t = 148.2 / 237.4 / 246.4 s
```

**把对照臂截到 219.4 s，它也只进了右上（左下最近 4.67 m、帘子 5.15 m）——
完全复现交付包那次的观测。** 也就是说：那版视频停在了机器人"正要拐进左下房间"之前
**17–27 秒**。

⇒ **`--duration` 是墙钟秒，而 Gazebo 跑不到实时。** 云机那台 RTF 只有 **0.545**，
所以 `--duration 400` 只买到 219 s 的**仿真**时间。本机容器今天 RTF 0.75–0.79（快 ~40%），
同样的墙钟能多跑三分之一的仿真时间。

## 2. 证据链

### 2.1 交付包那版：它是"还在全速跑"的时候被掐掉的

| 观察 | 值 |
|---|---|
| 帧数 / 仿真时长 | 1098 帧 / **219.4 s**（= 5.00 Hz 仿真帧率） |
| **`wall_s`** | **402.5 s** ⇒ **RTF = 219.4 / 402.5 = 0.545** |
| 最后 30 帧 | 全部 `drive`，`cmd_v = 0.55`（巡航速度），最后一帧 0.362 |
| `cmd_v == 0` 的帧 | **130 / 1098（12%）**，且**全部**是 `turn` |
| `explore_state` | drive 827 / arc 141 / turn 130 —— **没有 `backoff`、没有 `search`** |
| 结束时 `frontier_cells` | **1659**（还有大量可去的地方） |
| 里程 | 94.06 m / 219.4 s = 0.43 m/s（巡航 0.55） |

**没有卡住的任何一种签名**：不冻帧、不倒车、不放弃目标、不在原地打转。它就是**时间到**了。

### 2.2 房间进入时刻：截断点落在两次进房之间

对照臂（`out/b3k1ctlr1_sim`，同 build、`--obstacle-topo-fuse 0` = 默认值）：

| 房间 | 首次进入 | 在框内 |
|---|---|---|
| 右上 | **t = 148.2 s**（第 741 帧） | 131 帧 / 63.8 s |
| 左下 | **t = 237.4 s**（第 1187 帧） | 227 帧 / 53.6 s |
| 帘子 | **t = 246.4 s**（第 1232 帧） | 187 帧 / 37.8 s |
| 左上 | 从未进入（最近 2.81 m） | — |

**左下与帘子都在 237 / 246 s 才进入，而交付包那版在 219.4 s 就停了。**
把对照臂截断到 219.4 s ⇒ 只进右上 ⇒ 与交付包那次的 0/4 一致。

### 2.3 RTF 是这一串数的总开关

| 跑 | 仿真时长 | 墙钟 | **RTF** | 收尾方式 |
|---|---|---|---|---|
| **交付包（云机）** | 219.4 s | **402.5 s** | **0.545** | 墙钟到点 |
| §70 对照臂（容器） | 291.2 s | 390.1 s | 0.747 | 自己跑完 |
| §71 profiler 跑（容器） | 333.8 s | 422.6 s | 0.790 | 墙钟到点 |
| §70 B3 ON（容器） | 81.2 s | 121.6 s | 0.668 | 自己放弃 |

⇒ **同一句 `--duration 400`，在云机上只换到 219 s 仿真，在本机容器能换到 290–320 s。**
这就是为什么"同一个策略，一次进房间一次不进"。

## 3. 为什么会有"越改越差"的错觉

**因为我报告里的那两个 0/4 是开了实验开关跑出来的，而那个开关默认是关的。**

| | 配置 | 房间 | 里程 |
|---|---|---|---|
| §70 **B3 ON** | `--obstacle-topo-fuse 1.0` | 0/4 | 20.44 m |
| §71 profiler 跑 | `--obstacle-topo-fuse 1.0` | 1/4 | 21.5 m |
| **§70 对照臂 B3 OFF** | `--obstacle-topo-fuse 0` = **默认** | **3/4** | **123.98 m** |

* `worldmap.OBSTACLE_TOPO_FUSE_M2` **默认 `0.0`（关）**；
* 包里**没有任何代码**（规则明写"无需提交源码"）⇒ 包里更不可能有这个开关；
* `island_probe` 等新开关**默认也全是关**（`island_probe: bool = False`）。

⇒ **§70/§71 那两个 0/4 是我在测一个"尚未上线的实验机制"，不是系统状态。**
真正的默认构建 = 对照臂 = **3/4 房间、123.98 m、干净收尾**。**它比 10-04 那版更好，不是更差。**

**我的表述失误要认**：§70 报告标题里的 "FAIL" 是"这个机制不能上线"，
但它太容易被读成"系统退化了"。以后凡实验臂的结论必须在同段里带上对照组那句话。

## 5. 处置

### 5.1 不做的事

* **不回退**：没有哪个版本"曾经能进房间又被改坏"。回退只会丢掉 §64–§71 的修复（含 B4 写层 bug 修复）。
* **不动真实侧**：真实数据侧是 1427 帧的确定性重放，与本次问题无关，不重跑。

### 5.2 做：重跑仿真，给足墙钟

```
DURATION=800 bash vendor/sim_scripts/run_repeat.sh sub 3
```

* 墙钟给到 800 s ⇒ 按 RTF 0.75 约可换 **600 s 仿真时间**，而对照臂 291 s 就跑完了 ⇒ **余量充足**；
* 跑完会**自终止**（"no reachable frontier left"），所以正常一次约 **390 s 墙钟 / 7 分钟**；
* **3 次**是因为项目纪律：单跑的房间分配受运气支配（同构建多次跑的逐房间极差 ≈ 跨构建极差）；
* **挑法**：优先挑**自终止（干净收尾）**的那次，而不是单纯挑覆盖最高的（后者是挑选成绩）。

### 5.3 换包

把选中那次的 `run.mp4 / map.pcd / summary.json / frames.csv / label_table.yaml / tf.csv / tf/`
覆盖到 `r2slam/out/online_sim/`（**真实侧 `online_real/` 一个字不动**），然后照旧
`package_submission.py --root out --out 提交包`，并把 §1 的核验四件套再跑一遍。

* 视频时长：`run_repeat.sh` 会把播放速度设成 ≈112 s（`sp = ceil(span/112×10)/10`），
  无论跑多长都落在终审的 120 s 内；
* README 里 `sim` 的"1098 帧 / 94.06 m / 220.9 m²"三个数要一并更新（重跑后由 `summary.json` 决定）。

## 6. ★ 可复用的纪律（本轮新增）

1. **`--duration` 是墙钟秒，不是仿真秒。** 报任何"覆盖/走过多少"之前，
   **必须同时报 `wall_s` 与 `sim_span`（即 RTF）**——只报 `--duration` 会得出错误结论。
   本机容器 RTF 0.75–0.79、云机 0.545，差 40% 就足以让同一策略一次进房间一次不进。
2. **判断"卡住"要看最后 30 帧的 `cmd_v` / `explore_state` / `frontier_cells`。**
   "被截断"的签名是：**仍在全速前进 + frontier 还剩很多 + 无 backoff/search**。
3. **实验臂的结论必须与对照臂写在同一段里。** §70 的 "0/4" 与对照的 "3/4" 分在两节，
   结果被读成"系统退化了"。
4. **视频类交付物的验收要含"内容"，不只是"时长/编码"**：
   终审过去只查了 ≤120 s / 264 / 分辨率 —— 抽帧看一眼才发现机器人一次房间都没进。
   ⇒ 补一条验收：**从 `frames.csv` 复算房间进入情况**（本报告的脚本口径即可，不需要 grids）。
