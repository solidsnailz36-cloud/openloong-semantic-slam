# 候选枯竭归因：为什么 49 帧"没有目标"（§60）

> boss 2026-10-07 拍板：**D1 / D3 / D1+D3 全部封板**；下一步**只做**
> `_stranded_fresh → sweep/frontier → filter → target` 的**逐帧归因，不改参数**。
> 要求一张账，逐帧回答"明明存在 `_stranded_fresh`，为什么最终 `target_kind` 仍然为空？"，
> 并区分三类：**A 根本没生成 / B 生成了被过滤 / C 生成了没采纳**。

**结论：B 类，而且过滤点是唯一的一个（`barren_blacklist`）；但真正的天花板在它上面一层——
`reach` 只剩 1.59 m²。**

## 1. 账本怎么来的（只读仪器，默认关 = 逐位 no-op）

`explore.py` 新增 `strand_dump`（默认 `False`）+ `_strand_row()`，`replay_explore.py` 新增
`--strand-dump`。**每帧一行**，给出决策链上每一级的余额：

| 列 | 含义 |
|---|---|
| `stranded_m2` | `_stranded_fresh`：不可达但可走的地板 |
| `reach_m2` / `linked_m2` | 机器人所在连通分量 / 加上链接岛 |
| `sweep_fresh_m2` | sweep 眼里的"可从、未访问"地板 |
| `sw_none` / `sw_n` | sweep 有没有给出目标（`-1` 未问 / `1` 问过且无 / `0` 有），以及它的候选数 |
| `f_n_front → f_n_in_range → f_n_big → f_n_far → f_n_fu → f_n_bl → f_n_den` | **frontier 漏斗**，逐级递减；**第一个读到 0 的字段就是清空池子的那一级** |
| `front_pick` / `tgt_none` / `reused` | 最终有没有目标 / 有没有跑决策段 |

**Gate −1**：T0 臂的决策列 md5 = **`4e73b0d9086e05e6`** = §55 `full54_T0` ⇒ **逐位 no-op** ✅

> ⚠️ 第一版只记到 1368 行（少 49 行）。少的正是**那 49 帧**——它们走的是
> `if target_res is None:` 分支里的**提前 `return`**，在记录点之前就返回了。
> **只读仪器必须装在"每个能结束这一帧的出口"上，而不是"正常路径的末尾"。**
> 这一条是这轮最值钱的实现教训。

## 2. 那 49 帧（t = 127.7 – 137.3 s，即 D1+D3 臂的 `search 29` + `backoff 20`）

**每一帧的形状完全一样**：

```
reused = 0            (走了决策段)
sw_none = 1 (49/49)   sweep 被问过，给不出
front_pick = 0 (49/49) frontier 被调用，给不出
stranded_m2     = 147.7 – 148.3 m2      ← 有大量地板在门外
reach_m2        = 1.59 m2  (恒定)       ← ★ 可达区几乎枯竭
sweep_fresh_m2  = 0.03 – 0.20 m2        ← sweep 榨干了
frontier 漏斗   = 35-38 / 35-38 / 30 / 6-30 / 6-30 / 0 / 0
                     front  in_range  big  far   fu    bl  den
                                                        ▲
                                              49/49 帧在这一级归零
```

## 3. 三分法的判定

| 类 | 判定 | 证据 |
|---|---|---|
| **A 根本没生成** | **sweep 侧是 A** | `sweep_fresh_m2 = 0.03 m²` ⇒ 没有 fresh 地板可生成 |
| **B 生成了被过滤** | **★ frontier 侧是 B，而且过滤点唯一** | `f_n_fu = 6–30 > 0`（候选已通过可达性）但 **`f_n_bl = 0`，49/49 帧** ⇒ **`_barren_spots`（"去过没用"黑名单）把它们全清了** |
| **C 生成了没采纳** | **不成立** | `front_pick = 0`（49/49）⇒ 不存在"pick 回来了却没被采纳" |

**⇒ 是 B 类，过滤点是 `barren_blacklist` 这一级。**

## 4. ★ 但真正的天花板在它上面一层：`reach = 1.59 m²`

这是本轮最该记住的数：

| 量 | 值 |
|---|---|
| 可达区 `reach` | **1.59 m²** |
| sweep 的 fresh 地板 | **0.03 m²**（占 reach 的 2%） |
| 不可达但可走 `stranded` | **148 m²** |

⇒ **99% 的可走地板在门外，机器人被困在 1.59 m² 里。**

⇒ 所以：
- `sweep` 给不出目标是**必然**的（1.59 m² 里没有未访问地板了）；
- `frontier` 还能看到 6–30 个可达前沿格，**但它们全在 1.59 m² 的边界上，而且都已经"去过没用"
  ⇒ 被黑名单收走**；
- `island`（本轮 D1+D3 已修好）**已经把它那一个门口处理完并永久屏蔽了**（§59：`arrived=1`、
  `done_skip=293`）。

⇒ **三个候选源同时归零，而不是某一个"漏检"。**

### 与既有结论的关系

- **同族于 §53**：`障碍层 → 门口被判障碍 → lz(房间) ≠ pseed → other = 0 → 房间从不成为候选`；
- **同族于"第一不可逆分叉在地图层"**：`rf1r3` 的 `reach` 在 t≈66–69 s 一次性塌掉
  （143.3 → 12.9 m²）⇒ **两跑建了同样的图，可达面积差 11 倍**；
- **本轮的新增量**：把 `reach` 塌陷的**后果**链条补全了 ——
  `reach 1.59` ⇒ `sweep 0.03` ⇒ 只剩 `frontier` ⇒ **`frontier` 的候选被 `barren_blacklist` 收走**
  ⇒ `target_res = None` ⇒ `search`。

⇒ **不是"候选生成器漏检"，也不是"过滤过严"（这一层确实过严，但它是被逼的：
在 1.59 m² 里反复去同一批前沿格确实没用）——是"可达区枯竭"。**

## 5. 一个口径 bug 与它的修法

`_strand_row` 第一版用**空 tuple** 当"没问过"的哨兵，而 `None`（**问过且没有**）也被判成了
"没问" ⇒ `sw_none` 列把两者混成一个值。已改成 `"unset"` 字符串哨兵。
（本次数据仍可用：两处调用都传了 `sw`，所以那 49 帧的 `-1` 实际就是 `sw is None`。）
