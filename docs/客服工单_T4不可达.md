## 三、客服可能会问你要什么，先备好

| 客服会问 | 你给什么 |
|---|---|
| 账号 / 实例 ID | 控制台里的实例 ID、订单号（**先截图备份**） |
| 什么时候开始的 | "两天前开始，这期间我多次关机开机，一直连不上" |
| 你试过什么 | "换过 SSH 端口探测、ping、清了本地网络；境外节点测试是通的" |
| 能不能从别的网络试 | 如果已经用**手机热点**试过，把结果告诉他们（能连上＝校园网侧问题；也不能＝源网段问题） |
| 实例是否在运行中 | 控制台截图 |

## 四、别写进工单的东西

- **不要贴密码。**
- 不要贴带 `?token=...` 的完整 Jupyter 链接（只贴到 `/notebook/<名称>` 这一段就够辨识）。
- 不要贴你项目里的路径、数据信息（与问题无关）。

## 五、得到回复后

- 若给了**新 IP / 新端口 / 新域名**：`bash vendor/sim_scripts/t4_retarget.sh "ssh -p <端口> root@<主机>"` 一键接管并当场验证。
- 若对方说"实例没问题，请自测"：运行 `bash vendor/sim_scripts/t4_diag.sh` 把三层判决的原始输出贴回去——
  那份输出里有**对照组**（确定没人监听的地址全部失败），他们很难用"你那边网络问题"一句话带过。

## 六、2026-09-28 复核（开机后仍未通）+ 加急材料

### 复核结果：与 9/24 完全一致

| 项 | 结果 |
|---|---|
| 本机 TCP 30032 / 22 / 8443 | 全部 TIMEOUT；ICMP 丢包 |
| `pc1.jupytergateway.gpufree.cn` A 记录 | **仍是 183.239.162.232**（未变） |
| 平台主站 106.13.50.6:443 | OPEN |
| 第三方节点（带对照） | CONTROL `1.1.1.1:30032` **0/5 FAIL**；TARGET **6/6 OK** |

⇒ **不是"刚开机还没就绪"**，机器已就绪且对外服务正常，就是从我们的网络到不了。

### 新增证据：不是"整个中国移动都到不了"

```
移动 183.207.44.251:443   -> OPEN 19 ms      (能连到别的移动主机)
移动 183.239.162.232:30032 -> TIMEOUT        (目标，全端口)
阿里云 222.73.33.20:443    -> OPEN 46 ms
教育网 101.6.15.66:443     -> OPEN 9 ms
```

⇒ 更像是**具体到 `183.239.x` 这段前缀的路由/回程问题**，或平台侧对来源 IP 做了限制。
这句话对客服很有用：**"我能连到其他移动地址，只有你们这台连不上"** —— 他们没法甩给"运营商"了事。

### 加急理由（最强的那个）

**实例处于运行中 = 一直在按量计费，而我已经 4 天无法使用。**
付着钱用不了，这比"帮我看看"有力得多。诉求直接写成可执行动作：

> 请把这个实例的公网 IP / 端口换一组（或把实例迁到另一个机房/地域），换完我立刻复测。
> 如果短期修不好，请先帮我停掉实例并处理这段时间的计费。

### 渠道优先级（工单通常最慢）

1. **官方答疑群 / 用户群里 @管理员** —— 国内平台这是最快的。
2. 论坛发帖（公开压力）。
3. 重新提一个新工单，正文第一行写 **「已第 5 天，实例计费中但完全无法访问，申请升级处理」**，附旧工单号。
4. 有客服电话就打。

### 你自己 30 秒能做的两个定性测试（客服也会问）

- **手机热点**连一次：能上＝校园网侧问题；不能上＝平台/源网段问题。
- 浏览器打开 `https://www.itdog.cn/tcping/183.239.162.232:30032`：
  看**全国各运营商节点**能不能通，**截图**——这张图既能定性，也是给客服的硬证据。

| 出口 | 结果 |
|---|---|
| 校园网（CERNET / 山东大学，`58.194.168.205`） | 全端口 TIMEOUT，ping 不通 |
| **手机流量** | **Jupyter 正常打开** |
| 境外第三方节点 | 6/6 连通 |
| 平台主站 gpufree.cn | 正常 |

**这一条把责任钉死了**：同一个账号、同一组密码、同一台实例，
**只是换了个上网出口就能用** ⇒ 实例没问题、平台入口没问题、凭据没问题，
**问题在"校园网这条路径到不了目标"**（大概率是 CERNET ↔ 中国移动之间的回程路由，
或目标侧对来源网段的过滤）。

### 给客服的最终一句话

> 我的实例在运行中且对外服务正常：用手机流量可以正常访问 Jupyter；
> 只有从校园网（出口 58.194.168.205）过去才全端口超时。
> 请帮我**换一组公网 IP / 端口**（或把实例换到另一个机房），换完我立刻复测。

**理由补强**：实例运行中＝持续计费，从 9/24 起我已连续多天无法正常使用。

### 老板自己的工作通道（等客服期间照样能干）

1. **手机热点/USB 共享给这台电脑** —— 电脑的出口变成移动网络，SSH 直接可用，最省事。
2. **本机 v2rayN 切到「全局模式」** —— 它的 SOCKS 在 `127.0.0.1:10808`。
   注意：**规则/PAC 模式没用**，那种模式会把国内目的地放直连，等于又走回校园网。
   切好后：`bash vendor/sim_scripts/rr_proxy.sh '<命令>'`。
