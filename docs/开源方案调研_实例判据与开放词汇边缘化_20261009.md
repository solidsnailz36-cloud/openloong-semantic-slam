# 两条走不通的路 —— 开源项目里别人是怎么解的

> 面向：SLAM 大师赛（固态蜗牛队）感知/地图线
> 日期：2026-10-09
> 关联：`docs/语义地图朝向与灰斑修复_20261009.md` §11–§12
> 调研范围：13 个开源项目 / 论文，全部指向同一个问题 —— **"一个点云簇/区域，怎么判它是物体还是建筑结构"**，
> 以及延伸问题 —— **开放词汇检测怎么在 Orin Nano 级边缘设备上跑**。

---

## 0. 先把"失败的两条路"说清楚

我们判失败的两件事，**它们的瓶颈是同一个**：

| 路线 | 做了什么 | 失败形态 | 实测数字 |
|---|---|---|---|
| **① 实例层**（`r2slam/instances.py`） | 非地面回波 → BEV 栅格 → `cv2.connectedComponents` | **63.4% 的簇只落在墙上**，精度 35.9% | 3136 簇 / 874 帧；家具 16.2% / 真人 19.3% / 只落墙 63.4% / 空地 0.0% |
| **② 开放词汇 2D**（YOLO-World） | 36 prompts 烤进权重 → ONNX `[1,40,8400]` | **detect 3.8×，光它超 200 ms 预算** | 9.88 → 50.37 MB；99 → 381 ms |

**共同瓶颈：我们缺一个能判"这是不是物体"的判据。**
—— ①是想从点云里造这个判据，②是想用 2D 换词表宽度，但**换不掉"没见过的东西算不算物体"**。

**这次调研最重要的发现是：这个判据在主流开源项目里，几乎没有人真的去"解"它 —— 大家绕开了它。**

---

## 1. 结论先行（7 条，按对我们的价值排序）

### 结论 1 ★★★★★ 主流解法是"2D 引导 3D"，不是"从 3D 里判物体"

**所有一手的开放词汇 3D 实例分割项目（OV-MAP / OpenMask3D / Open3DIS / MaskClustering / OV-Octree-Graph / OVO / FindAnything / ConceptGraphs），无一例外都是：**

```
2D class-agnostic mask（SAM / CropFormer / eSAM）
        ↓ 用深度 / SLAM 位姿反投影
   3D mask
        ↓ 跨帧合并 + 投票
   3D 实例
        ↓ CLIP 特征
   开放词汇查询
```

**它们不在点云上做"这是不是物体"的判断。** 判据来自 2D 分割器 —— 而 2D 分割器（SAM 系）**天然就知道墙和椅子不是一回事**，因为它是**类无关但实例感知**的（`class-agnostic instance`）。

> ★ 对照：我们的 `instances.py` 是**纯几何聚类**，没有 2D 参与 ⇒ 没有任何东西告诉它"墙是一片，椅子是一个"。
> 这正是 63.4% 落在墙上的**结构性原因**，不是阈值没调好。

---

### 结论 2 ★★★★★ 但有个大坑：把 SLAM 重建几何喂给 3D 实例分割会灾难性退化

ECCV 2026 一篇论文（*Online 3D Instance Segmentation at Task-Oriented Granularity with Unposed Monocular Video*）做了我们正想做的事，并给了**明确的负面数字**：

| 方法 | 用深度传感器点云 | 用 MASt3R-SLAM 重建几何 |
|---|---|---|
| Open-YOLO 3D | 31.7 AP50 | **0.8** |
| OnlineAnySeg | — | **0.1** |

**原因（论文原文）**：噪声、局部扭曲、几何伪影 —— 破坏 3D 卷积和空间投影的前提假设。

> ★★ **这条直接解释了我们的 63.4%**：我们的实例层跑在**累积体素地图**上（有 ATE p50 0.276 m 的横向抹开、有障碍层的票数累积），
> 而不是干净的当帧深度点云。**在这种几何上做"实例聚类"，业内已经证明会崩。**
> ⇒ **不是我们调参没调对，是这条路本身在"带漂移的累积地图"上有系统性缺陷。**

**他们的解法**（也是我们要抄的）：**correspondence reuse** —— 不用 3D 坐标做关联，而是复用 SLAM 提供的**像素级对应**（这些对应在 bundle adjustment 前后不变）。

---

### 结论 3 ★★★★ 一个极便宜且有效的硬边界：帧内互斥（MEM）

同一篇论文的消融：

| 配置 | Replica AP50 |
|---|---|
| 完整 | 23.4 |
| **去掉 MEM** | **8.2** |

**MEM = Intra-frame Mutual Exclusivity**：**同一帧里的两个不同 2D 检测，不可能属于同一个 3D 实例。**

这是一条物理公理，零成本，却能阻断"贪心聚类一次错误链接 → 跨视级联合并 → 整间屋子塌成一个簇"的级联。

> ★ 我们的 `cv2.connectedComponents` **完全没有这条约束** —— 相邻的两个簇在 BEV 栅格里只要接触就连上，
> 而墙和贴着墙的椅子在 0.1 m 分辨率下**必然接触**。**这大概率就是 63.4% 的第二个成因。**

---

### 结论 4 ★★★★ 概念框架：我们缺的是 `stuff` vs `thing` 的区分

Semantic SLAM Survey（arXiv 2510.00783）把场景分成两类：

- **stuff（无定形）**：地面、墙、天花板、道路、植被 → **没有实例概念**，不该有 instance id
- **thing（离散物）**：家具、人、车 → 才有实例

**全景（panoptic）分割天然区分两者；纯几何聚类天然不区分。**
⇒ 我们的目标不该是"把所有簇都变成物体"，而是**只保留 thing，明确承认 stuff**。
⇒ 这跟我们已知的"墙/地面是 `ground`/`obstacle`，家具才该进语义层"是同一件事 —— **只是我们一直想用高度/票数去判，而人家是用模型判。**

---

### 结论 5 ★★★★ 几何法确实存在，而且最轻 —— 但它是为"单帧扫描"设计的

`YongxueLiu/point-cloud-processor`（ROS2 + Open3D，**纯几何、零神经网络**）的管线：

```
RANSAC 地面移除
  → 迭代垂直墙移除（multi-pass RANSAC + 法向角验证）
  → DBSCAN 聚类
  → 3D bbox
```

它用**法向角**区分地面 / 墙 / 斜面（`Smart plane classification: Distinguishes ground, walls, and oblique surfaces by normal angle`）。

> ★ **这是唯一一条不需要任何模型、能直接上边缘的路。** 但两个前提要验：
> ① 它是**单帧扫描式 LiDAR** 的思路（一次 RANSAC 能拟出一个平面）；
> ② 我们的地图是**累积体素地图**，墙在 ATE 0.276 m 下**不是一个平面**，RANSAC 会拟不干净。
> ⇒ **值得做 30 分钟的小实验：在我们真实的 `ground_ever` 栅格上跑一遍法向角分布**（见 §6 方案 B）。

---

### 结论 6 ★★★★ 边缘化的手段是"工程组合拳"，不是换一个更小的模型

把开放词汇塞进 Orin 级的项目，用的都是这几招（**每一条都有实测数字**）：

| 手段 | 谁在用 | 实测 |
|---|---|---|
| **prompt-then-detect（离线词表）** | YOLO-World | 文本塔重参数化进 1×1 卷积 ⇒ **在线不跑文本塔** |
| **降分辨率 + 减少提示点** | FindAnything | 图像降一半 + 只查 **25–36 个点**（原 64 提示） |
| **关键帧策略** | Compositional Object SLAM | PointRend **每 10 帧**跑一次，中间帧 warp mask |
| **队列丢帧 / 软件限速** | FindAnything | 无 CLIP/SAM 时**照常融合深度，限速 3 Hz** |
| **INT8 量化 + TensorRT** | 通用实践 | **2.3× 提速，精度掉 <1%**；`trtexec --fp16` 可到 60 FPS |
| **描述子压缩** | LEGO-SLAM | 高维 CLIP → **16 维**，内存 **82–257 MB**，15 FPS |
| **模型蒸馏（大模型当老师）** | YOLO-EOVOD | 蒸馏后 **Jetson NX 上 15.6 FPS**，且带开放词汇 |
| **轻量 backbone 替换** | MobileSAM | ViT-H(611M) → Tiny-ViT(**5M**)，整链 615M → **9.66M**，456 → **12 ms** |

> ★ **最重要的一条**：**FindAnything 在 Jetson Orin NX 16GB 上真机跑通了**（MAV 机载），
> 但代价是 **3 Hz 的语义更新率** —— 也就是**别人也接受"语义层跟不上 5 Hz 主循环"**，靠队列解耦。
> ⇒ **我们的 200 ms 预算不该假设"语义层必须每帧跑"。**

---

### 结论 7 ★★★ 主干模型的重型依赖是硬伤，要按"能不能 ONNX 导出"筛

| 项目 | 依赖 | 能否上边缘 |
|---|---|---|
| OVO | SAM2 + CLIP/open_clip + torch 2.5 | ❌ |
| OV-MAP | CropFormer + pointops + detectron2 + SAM | ❌ |
| Hydra | C++/ROS2/GTSAM/voxblox/spatial_hash | ❌（且是 C++ 研究码） |
| ConceptGraphs | Grounded-SAM + GradSLAM + PyTorch3D + LLaVA-7B + GPT-4 | ❌❌ |
| LEGO-SLAM | 3DGS + LSeg + diff-gaussian-rasterization | ❌ |
| opcseg | PointNet2 (torch) | ❌ |
| **MobileSAM** | torch → **可导出 ONNX** | ✅（9.66M） |
| **YOLO-World v2** | ultralytics → **ONNX/TensorRT 官方支持** | ⚠️（50 MB / 3.8×，需量化） |
| **point-cloud-processor** | Open3D + PCL | ✅（纯 CPU） |

**规则**：**离线训练/原型可以用任何项目；在线只允许"能导出 ONNX 或纯 numpy/OpenCV"的东西。**

## 2. 逐项目拆解（13 个）

### 2.1 `tberriel/OVO` —— 在线开放词汇语义建图（RAL 2025，MIT）

- **做什么**：输入带位姿的 RGB-D 关键帧，**在线**跟踪 3D 实例、融合 CLIP 特征。
- **关键机制**：
  - 2D mask 用 **SAM 2** 初始化（兼容 SAM 1）
  - **跨关键帧跟踪 3D segment**，按可见性聚合 CLIP，**含学习式 CLIP merge**
  - 可对接 ORB-SLAM3 / Gaussian-SLAM，**支持回环场景**
- **数字**：Replica 上 IoU 35.7% / Acc 57%（换 TextRegion + Perception Encoder 后；原论文 27.0 / 39.1）。
- **对我们的意义**：**"学习式 CLIP merge"= 我们需要的"跨帧同一个物体合并"判据**（我们是靠 BEV 连通域，无学习）。
- **硬约束**：重依赖（torch 2.5 + SAM2 + open_clip），**只能离线参考，不能上板**。

### 2.2 `FindAnything`（TUM × ETH，arXiv 2504.08603）—— 对象级体素子地图

- **做什么**：开放词汇 + 对象中心的 3D 建图，**机载实时**（MAV）。
- **关键机制**（**最值得抄的一个**）：
  - **不存逐体素高维特征**，而是 **eSAM 段 → 对象级聚合** → 特征存进"对象中心子地图"
  - eSAM 分割后按 **质量 > 0.7、稳定性 ≥ 0.9 过滤**（**这就是它的"判据"**）
  - CLIP ViT-L/14 提 768 维嵌入；跨视角用 **IoU 重叠**保持一致性
  - `supereight2` 多分辨率体素 + **子地图与 SLAM 关键帧绑定**（回环时刚性变换子地图 ⇒ 不用重新积分！）
- **数字**：**Jetson Orin NX 16 GB 真机部署**；图像降一半 + 只查 25–36 个点；**无 CLIP/SAM 时也融合深度，软件限速 3 Hz**；Replica mIoU 62.9。
- **对我们的意义**：★★★★★
  1. **"子地图绑关键帧、回环时刚性变换"** —— 直接解我们的漂移/重积分问题
  2. **质量/稳定性双门过滤** —— 是一个可直接抄的 mask 判据
  3. **3 Hz 语义更新** —— 证明了"语义不必每帧"
- **硬约束**：**未独立开源**（将并入 OKVIS2-X），目前只能读论文抄设计。

### 2.3 `teamROBI/OV-MAP`（IROS 2024，MIT）—— 零监督 3D 实例分割地图

- **做什么**：**不做 3D 监督网络**，把 2D class-agnostic mask 提升到 3D 建实例地图。
- **关键机制**：
  1. **合成深度补充原始深度**（从重建点云渲染补洞）
  2. **CropFormer 2D mask → 反投影 3D**
  3. **3D mask-voting + dominant voting over mesh segments** 得实例
  4. CLIP 特征标注实例
- **数字**（ScanNet200 val，3D 实例分割）：

  | 方法 | 3D 监督网络 | AP | AP50 | AP25 |
  |---|---|---|---|---|
  | Mask3D（监督上界） | ✅ | 26.9 | 36.2 | 41.4 |
  | OpenMask3D | ✅(Mask3D) | 15.4 | 19.9 | 23.1 |
  | SAM3D | ❌ | 8.4 | 13.1 | 18.7 |
  | **OV-MAP** | **❌** | **11.9** | **17.4** | **23.2** |

- **对我们的意义**：**"不用 3D 网络也能做出可用的实例分割地图"的最硬证据**（AP25 23.2，接近监督版）。
  `dominant voting over mesh segments` 是可直接借的合并判据。
- **硬约束**：依赖 CropFormer + pointops + detectron2，重。

### 2.4 `MIT-SPARK/Hydra` —— 实时 3D 场景图

- **做什么**：增量构建 3D 场景图（RSS 2022 / IJRR 2024），ROS2 Jazzy / Ubuntu 24.04。
- **关键机制**：跟 `semantic_inference` 配合用真语义分割模型；节点颜色与语义标签解耦；下游 Khronos / Clio 做开集语义。
- **对我们的意义**：**架构参考**（我们其实是个简化版的"几何 + 语义双通道"）。但它**没有告诉我们 2D→3D 实例的判据**（README 明确是研究码、不帮适配）。
- **硬约束**：C++/ROS2/GTSAM/voxblox，**研究码，README 声明不提供移植支持**。❌

### 2.5 `concept-graphs/concept-graphs` —— 开放词汇 3D 场景图

- **做什么**：posed RGB-D → 2D 检测/分割 + 逐区域 CLIP → 对象级 3D 地图 → 场景图。
- **关键机制**（对我们有直接借鉴）：
  - **`skip_bg=True`** —— 显式**跳过背景**（配合 `class_agnostic=True`）
  - **`max_bbox_area_ratio=0.5`** —— **限制 bbox 面积比例 ⇒ 间接排除墙面这类大面积区域**
  - 跨帧合并：`spatial_sim_type=overlap` + `match_method=sim_sum` + `sim_threshold=1.2` + `dbscan_eps=0.1`
  - 定期合并：`merge_interval=20`，视觉相似度 0.8 / 文本相似度 0.8
  - 可选轻量分割器：**FastSAM / MobileSAM / Light HQ-SAM**
- **对我们的意义**：★★★
  - **`max_bbox_area_ratio` 是一个极便宜、可立刻试的判据**：**面积占比过大的簇 = 背景，直接扔**。
    我们的 63.4% 墙簇大概率是"大面积长条" ⇒ **一行代码就能筛掉一大半**（但要验证不误杀大件家具）。
- **硬约束**：Grounded-SAM + GradSLAM + PyTorch3D + **LLaVA-7B + GPT-4**，在线不可能。❌

### 2.6 `YongxueLiu/point-cloud-processor` —— 工业 LiDAR 感知（ROS2 + Open3D）

- **做什么**：工业移动机器人/UAV 的实时 3D 感知，输出分割点云 + 3D bbox + 跟踪 + 动静分类。
- **完整管线**（10 步，全几何）：
  1. 单位自适应（mm→m）2. NaN/自身/远点过滤 3. 自适应体素降采样 4. 统计离群去除（SOR）
  5. **RANSAC 地面移除** 6. **迭代垂直墙移除（multi-pass RANSAC + 法向角验证）**
  7. **DBSCAN 聚类** 8. 3D bbox 9. 恒速卡尔曼多目标跟踪 10. 速度判动静
- **对我们的意义**：**唯一一条纯 CPU、零模型、可直接上边缘的路**（见 §6 方案 B）。
  它把"墙"从一个**被动残留**变成一个**主动要移除的类别** —— 这正是我们没做的。
- **硬约束**：为**单帧扫描式 LiDAR** 设计；我们的累积体素地图里墙不是平面，需先验证。

### 2.7 `peiyunh/opcseg`（CMU，RAL/ICRA 2020）—— objectness + 图搜索

- **做什么**：LiDAR 点云的**类无关实例分割**。
- **关键机制**：训练一个 **point-based objectness 模型（PointNet）**，然后用图搜索在**指数级多的候选分割**里找"最坏片段 objectness 最高"的最优分割（有 worst-case 与 average-case 两个高效算法）。
- **对我们的意义**：**"objectness"就是我们所缺的那个判据的学术名字。** 但注意它的输入前提：**背景已移除**（论文图注明确 "with background removed"）⇒ **它不解决背景问题，只解决"切几刀"。**
- **硬约束**：PointNet2 + torch，需训练数据。❌ 在线

### 2.8 `ChaoningZhang/MobileSAM` —— 轻量 SAM

- **做什么**：把 SAM 的 ViT-H 图像编码器换成 **Tiny-ViT**。
- **数字**：

  | | 原 SAM | MobileSAM |
  |---|---|---|
  | 编码器 | 611M (ViT-H) | **5M** |
  | 整链 | 615M | **9.66M**（↓60×） |
  | 编码器时延 | 452 ms | **8 ms** |
  | 整链时延 | 456 ms | **12 ms**（单 GPU） |
  | CPU (Mac i5) | — | ~3 s |

  对比 FastSAM：小 7×、快 5×，且与 SAM 的 mIoU 对齐更好（0.73 vs 0.27）。
- **对我们的意义**：★★★ **如果走"2D 引导 3D"路线，MobileSAM 是唯一可能上板的 2D 分割器**（9.66M，**支持 ONNX 导出**）。
  ⚠️ **但它只有几何提示（点/框），不支持文本 ⇒ 不是开放词汇**。要开放词汇必须配一个检测器（YOLO-World）或 grounding 模块。
- **硬约束**：CPU 上 3 s 太慢 ⇒ **只能关键帧跑**。

### 2.9 `Lab-of-AI-and-Robotics/LEGO-SLAM`（arXiv 2511.16144）—— 语言嵌入高斯 SLAM

- **做什么**：3DGS-SLAM 内做实时开放词汇建图。
- **关键机制**：
  - **场景自适应自编码器**把高维语言嵌入蒸馏到 **16 维**
  - **语言引导剪枝**：识别语义冗余，**高斯数减 58–60%** 而渲染质量不变
  - **语言特征复用做回环检测**（省掉单独检测模型）
- **数字**：**15 FPS**；地图内存 **82–257 MB**（对比非压缩基线高一个数量级）。
- **对我们的意义**：★★ **"特征压缩到 16 维"是我们 §12 算力账里 `ms_map` 的同类问题**（我们是 `free_space` 平方律）。
  ★ **"用语义特征复用做回环检测"** 是个有趣的可选优化，但优先级低。
- **硬约束**：3DGS + LSeg + 自定义光栅化 CUDA 扩展。❌

### 2.10 `AILab-CVC/YOLO-World`（CVPR 2024）+ `ultralytics` 集成

- **关键机制**：**prompt-then-detect** —— 自定义 prompts **预先编码存成离线词表嵌入** ⇒ 推理时**不跑文本塔**。
- **对我们的意义**：
  - **`yolov8s-worldv2` 支持官方导出 ONNX/TensorRT**（`yolov8s-world` v1 **不支持导出**）⇒ **我们用的 v2 是对的选择**
  - ⚠️ **v2 没有 nano 版** ⇒ **下不去**（这是我们的卡点）
  - 官方 mAP：`yolov8s-worldv2` COCO 37.7 / LVIS-mini 13.5
- **硬约束**：规模决定了它必须量化才可能上边缘。

### 2.11 `Compositional Scalable Object SLAM`（CMU，arXiv 2020）—— 对象即 landmark

- **关键机制**（两条非常有价值）：
  1. **2D–3D 数据关联不只靠 IoU，还比较分割网络倒数第二层的深度特征嵌入** —— **防止把相邻的相似物体混成一个**（"一个办公室五把一样的椅子"）
  2. **物体体积当刚体，位姿更新时整体变换** ⇒ **完全绕过体素重积分**（跟我们 `free_space` 平方律是同一类优化）
  - 还有：PointRend **每 10 帧**跑一次分割，中间帧用位姿 **warp mask**
- **数字**：RGB-D Scenes V2 上 **ATE < 5 cm**；单 GPU / Actor 异步五模块。
- **对我们的意义**：★★★ **"用特征嵌入而不是 IoU 做跨帧关联"** 直接对应我们的痛点（墙和椅子接触）；
  **"warp mask 代替每帧重跑"** 是省算力的现成做法。
- **硬约束**：需 GPU（PointRend）。❌ 在线

### 2.12 *Online 3D Instance Segmentation at Task-Oriented Granularity*（ECCV 2026）

**这篇最贴我们的处境，单独列。**

- **范式反转**：**不做"先分割再识别"（bottom-up），而是 task-oriented** —— 用**开放词汇检测器 + 提示式 2D 分割**在每帧直接解耦物体。
  ⇒ **语言指令 → 聚焦的类别表 → 自上而下引导检测器**，防止小物件被背景家具吸收。
- **MEM（帧内互斥）**：见结论 3。
- **correspondence reuse**：**用 SLAM 的像素对应**，而不是会漂移的 3D 坐标。
- **性能拆解（关键！每关键帧）**：

  | 阶段 | 耗时 |
  |---|---|
  | YOLO-World 检测 | **30.1 ms** |
  | SAM2 分割 | **132.4 ms** |
  | GAM 计算（每关键帧对） | 9.0 ms |
  | 在线 mask 合并 | 32 ms |
  | **整链** | **10.87 FPS (Replica office0) / 7.32 FPS (ScanNet)** |

  对照：单独 MASt3R-SLAM 是 11.23 / 7.58 FPS ⇒ **实例分割的额外开销几乎为零**（因为复用了 SLAM 的对应）。
- **对我们的意义**：★★★★★
  1. **"SLAM 几何上做 3D 实例分割会崩"** 有权威负面证据（结论 2）
  2. **SAM2 一项 132 ms** ⇒ 印证我们"2D 分割是主要成本"，**必须走 MobileSAM / 关键帧 / 降分辨率**
  3. **task-oriented（类别表自上而下）** 与我们 §12 的"扩词表"思路一致，但它是**用检测器引导分割**，比我们"独立聚类"更省
  4. **整链 10.87 FPS 是在 RTX 3090 上** ⇒ Orin 上要打折，但仍说明**架构可行**

### 2.13 其他开放词汇 3D 实例分割（作为方法池）

| 项目 | 一句话 | 可迁移点 |
|---|---|---|
| **OpenMask3D**（NeurIPS 2023） | 类无关 3D mask + 多视图融合 CLIP 特征 | 需要 Mask3D 提供 3D 提议（重） |
| **Open3DIS**（CVPR 2024） | **2D mask 引导**开放词汇 3D 实例分割 | 2D 引导范式的代表 |
| **MaskClustering**（CVPR 2024） | **视图共识** + mask 图聚类 | "多视图投票"防单帧错误 |
| **OV-Octree-Graph**（ICCV 2025） | 2D mask 按时序分组合并 + 自适应八叉树图；支持实例检索/路径规划 | **八叉树图表示实例占用** —— 与我们的栅格地图可比 |
| **SAM3D** | 无 3D 提议的实例分割 | 上表 AP 8.4 / 17.4 / 18.7 |
| **MaskFusion** | ElasticFusion surfel + Mask R-CNN + **贝叶斯更新** | **作者自述局限：Mask R-CNN 边界不完美，但边界处通常是深度不连续 ⇒ 可用深度做几何细化** |

## 3. 横向对比：三条范式

| | **A. 纯几何法** | **B. 2D 引导法（主流）** | **C. 学习法（3D 网络）** |
|---|---|---|---|
| 代表 | point-cloud-processor、opcseg（背景已去） | OV-MAP、Open3DIS、ConceptGraphs、FindAnything、OVO、ECCV2026 | Mask3D、PointGroup、SAM3D |
| 判据来源 | 法向角 / RANSAC 平面 / objectness 模型 | **2D 分割器（类无关但实例感知）** | 3D 网络学出来的 |
| 需要模型 | 无（或一个小 PointNet） | 1 个 2D 分割器 + 可选 CLIP | 3D 网络（重） |
| 能上边缘 | ✅ | ⚠️（MobileSAM 可，需关键帧/降分辨率） | ❌ |
| 开放词汇 | ❌ | ✅（配 CLIP / YOLO-World） | ⚠️（需额外对齐） |
| 在我们"累积体素地图"上 | **未验证**（为单帧设计） | **业内证明会崩，但有 correspondence reuse 解法** | — |
| 实测 | — | OV-MAP AP25 **23.2**；ECCV2026 10.87 FPS | Mask3D AP25 41.4（上界） |

**读法**：
- **A 是"能用但可能不够"**（我们地图的墙不平面）
- **B 是"对但重"**（要引入 2D 分割器 + 解决漂移几何问题）
- **C 是"好但上不去"**（Mask3D 需要 MinkowskiEngine/稀疏卷积 → **导不出 ONNX**，与 §12 的判死一致）

## 5. 反例与警告（别人踩过的坑，别重踩）

1. **❌ 在 SLAM 重建几何上跑 3D 实例分割** → AP50 31.7 → **0.8**。（ECCV 2026）
2. **❌ 省掉帧内互斥（MEM）** → AP50 23.4 → **8.2**。跨视图级联合并会把整间屋子塌成一个簇。
3. **❌ 只靠 IoU 做 2D–3D 关联** → 相邻相同物体被混成一个。必须加**特征嵌入**（Compositional Object SLAM）。
4. **❌ 用"高度带 / 票数"判物体** → 我们已用 8-run 真值推翻过（"高度带能排除桌椅"）。
5. **❌ 指望 3D 大模型** → MinkowskiEngine CUDA 算子导不出 ONNX（§12 已判死，本次调研再次确认：所有 3D 网络方案都要它）。
6. **❌ 指望开放词汇覆盖"我们没见过的具体物件"** → 灭火器箱 / 栏杆 / 地毯 / 健身器材 / 人形机器人**一个都烤不进 YOLO-World**。
   开放词汇解决**词表宽度**，不解决**具体未见物件**。（só 换判据能解决，见 §6）

## 6. 三个候选方案（按边缘代价从低到高）

### 方案 A ★★☆☆☆（最便宜，立刻可试）：面积/形状先验当判据

**抄 ConceptGraphs 的 `max_bbox_area_ratio=0.5` + MaskFusion 的"边界在深度不连续处"。**

- **做法**：
  1. 在现有 `instances.py` 上加一条：**簇的 bbox 面积占比 > 阈值 ⇒ 判为 stuff（墙/地面），不给 instance id**
  2. 加上**帧内互斥**（同帧不同检测不得合并）
  3. 用 `ground_ever` 做一次"该簇是否曾有地面证据"的交叉检查
- **成本**：**< 半天**，纯 numpy，零新模型，时延不变。
- **判据（可量化）**：**"只落墙"占比从 63.4% 下降到多少？"落空地上"必须保持 ≈0；"落家具上"不能掉。**
- **风险**：**大件家具（衣柜/冰箱）可能被误杀**（Truncated 真值显示 Wardrobe/Refrigerator 从未被认领，要特别看这两个）。

### 方案 B ★★★☆☆（纯几何、可上边缘）：迭代去墙

**抄 `point-cloud-processor` 的第 5–7 步。**

- **做法**：
  1. 在地图上（或每帧点云上）跑 **RANSAC 拟垂直平面**（用**法向角**判定是否为墙面）
  2. **多轮迭代**移除墙面，剩余非地面点再做聚类
  3. 聚类**前**先做"垂直结构掩码"，聚类**后**再做面积/长宽比筛选
- **成本**：**1–2 天**。Open3D/PCL 或纯 numpy（法向可由协方差特征值估）。
- **判据**：**先做 30 分钟小实验 —— 在我们真实 `ground_ever` 栅格上画法向角分布，
  看"墙"是否真的聚成一个可分的角度峰。** 分不开就别继续。
- **风险**：**累积地图的墙因 ATE 0.276 m 不是平面** ⇒ RANSAC 拟不干净（这正是要先用小实验验证的点）。

### 方案 C ★★★★☆（正确但重）：2D 引导 3D + 关键帧

**抄 OV-MAP / ECCV2026 / ConceptGraphs 的主线。**

- **做法**：
  1. **只在关键帧**跑 2D 类无关分割（**MobileSAM 9.66M**，或先用现有 yolo26n 的框当 prompt）
  2. mask **反投影**到 3D（我们已有 LiDAR-camera 外参，虽然只在 yaw≈0 成立 —— **仿真侧要特别注意**）
  3. 用 **correspondence reuse（像素对应）** 而不是 3D 坐标做跨帧关联 —— **避开漂移**
  4. **MEM** + **特征嵌入关联**（不能只用 IoU）
  5. 开放词汇：**YOLO-World v2 + INT8 + TensorRT**，或先不做开放词汇
- **成本**：**1–2 周**起。引入 MobileSAM（可 ONNX）+ 一个关联模块。
- **判据**：**在仿真上必须有真值**（我们已有 `out/_truth_geo.py --dump-models` + `out/_inst_truth.py`），
  对齐口径 p50 0.200 m。
- **风险**：
  - **仿真相机的 yaw 问题**（LiDAR 不随车体转、外参只在 yaw≈0 成立）⇒ **反投影在仿真里天然不可靠**，
    **门必须落在真实 bag 上**，但真实侧**无真值** ⇒ **只能在仿真上验证机制、在真实侧只看一致性（`seen_not_classified_cells`）**。
  - MobileSAM 在 CPU 上 3 s ⇒ 必须关键帧化。

## 7. 建议

**按"每瓦覆盖率"，我的排序：**

1. **先做方案 A 的第 1 条（面积占比筛掉 stuff）** —— 半天，直接冲 63.4%，且**不需要新模型**。
   ⚠️ **但必须先立判据**：不是"看起来好了"，而是 **"只落墙% 下降 / 落家具% 不降 / 落空地≈0"** 三个数一起看。
2. **同时做方案 B 的 30 分钟小实验**（法向角分布）—— 决定纯几何路线值不值得投 1–2 天。
3. **方案 C 先不动**，除非 A + B 都到顶。理由：**C 的真实阻塞不在算法，在仿真外参不可靠 + 真实侧无真值**。
4. **无论走哪条，先补一件没做的事：在指定参考平台上量逐阶段预算**（§12 已列，仍未做）。
   **不量预算就加模块，是在超预算的基础上再超。**
5. **量化这条路（INT8 + TensorRT）是目前唯一"不碰判据就回血"的现成手段** —— 别人实测 2.3×，值得先做在 YOLO-World 上。
