## 0. 结论（先行）

### 0.1 两个实验都**有对象、都改得动** —— boss 的实验设计站得住

改写率（在基准臂的每一次决策上，另一臂是否给出**不同**的目标；判据事前写死 `≥10%`）：

|---|---|---|---|---|---|
| rf0r1 | **60.0%** | **96.0%** | 96.0% | 96.0% | 96.0% |
| rf1r1 | **32.4%** | **92.3%** | 92.3% | 86.5% | 86.5% |
| rf1r3 | **93.8%** | **81.2%** | 81.2% | 93.8% | 93.8% |
| rf1r2 | **37.0%** | **85.2%** | 85.2% | 88.9% | 88.9% |

⇒ 两条路线 **4/4 采集**都远超门槛。**这不是"没咬到"，是"咬得很深"。**

### 0.2 但**读数方向不一致**，而且发现一个**共同的上游成因**

| 采集 | K1 `arrivals` | **E3** | **K4** |
|---|---|---|---|
| rf0r1 | 13 | 12 | **3**（−77%） |
| rf1r1 | 18 | 16 | 16 |
| rf1r3 | 7 | 6 | 7 |
| rf1r2 | 5 | **13**（+160%） | 4 |

* **λ 的效应逐采集不一致**（一处大幅改善、两处略降）⇒ **不能判它"更好"**。
* **K4 唯一 4/4 一致**的读数是 `switches`（目标切换次数）**全部下降**
  （25→17、38→14、20→13、27→21）；但 `arrivals` **在 rf0r1 上崩掉 77%**。
* **K4 的第一次改写位移 = 9.8–13.2 m，4/4 采集**（rf0r1 9.8 / rf1r1 11.5 / rf1r3 13.2 / rf1r2 11.7）
  ⇒ **超过 Gate 3 的「跨区 > 5 m ⇒ 直接失败」**。

### 0.3 ★★ 本轮最重要的发现：**"没对象"与"两代表点相距十几米"共享同一个上游成因**

**先说清楚这句话的强度**（boss，2026-10-07 要求的降级）：

> 二者**不是代码层面的同一个 bug**，而是**共享同一个上游对象粒度问题**：
> 候选生成所依据的 `fresh` 连通分量**尺度过大**。

分开说，因为它们各自的成立条件不同：

* **K1 的"只有一个候选"** 还牵涉 **sweep 候选生成条件**（`sweep_min_m2` / `sweep_min_dist` /
  深度门），一个横跨全屋的对象之所以只出 1 个点，是"每 patch 1 个点"这条规则的作用；
* **K4 的"多个候选跨度十几米"** 牵涉 **同一 patch 内代表点采样**（NMS + 扇区门）。

**共同的部分只有一条**：两者的**分母**都是"一个连通分量"，而这个分量横跨全屋。
后面 complete-linkage 切分做完，如果 K1 仍然常常只有 1 个候选，
**那也是干净的第二条结论**（对象切了，但候选生成条件仍在压制数量），而不是对现在这套论证的否定。
所以正式写法用"共同上游成因"，不用"就是同一个病"。

**证据链（全部可复核）**：

1. **K1（现状）下 `sweep` 层几乎没对象**：`P(≥2 候选)` = **0.00 / 0.02 / 0.00 / 0.29**（4 采集）
   ⇒ 复现 §35 的「41/43 次决策桌上只有 1 个候选」。
2. 而 K4（每个 patch 取 4 个点）从**同一个** patch 取出的点，被选中的那个与 K1 的点
   **相距 9.8–13.2 m**。
   ⇒ **这个 patch 的空间跨度 ≥ 9.8 m。**
3. `sweep_cands_per_patch` **只改"从每个 patch 取几个点"，不改"哪些 patch 合格"**
   ⇒ K4 的点与 K1 的点**必然来自同一个连通分量**（读代码可证，`gather()` 未变）。
4. ⇒ **早期 `fresh = reach & ~visited` 的连通分量 = "整屋未访问地板"**（机器人刚起步，
   只在原点附近有一小片 visited）⇒ **唯一的那个决策对象横跨全屋。**

**所以**：

* **不是 NMS 缺失**：`sweep_cand_sep_m = 1.0` 一直在生效，实测 `sep_min` = **1.1–4.1 m**
  （K4）、**5.3–9.92 m**（K1）⇒ 候选之间**从来没有"太近"过**。
  boss 说的「两个代表点相距 15 m」**是真的，但方向相反** ——
  NMS 管的是**下界**，那个 15 m 是**上界**问题。
* **也不是打分形式不对**：在 sweep 层只有 1 个候选时，打分器**没有被咨询**。

⇒ **A 和 B 现在都泡在"决策对象横跨全屋"这个噪声里。**

**一句话概括（boss 给的版本，已采纳）**：

> 当前主要问题不是"候选太近"，而是**"候选所代表的对象太大"**。

```
NMS 解决的是:            实际遇到的是:
 一个对象                   一个对象
  ├─ 点 A                  ┌──────────────────────────┐
  └─ 点 B                  │                          │
      ↑ 太近 → 去重         │ A                    B   │
                            └──────────────────────────┘
                                  ←── 13 m ──→
                            A 和 B 根本不近，NMS 无能为力
```

| 检查 | 结果 |
|---|---|
| `disc_lambda=0` vs 不传 | `noop_d0_REF.csv` md5 = `c249d08fd3af81431bc7cba0d88ebd71` = `B1` 臂，**逐位相同** |
| `disc_lambda=0.0` vs 不传 | `noop_d00_B2.csv` md5 = **同一个 `c249d08f…`** |
| 整条管线未变 | `lam_*_K1.csv` 的 md5 = **`1a4cd39179e4`（rf1r3）/ `74b7564bf094`（rf0r1）**，与 §44 记录的基线一致 |

⇒ 新开关是**精确 no-op**；`K1` 是**真对照臂**。

**改动面**（共 4 处，全部集中在一个函数）：

```
r2slam/explore.py
  + disc_lambda: float = 0.0            # 构造函数新参数
  + self.disc_lambda = float(disc_lambda)
  + def _fold(self, value, d):
        if self.disc_lambda > 0.0:
            return float(value) * float(np.exp(-self.disc_lambda * float(d)))
        return value / (1.0 + float(d))
  三处调用点改为 self._fold(...)：
      _pick_sweep_target   base = ncell * cell / (1 + d0)   ->  _fold(ncell*cell, d0)
      _pick_shadow_target  score = area / (1 + d0)          ->  _fold(area, d0)
      frontier picker      fsize[i] / (1 + dist[i])         ->  _fold(fsize[i], dist[i])
```

**一处而不是三处**：如果只改一个 picker，臂间差异就可能由"两个 picker 不一致"产生，
而不是由形状本身产生 —— 这正是 §34 付过代价的混淆。

## 5. ★★ 对 boss 判断的一处修正

boss 说：**「NMS 优先级不低于 A。因为同一个 patch 出现两个代表点，距离可达 15 m。」**

**数据说：这句话的左半对、右半反。**

| boss 的说法 | 实测 |
|---|---|
| 「加 NMS（相邻候选只留一个）」 | **NMS 已经在做**：`sweep_cand_sep_m = 1.0`，实测 `sep_min` **1.1–4.1 m**（K4）⇒ **没有"太近"的候选对** |
| 「两个代表点相距可达 15 m」 | **真的**，但它是**上界**问题（K4 首改位移 9.8–13.2 m），**不是 NMS 能管的** |
| 「Region-first + NMS」 | 更准确的表述：**Region-first + 给决策对象加尺度上界** |

**这两件事的关系**（措辞按 boss 2026-10-07 的修正降一级）：
`fresh` 的连通分量在早期就是整屋，所以"只有一个候选"（排序器没活干）
与"两个代表点相距 13 m"（对象太大）**共享同一个上游成因——对象粒度过大**。

⚠️ 但**不要**写成"就是同一个 bug"：前者还牵涉 sweep 候选生成条件、后者牵涉 patch 内采样，
它们只是在"分母是一个横跨全屋的连通分量"这一点上同源。
这么写的好处是：**切分做完若 K1 仍常只有 1 个候选，那是干净的第二条结论，不是本论证被推翻。**

## 6. 建议的下一步（**一个变量**，等 boss 拍）

**先做「给决策对象加尺度上界」，再重跑 A/B。**

具体：对 `fresh` 的连通分量做 **complete-linkage 切分**（簇内任意两点距离 ≤ `link_m`），
`link_m = 3.0 m`。**只加这一条约束**：

* **不是** FUEL 的 `splitHorizontally`（PCA 二分）—— 那会同时改**区域数量**与**区域拓扑**；
* **不动** 区域评分、不动候选评分、不动 `rfirst`、不动 fallback；
* 这正是 boss 列的四项变量里**只动一项**，也回应了"变量太多"的顾虑。

**项目里已经有现成的正结果**（技能 & §30）：用 complete linkage 而不是 single linkage
⇒ `link_m` **顺带成为"点层位移的硬上界"**，实测「`link_m = 3.0 m` ⇒ 整跑最大簇内跨度 2.9–3.0 m」。
⇒ **换成"把已验证过的切分接到 `fresh` 上"，而不是新发明一个机制。**

**做完之后的验收顺序**（boss 2026-10-07 拍板后的版本，已实施在 §50）：

1. **实验 C0（机制实验，不是性能实验）**：先只回答"原来那个 10–13 m 的超大对象是否真的消失"。
   `λ = 0`、`K4` 关闭、NMS 不动、评分不动、fallback 不动、`rfirst` 不动、blacklist 不动。
2. **C1**：`K1` vs `K1 + 切分`（不引入 λ），看 `arrivals` / `switches` / `picks` /
   `≥5 m` 跳跃率 / 最大跳跃 / 首次决策位移 / 决策点空间分布——**原 K1 的 5 次 ≥5 m 跳跃是否消失**。
3. **C2**：`K4` vs `K4 + 切分`——**首改位移 9.8–13.2 m 是否被压到约 3 m 内**。
   若是，则"候选对象尺度 → 候选空间跨度 → 策略跳跃"这条因果链被直接打通。
4. 最后才谈仿真预算与 λ 阶梯。

---

## 7. 局限（必须一起读）

1. **影子重放测决策、不测覆盖**。`reach` / 覆盖率 / 每米收益在本文里**跨臂恒等**，
   所以本文**没有能力**回答"哪个更好"。能回答的是"有没有对象 / 改了多少 / 搬了多远"。
2. **改写率的分母是基准臂的决策点**，而两臂在第 0 个决策就分叉，
   所以这个数是"两条决策序列有多不同"（含传播），**不是"独立改写了多少次"**。
   在影子重放里分不出这两者 —— 这也是为什么它只能当门，不能当结论。
3. **只跑了 4 个采集**（rf0×1、rf1×3），且都是同一场景、同一策略。
4. **λ=1 的强度**在 4/4 采集上与 `K4` 的**改写率**相同、但 3/4 采集上 md5 不同 ——
   "临界强度"这个说法需要更多采集才能确认。
5. **`arrivals` 是决策侧代理**，不是覆盖率：它数的是"指令的目标有没有被记录轨迹靠近过"。
