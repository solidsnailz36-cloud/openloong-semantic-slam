## 1. 四个系统的实际机制（源码级）

### 1.1 FUEL（HKUST，RA-L 2021）—— frontier + 分层巡游

| 环节 | 实际做法 | 出处 |
|---|---|---|
| 探索对象 | **frontier = "free 且六邻域含 unknown" 的格** —— 是**边界**，不是内部未访问区 | `isNeighborUnknown` / `knownfree` |
| 成簇 | 26 邻域 BFS 区域生长；`z < 0.4` 剔除地面噪声 | `expandFrontier` |
| 尺寸过滤 | 体素数 > `cluster_min_` | `searchFrontiers` |
| **大簇切分** | **超过 `cluster_size_xy_` 就沿 PCA 第一主轴二分** | `splitHorizontally` |
| 视点生成 | 极坐标网格采样位置（`candidate_rmin_`→`rmax_`，`candidate_dphi_`），**再加 6 个 yaw 候选取增益前 3**（20° 步长、9 片 80° hFOV） | `sampleViewpoints` / `findViewpoints` |
| 视点价值 | `visib_num_` = `countVisibleCells()` **可见的 frontier 格数**（含 FOV 判断 + 逐格 raycast） | `countVisibleCells` |
| 视点排序 | 按 `visib_num_` 降序，**`front()` 即最优** | `computeFrontiersToVisit` |
| **代价 vs 价值** | **cost 矩阵是纯移动代价**（`ViewNode::computeCost`）；**`visib_num_` 不进矩阵**，只用于筛选/排序视点 | `getFullCostMatrix` / `updateCost` |
| 选择 | 全局 **ATSP**（LKH）→ `refineLocalTour` 用 GraphSearch+Dijkstra 在前 K 个簇的 top-N 视点间找最优序列 | `findGlobalTour` / `refineLocalTour` |
| fallback | ①找不到视点的 frontier 进 **`dormant_frontiers_`**；②`NO_FRONTIER`；③无路径 `FAIL`；④**近/中/远三级目标回退**（`radius_close=1.5` / `radius_far=5.0`） | `frontier_finder.cpp` / `fast_exploration_manager.cpp` |

### 1.2 NBVPlanner（ETH-ASL，ICRA 2016）—— RRT + 信息增益

| 环节 | 实际做法 | 出处 |
|---|---|---|
| 候选生成 | **RRT**。新节点在**球内均匀随机采样**（半径 = 探索空间对角线），叠加 root 偏移，再按 `softBounds_` 裁剪；最近邻后**截断到 `extensionRange_`** | `rrt.cpp: iterate()` |
| 采样偏置 | **无**。源码注释原文：*"This method is to not bias the tree towards the center of the exploration space."* |
| 增益 | `gain(state)`：在 `gainRange_` 内的体素上遍历，逐格做 FOV 判断 + `getVisibility` raycast，按格状态累加 `igUnmapped_` / `igOccupied_` / `igFree_`，最后 `gain *= pow(disc, 3.0)`；若有 mesh 再加 `igArea_ * computeInspectableArea` | `rrt.cpp: gain()` |
| **沿分支累计** | `newNode->gain_ = newParent->gain_ + gain(newState) * exp(-degressiveCoeff_ * distance_)` | `rrt.cpp: iterate()` |
| 去重/重叠惩罚 | **没有**。只有上面的**指数距离衰减**；`gain(state)` 本身无状态、无去重 | 同上 |
| **选择** | **`if (newNode->gain_ > bestGain_)`** —— **纯增益最大化，没有除以或减去任何代价** | 同上 |
| yaw | 新节点独立随机采样 yaw；`gain()` 里用 yaw 旋转相机视场法向；路径插值按 `dyaw_max_` 离散 | `samplePath` |

### 1.3 ASE（Tampere，RAS 2016）—— 前向模拟 + 互信息

| 环节 | 实际做法 | 出处 |
|---|---|---|
| **候选单位** | **轨迹**（每条由 `horizon` = 3 个控制动作组成），不是点 | README §7 |
| 生成方式 | **序列蒙特卡洛**：第 1 轮在均匀分布上采样（`num_particles` = 10 条），后续轮用**以上一轮轨迹为中心的高斯核**改进；采样数按 `k = a·i + b` 递增 | `schedule_a/b`、`num_kernels` = 5 |
| 奖励 | **地图与未来观测的互信息**，用**模拟激光**在多个"地图假设"上 raytrace | README §7 模拟激光参数 |
| 有效性门槛 | `min_traj_length` = 0.2 m、`min_reward` = 30（≈ 期望看到的新格数） | README |
| 折扣 | `discount`（1.0 = 不偏好即时收益） | README |
| **fallback** | **明确存在**：*"the planner detects whether the robot might be stuck or if the local trajectories it has sampled are not very informative. If this happens, the planner will instead apply **classical frontier-based exploration** ... and afterwards again resumes planning via forward simulation"* | README 首段 |

## 2. 逐项对照：我们 vs 成熟系统

| 维度 | FUEL | NBV | ASE | ROS2 | **本项目** |
|---|---|---|---|---|---|
| **探索对象** | frontier（**边界**，薄） | RRT 节点（空间均匀） | **轨迹** | frontier（**边界**） | **patch = 未访问的**内部地板**（**面**，可达 120 m²） |
| 对象是否天然有尺度上限 | **是**（`cluster_size_xy_` + PCA 切分） | 是（采样密度） | 是（轨迹长度） | 是（边界很薄） | **否** |
| 每对象几个候选 | 多个视点 × 6 yaw 取前 3 | 每节点一个 | 每条轨迹 | 每 frontier 一个 | **1（K=1）/ 4（K=4）** |
| 价值量 | `visib_num_`（可见前沿格数） | 射线可见体素加权 + mesh 面积 | **互信息** | information gain | **patch 面积** |
| 代价 | 移动代价 → **ATSP** | **不做除法**，指数衰减 | 折扣 | 独立过滤 + 打分 | **`size/(1+d0)`** |
| 选择 | TSP + 图搜索精化 | `argmax(gain)` | 粒子滤波 | 排序 + top-N | 排序取第一 |
| 视点层 | **有**（极坐标网格 + yaw 候选） | 有（节点即视点） | 轨迹即视点序列 | 有（goal 生成） | **弱**：`shadow` 只在盲点用 |
| 失败处理 | dormant frontier + 三级回退 | 无 | **退回经典 frontier** | blacklist + cooldown + watchdog + top-N | blacklist / denied |
| 对"某房间没被探索"的机制 | 该 frontier 找不到视点 ⇒ dormant，或 TSP 未选中 | 采样未覆盖 | — | 进不了 reachable 集 | **patch 只有一个代表点，方向被 tiebreak 决定（§35/§36）** |

## 3. 结论一：**"一个大区域只用一个代表点"这个问题，成熟系统里根本不存在**

四个系统的探索对象分别是：**边界**（FUEL、ROS2）、**均匀采样点**（NBV）、**轨迹**（ASE）。
**没有一个把"一坨未访问的地板"当作一个决策对象。**

* frontier 在空间上是**薄**的 —— "一个 frontier 一个视点"不会丢信息；
* RRT 的采样密度是**空间均匀**的，与连通性无关；
* 轨迹本来就是**一条空间序列**。

⇒ **我们 §35/§36 量到的"同一个 patch 两个代表点相距 15 m、87.7% 发生"，
不是"代表点规则没选好"，而是"我们选了一个成熟系统都不用作决策单位的对象"。**
boss 问的"表达能力差异"，根源在这里 —— **不是少了一层 viewpoint，而是对象选得不一样。**

---

## 4. 结论二：**"价值 ÷ 距离"这个形式，四个系统里只有我们在用**

* **FUEL**：cost 矩阵**纯移动代价**，交给 ATSP 求最优巡游；`visib_num_` 只用于**筛选和排序视点**。
* **NBV**：`gain_ = parent.gain_ + gain(state)·exp(-λ·distance_)`，选 `argmax(gain_)` ——
  **代价以指数衰减的形式进入增益内部，而不是把增益除掉。**
* **ASE**：`discount` 是一个独立因子，收益与代价不混在一个除法里。
* **ROS2**：information-gain 打分 + **独立**的距离/范围/净空过滤。

⇒ 这正好解释 §33（观察位价值 1.55 倍输给 3.9 m 的距离折算）与 §34（候选代表点由 `cd` 挑）：
**"距离压倒价值"不是我们实现得不好，是这个形式本身的性质** ——
而成熟系统要么用 TSP 解代价，要么用指数衰减，**都不做这个除法**。

---

## 5. 结论三：我们**两条腿都有**，但主力是自创的那条

`explore.py` 里其实有两套候选族：

| 我们的机制 | 对标 | 判定 |
|---|---|---|
| `frontier` picker（边界 + 扇区） | FUEL / ROS2 的 frontier | **成熟范式** ✓ |
| `island`（门口探针） | FUEL 的 doorway / 前沿跨门 | 自创，思路接近 |
| `shadow`（盲点观察位） | **NBV / FUEL 的 viewpoint** | **成熟思想，但是弱实现**（只在"盲点"触发，不是系统化的视点采样） |
| **`sweep`（patch = 未访问地板，按面积/(1+d) 排序）** | **无对应** | **★ 自创，而且是实跑主力** |

**而 §23–§36 的全部问题都出在最后这一条上。** 泛化风险因此非常集中：
`WorldMap → fresh → patch → score → representative` 这一整段是自创的，
而 rest（A*、planner、frontier、帧同步、地图）都是成熟做法。

## 6. 三处与二手转述不符的地方（必须纠正）

| 转述 | 源码实际 |
|---|---|
| NBV 用"**候选树**"并带"**候选间重叠惩罚（overlap penalty）**" | 候选是 **RRT 球内均匀随机采样**；**没有任何重叠惩罚或去重**，只有 `exp(-degressiveCoeff_ * distance_)` 这条沿分支的指数衰减 |
| FUEL 的 frontier **按 gain/cost 打分** | `frontier_finder.cpp` 里 **gain 不进 cost 矩阵**。矩阵全由 `ViewNode::computeCost` 产生；`visib_num_` 只排序/筛选视点。（gain/cost 的组合需再查 `graph_node.cpp` 的 `computeCost`，但**至少不在这里**） |
| "FUEL 把大区域切成子区域"是我们要借鉴的**新想法** | FUEL **早就在做**：`cluster_size_xy_` 阈值 + `splitHorizontally` **沿 PCA 第一主轴二分**。我们要做的"限制 patch 尺度"**有现成参考实现** |

## 7. 对本项目的直接含义（不改代码）

1. **`sweep`/patch 这条腿是自创的，而且是主力** ⇒ 泛化风险集中在这里，这与"真实场景不一样怎么办"
   的担心是同一件事。**成熟系统不拿"面"当决策单位**。
2. **"价值÷距离"要改** —— 但不是改成另一个权重，而是改成成熟系统的两种形式之一：
   **代价进 TSP / 图搜索**（FUEL），或**代价以指数衰减进入增益内部**（NBV）。
   §33 的 `V_deficit` 正好可以直接接进后者：`gain = Σ w_r·A_new · exp(-λ·d)`。
3. **视点层要从"盲点专用"升级成"系统化采样"** —— FUEL 的做法可直接抄结构：
   **极坐标网格采位置 + 若干 yaw 候选取增益前 N**，`visib_num_` 排序。我们的 `shadow` 已经是雏形。
4. **fallback 要补一层** —— ASE 的"高级策略失效就退回经典 frontier"与 ROS2 的
   `failed-goal blacklist(r=1 m, cooldown 90 s)` / `stuck watchdog(12 s)` 都是低成本、可直接照搬的保险。
5. **不要整套搬 FUEL**（boss 已明确）：有价值的是**机制**；而且我们的地图/规划/建图侧是成熟的，
   不该动。

**下一步（要 boss 拍）**：是否把 §33 的 `V_deficit` 按 NBV 的形式（`V·exp(-λd)`）做一次离线对照，
与现在的 `V/(1+d)` 并排比较 —— **仍然不接 planner、不跑仿真**。
