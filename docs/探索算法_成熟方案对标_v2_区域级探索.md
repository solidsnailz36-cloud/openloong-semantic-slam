## 0. 结论（先行）

### 0.1 三个判定

| 问题 | 判定 |
|---|---|
| **Region-first（先区域、再在区域内选点）是重复造轮子吗？** | **不是。** 这个结构在成熟系统里是**标准做法**：LRAE / TARE 几乎是同构的，FUEL / GBPlanner2 是它的变体。 |
| **Region-first 是"合理改造"吗？** | **是，但只改对了一半。** 结构对，**排序层的形式错**。 |
| **哪一处是自创的（而且是错的）？** | **`score = 价值 ÷ (1 + 距离)`。10 个系统里没有一个用除法。** |

### 0.2 三个可直接搬走的机制（按价值排序）

1. **★★ 排序层的形式：`Σ Vᵢ·exp(−λ·累计路程ᵢ)` + 2-opt，λ ≈ 3.0。**
   FAEL（`two_opt.h:57 computeUnity`）与 LRAE（`two_opt.h computeUnity`）**用的是同一个模板、同一个 λ=3.0**。
   GBPlanner2 是同一族的单步版本（`rrg.cpp:2452` `gain·exp(−penalty·path_length)`）。
   ⇒ **候选不是"选一个点"，而是"排一条巡游顺序"，只执行第一站，滚动重规划。**
2. **★★ 区域内选点用「归一化等权相加 + 非极大值抑制」**，LRAE `assessUnknownRegion` + `purgeViewpoint`：
   `score = Σ wₖ·(xₖ / max xₖ)`，然后 **NMS：相邻视点只留一个**（`|Δix|+|Δiy| > 1`）。
   ⇒ 这直接给了我们 §35/§36「同一个 patch 两个代表点相距 15 m、87.7% 发生」的**成熟解法**。
3. **★ 复访抑制不是 blacklist，是"消耗"。**
   FAEL：视点离机器人 < `sample_dist_/2` 时，**把它负责的 frontier 从 `global_frontier_cells_` 里 erase**
   （`viewpoint_manager.cpp:170-180`）——"完成"是一个**显式的擦除动作**，不是超时拉黑。

### 0.3 一条反直觉的实测

**explore_lite（最广泛部署的 2D frontier 探索器）的默认参数下，距离项被压掉约三个数量级。**

`frontier_search.cpp:192-197`：

```cpp
double FrontierSearch::frontierCost(const Frontier& frontier) {
  return (potential_scale_ * frontier.min_distance * costmap_->getResolution())
       - (gain_scale_ * frontier.size * costmap_->getResolution());
}
```

而 `min_distance` **本来就是米**（`:153-156`，由 `mapToWorld` 后的世界坐标算欧氏距离），
`size` 是**格数**。乘上同一个 `res` 之后：

| 项 | 表达式 | 量级（res=0.05） |
|---|---|---|
| 距离项 | `1e-3 × d_m × res` | `5e-5 · d_m` |
| 增益项 | `1.0 × size_cells × res` | `0.05 · size_cells` |

⇒ 增益/距离的量级比 ≈ **`1000 · size_cells / d_m`**。
一个 100 格（5 m）的 frontier 在 10 m 外 ⇒ 比值 **约 10000 倍**。

**⇒ 默认参数下它实际上在"最大化 frontier 尺寸"，距离只是尾数。**
（顺带：把"米"再乘一次 `resolution` 看起来是**原仓库的单位不一致** ——
ROS1 `explore.cpp:67-69` 与 ROS2 `explore.cpp:68-71` **默认值完全一样**，所以这不是移植引入的。）

**这与我们"距离压倒价值"（§33 实测 3.9 m 就折掉 3 倍）正好相反。**
⇒ **"价值÷距离"和"距离权重≈0"是两个极端，而中间那一档（指数衰减）才是主流。**

### 2.6 FUEL（`HKUST-Aerial-Robotics/FUEL`）—— 簇 + PCA 切分 + ATSP（v1 已拆，此处摘要）

- frontier = "free 且六邻域含 unknown"（`isNeighborUnknown`）；26 邻域 BFS 区域生长（`expandFrontier`）
- **簇超 `cluster_size_xy_` ⇒ 沿 PCA 第一主轴二分**（`splitHorizontally`）
- 视点：极坐标网格采样 + 6 个 yaw 取增益前 3（`sampleViewpoints`/`findViewpoints`）
- 增益 `visib_num_` = 可见 frontier 格数（`countVisibleCells`）
- **选择：全局 ATSP（LKH）→ `refineLocalTour`（GraphSearch+Dijkstra 在 top-K 簇的 top-N 视点间精化）**
- **cost 矩阵是纯移动代价；`visib_num_` 不进矩阵**（`getFullCostMatrix`）
- fallback：`dormant_frontiers_` + 无路径 `FAIL` + **近/中/远三级半径回退**（`radius_close=1.5`/`radius_far=5.0`）

**★ 最独特**：**"大簇按 PCA 主轴切分"** —— 这是我们"限制 patch 尺度"的现成参考实现。

## 3. ★ 六个维度的横向对比

### 3.1 区域选择

| 系统 | 区域怎么定义 | 区域怎么排序 |
|---|---|---|
| LRAE | 滑动窗口内的未知格簇（`unknown_num_thre_=80`） | **TSP：`Σun·exp(−3·累计代价)`** |
| TARE | 世界固定 **18 m 网格 cell** | **贪心集合覆盖 → TSP → 取最短** |
| FUEL | frontier 簇（26 邻域 BFS），超 `cluster_size_xy_` **按 PCA 主轴二分** | **ATSP（纯代价矩阵）** |
| FAEL | **无独立区域**；"区域"= 视点负责的 frontier 集合 | 半：local(<5 m) 优先于 global |
| GBPlanner2 | **compartment（config 预设中心 + 尺寸）** | **按预设顺序，不算** |
| mav_3d_planning / rrt_exploration / explore_lite / ros2_explorer / ActiveSLAM | **无** | — |

**⇒ "区域级"在 5/10 个系统里存在。它不是新想法。**
**但"区域"的定义方式没有统一答案**：滑动窗口 / 固定网格 / frontier 簇 / 外部给定，四种都有。

### 3.2 代价与价值怎么组合（本节最重要）

| 系统 | 形式 |
|---|---|
| **explore_lite** | `1e-3·d_m·res − 1.0·size_cells·res` ⇒ 增益压倒距离约 `1000·size/d` 倍（**≈只看尺寸**） |
| **ros2_explorer** | 只有未知量，**没有代价** |
| **rrt_exploration / ActiveSLAM** | `gain×3 − d`（**加权和**） |
| **LRAE / FAEL** | **`Σ gainᵢ·exp(−λ·累计路程ᵢ)`，λ = 3.0**（2-opt TSP 的目标） |
| **GBPlanner2** | `gain·exp(−penalty·length)`（**单步版**，argmax；默认 penalty=0） |
| **FUEL** | **cost 矩阵纯移动代价 → ATSP**；价值只用于筛选/排序视点 |
| **mav_active_3d_planning** | **三种都有**：`gain/cost`（默认）/ `gain·exp(−λc)` / `w_g·gain − w_c·cost` |
| **TARE** | 不组合：**贪心集合覆盖选点 → TSP 最小化路径长度** |
| **NBVPlanner**（v1） | `parent.gain + gain(state)·exp(−λ·d)` |
| **本项目** | **`size / (1 + d)`** |

**⇒ 10 个系统 + v1 的 NBV = 11 个，没有第二个用"价值 ÷ 距离"。**
**唯一另一个用除法的（`mav_active_3d_planning` 的默认 `GlobalNormalizedGain`）**，
它的除法是在**轨迹树内部按子树取 max(gain/cost)**，是"归一化排序"，不是"单步折算"。
**⇒ `V/(1+d)` 是自创的，而且带结构性后果（§33：3.9 m 就折掉 3 倍）。**

### 3.3 重复访问抑制 / 防饿死

| 机制 | 系统 | 关键参数 |
|---|---|---|
| **目标黑名单** | explore_lite | 同目标 + **30 s** 无进展 ⇒ 拉黑；abort 也拉黑 |
| **滞回（偏好当前区域）** | rrt_exploration、ActiveSLAM | `hysteresis_radius=3.0`、`hysteresis_gain=2.0` |
| **增益折扣** | rrt_exploration、ActiveSLAM | 已被认领质心附近的未知格 gain −1 |
| **显式擦除（"完成"）** | FAEL | 视点到达 ⇒ 把它负责的 frontier 从 `global_frontier_cells_` erase |
| **已观测体素 erase** | mav_active_3d_planning | `isObserved` 的体素从增益统计里去掉 |
| **不加重复顶点** | GBPlanner2、TARE | `kRangeCheck=0.5` / `kUpdateRadius=2.0` / `ViewPointVisited()` |
| **卡死自愈** | ActiveSLAM | >10 s 且位移 < 0.2 m ⇒ reset；ABORTED > 1.5 s ⇒ reset |
| **复用上一轮视点** | TARE | 若仍能覆盖 ≥ `kMinAddPointNum` 个未覆盖点 |
| **无任何机制** | ros2_explorer、rrt_exploration（无 fallback） | — |

**⇒ 三种主流做法：黑名单（超时）/ 滞回（偏好当前）/ 消耗（显式擦除）。**
我们现在的 `blacklist` 是第一种，**缺"消耗"和"滞回"**。

### 3.4 未知空间表示

| 表示 | 系统 |
|---|---|
| 三态 OccupancyGrid（-1/0/100） | explore_lite、ros2_explorer、rrt_exploration、LRAE、ActiveSLAM |

| TSDF/ESDF 体素三态 | mav_active_3d_planning（voxblox）、GBPlanner2（map_manager） |
| **没有一处用显式 log-odds** | — |

**⇒ 没有任何一个系统用"标准 log-odds 占据栅格 + 射线自由空间"。**
⇒ v1 里我建议的"换成 log-odds 占据栅格"**是一个有依据的方向，但没有现成对标**；
真正普遍的做法是"**三态 + 显式的模糊/假障碍后处理**"（见 3.6）。

### 3.5 信息增益怎么算

### 3.6 动态 / 错误障碍鲁棒性

## 4. ★★ 对 Region-first 的判定

### 4.1 结构层：**不是重复造轮子**

`Region-first → 先选区域 → 区域内再选 point` 这个结构与下列系统**同构或近似同构**：

| 系统 | 它的两级 |
|---|---|
| **LRAE** | 区域（Centroid）级 TSP → 区域内视点选择（含 NMS） |
| **TARE** | 全局 cell 级 TSP → 局部视点集合覆盖 + TSP |
| **FUEL** | 全局 ATSP over frontier 簇 → `refineLocalTour` 局部精化 |
| **GBPlanner2** | global frontier 图 → 局部 RRG；再加 compartment 状态机 |
| **FAEL** | local(<5 m) → global（空间范围两级，不是语义两级） |

**⇒ "两级决策"在成熟系统里是主流。Region-first 的结构是合理改造，不是重复造轮子。**

### 4.2 参数层：**改对了一半**

**对的部分**：结构、以及"限制候选尺度"这个动机（FUEL 的 `cluster_size_xy_` + PCA 切分、
TARE 的 18 m cell、LRAE 的滑动窗口 —— **成熟系统都在限制决策对象的空间尺度**）。

**错的部分（三处，按严重度）**：

1. **★★★ 排序层的组合形式。**
   我们：`V/(1+d)`。他们：`Σ V·exp(−λ·累计路程)`（LRAE/FAEL，λ=3.0）/ ATSP（FUEL）/
   `gain·exp(−penalty·length)`（GBPlanner2）/ `gain×3 − d`（rrt_exploration）/
   贪心覆盖 + TSP（TARE）。**没有一个用除法。**
   ⇒ **Region-first 要落地，第一件事是把区域排序换成"指数衰减 + TSP"，而不是继续调 `V/(1+d)`。**
2. **★★ "区域内选点"必须变成"选一组点并排序"。**
   除 explore_lite / ros2_explorer / rrt_exploration（它们只有一个点）外，
   **LRAE / FAEL / TARE / FUEL / GBPlanner2 都是"选一组 → 排序 → 只执行第一站"**。
   我们**选一个点、执行到底**。这是我们 §35/§36 那个"同一个 patch 两个代表点相距 15 m"的另一个根源。
3. **★★ 代表点之间要有 NMS。**
   LRAE `purgeViewpoint` 的 `|Δix|+|Δiy| > 1` 是**现成的**一行代码级的解法。

### 4.3 一处可以直接抄的"区域切分"

**FUEL 的 `splitHorizontally`：簇超 `cluster_size_xy_` 就沿 PCA 第一主轴二分。**
这是**"限制区域尺度"**的现成实现 —— 而我们 Region-first 的动机正是这个。
**它比"按房间切"更通用**（不需要房间语义），而且**保证区域有尺度上界**。

### 4.4 一条明确的负面结论

**"区域排序按增益排序"不是通用做法。** GBPlanner2 的 compartment **按预设顺序**推进，
TARE 的区域（cell）顺序由**全局 TSP 的代价**决定而不是增益。
⇒ **"哪个区域更重要"这个量，成熟系统要么不单独算（并入 TSP 目标函数），
要么由外部给定。我们把它单独拎出来当第一级排序，是一个需要论证的设计。**

## 8. 结论一页纸

```
问题：Region-first 是合理改造还是重复造轮子？
答案：结构 = 合理改造（LRAE/TARE 几乎同构）；
      排序形式 = 自创且错（10/10 不用除法）；
      区域内选点 = 缺"一组 + 排序"，只选一个点；
      代表点 = 缺 NMS。
```

**一句话**：**Region-first 的"两级"抄对了，但每一级内部的形式都没抄。**
成熟系统的两级是"**TSP（区域层）+ 集合覆盖/TSP + NMS（点层）**"，
我们是"**`V/(1+d)` 取第一（区域层）+ `V/(1+d)` 取第一（点层）**"。
