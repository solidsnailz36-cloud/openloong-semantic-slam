## 0. 结论

**第三层不是"走不到"，是"最后 0.3 m 到不了，到了也不结账"。**

拆成两条，**第二条是根因**：

1. **起步代价是结构性的**：`island` 只在 sweep/shadow/frontier **全部无候选**时才被调用
   （`command()` 的最后手段）。所以每次轮到它，航向已经指向别处：实测 **11 次 kind 切换，
   10 次伴随 `|err| > 25°`、8 次 `> 90°`，中位 115°**。而 1 次 probe 在旧语义下只有 12 帧。

2. **★ 根因：目标点的几何位置与 `_ahead_clear` 的尺度不相容。**
   `_pick_island_probe` 把目标选成"patch 内**距 `reach` 最近的格**"，而 `reach` 的边界就是
   障碍膨胀边界 ⇒ **目标点必然紧贴障碍**。实测（4/4 跑）：**目标点到最近 blocked 格
   0.40–0.60 m**。而 `_ahead_clear` 要求**正前方 0.7 m 净空**（`front_stop = 0.75`，
   查 `0.1…0.7 m`）。两者只差 **0.1–0.35 m**。
   ⇒ 机器人越接近目标，正前方就越是那个障碍 ⇒ `aligned && !ahead` ⇒ **`mode = "wedge"`
   ⇒ 立即 `backoff`**。

**而且 probe 没有"到达"终止条件**（`n_arrivals` 只在 sweep/frontier 分支自增）⇒ 到达 0.21 m
也不算数，patch 在门口清不掉（2.86 → 2.68 m²，只清 6%），目标不消，**形成自持振荡**。

**判定表**

| 候选 | 结论 | 依据 |
|---|---|---|
| **C1 转向控制有问题** | **不成立** | P2 段 `\|err\|` 从 **149.1° → 0.9°**；live 四跑 `err_yaw_deg` 最大 24–84° |
| **C2 规划目标 ≠ 跟踪目标** | **P1/P2 不成立，P3 成立** | `\|aim − goal\|`：P1 `0.0/0.0`、P2 `0.0 / p90 2.0 / max 2.2°`；**P3 med 51.1°、max 60.5°、drift 13.47 m** |
| **C3 局部避障 / backoff 卡在门口** | **★ 成立，且是几何必然** | 见 §4 |

## 1. 先说清两个数据源各自能测什么

**这一节是必需的**，否则会像本轮的初稿一样把"记录轨迹的性质"读成"策略的代价"。

| 源 | 位姿来源 | 能测 | **不能测** |
|---|---|---|---|
| replay `out/island2/full54_T0.csv`（1417 帧） | **记录轨迹**（KISS-ICP），策略输出**不回灌** | 策略当场算的一切：`state`/`mode`/`target`/`heading_err`/`ahead`/`wedge`；目标生命周期；几何判定 | **指令 → 运动的传递**。`turn` 到底有没有转起来，replay 判不了 |
| live `out/island/A0I_r{1..4}_frames.csv`（各 ≈1530 帧） | **真闭环** | 传递、真值位姿（`truth_*`、`err_yaw_deg`） | **probe 活不过 12 帧**（见 §2），够不到"最后 0.3 m" |

> ⚠️ **踩过的坑**：`replay_explore.py` 写的 `yaw` 列是**弧度**，`online_pipeline.py` 的
> `yaw_deg` 是**度**。第一版手工脚本把 replay 的 `yaw` 当度用，算出 "`aim − goal` = 8.6–109°"
> 的**假结论**。修正后（`aim = yaw[rad] + radians(err)`）偏差是 **0.0–2.2°**。

## 4. ★★ C3 的根因：0.40–0.60 m 对 0.70 m

`_pick_island_probe` 的目标点 `(gx, gy)` 取自 `reach` 窗口内"距 patch 格最近"的**可达格**
（`explore.py` 2893–2900）。`reach` = 按半径腐蚀后的可达区，**它的边界就是障碍膨胀边界**
⇒ **目标点按构造必然紧贴障碍。**

用 live 四跑的**最终障碍层**（`grids_A0I_r*`）量 replay 探针的目标点
（同一世界系，`res 0.10 / extent 30.0`）：

| 目标点 | → 最近 **blocked** 格 | → 最近 `obstacle` 格 | 在 blocked 上？ |
|---|---|---|---|
| `(−1.45, 5.95)` | r1 **0.50** / r2 **0.50** / r3 **0.60** / r4 **0.60** | 同 | 否 |
| `(−1.35, 5.95)` | r1 **0.40** / r2 **0.40** / r3 **0.50** / r4 **0.50** | 同 | 否 |

⇒ **4/4 跑全在 0.40–0.60 m，全部 < `front_stop = 0.75 m`。**

驻留点（f572，机器人 `(−1.65, 6.06)`，`dist = 0.32 m`）朝当前 `yaw` 看第一个 blocked 格：

| 地图 | 第一个 blocked 距离 | `_ahead_clear`（查 `0.1…0.7 m`） |
|---|---|---|
| r1 / r2 | **0.70 m** | **False ⇒ wedge** ✅（与 replay 实测 `ahead=False, wedge=True` 一致） |
| r3 / r4 | 0.80 m | True ⇒ 不触发 |

**完整机制链**：

```
_pick_island_probe 的目标 = "patch 内距 reach 最近的格"
        │  reach 的边界就是障碍膨胀边界
        ▼
目标点必然紧贴障碍            ── 实测 0.40–0.60 m（4/4 跑）
        │
        │  front_stop = 0.75 m，steps = 7 ⇒ _ahead_clear 查 d = 0.1 … 0.7 m
        ▼
机器人走近目标（越近越必然）⇒ 正前方 0.7 m 内就是那个障碍 ⇒ ahead = False
        │
        ▼
aligned (|err| ≤ turn_only_deg 25°) && !ahead  ⇒  mode = "wedge"
        │
        ▼
立即 backoff：10 帧，v = −0.248，w = −0.495
        │  故意反打 ⇒ |err| 从 8.1° 打坏到 74.1°
        ▼
退出后 err 大 ⇒ turn（v = 0）花 ≈1.7 s 转回来
        │
        ▼
再接近 ⇒ 再 wedge        ⇒  dist 锁死在 0.30 m，patch 清不掉，probe 不结
```

**注意它不是"每次都触发"**：r3/r4 的地图把那个格画在 0.80 m ⇒ 落在 `0.1–0.7` 之外 ⇒ 不触发。
**这正是它一直没被抓到的原因**——跑间地图差一格，行为就差一个状态机分支。

### 4.1 附带确认：probe 没有"到达"终止条件

- `n_arrivals` 只在 sweep/frontier 分支自增（`explore.py` 4963 / 4974），**island 分支没有**。
- probe 的结束只靠两条：`self._probe & ~visited` 变空，或目标跳变 > `island_probe_same_m`。
- 实测 P2：`patch_m2` **2.86 → 2.68**（只清 6%），而机器人已在门口 0.3 m。
  ⇒ **站在门口清不掉门内的地板** ⇒ patch 不消 ⇒ 目标不消 ⇒ **无限重试同一格**。

### 4.2 顺带：`aim` 是对的，控制器没有跟错点

`heading_err_deg` 的定义是 `atan2(aim − pose) − yaw`，所以 `aim = yaw + heading_err` 是**可反算的**。
反算结果（P2）：`|aim − goal|` 中位 **0.0°**、p90 2.0°、max 2.2° ⇒ **前视点就是目标点**，
`_lookahead` 在这段没有把机器人带偏。**C2 在 P2 不成立，可以排除。**

风险最大，要留到最后。

**★ 不要动的东西**：`island_trigger_m2`（r4 的模式 B 是独立问题）、`island_min_m2`
（实测 patch 2.7–2.9 m²，是门槛 5 倍以上）、`0.5`/`link_m`/`d0`/价值函数。

## 6. 本轮修正的两个口径（纪律，已落进工具）

1. **backoff 的归因必须按事件、不能按帧。** `state == "backoff" and wedge` 按帧数会报 **3**，
   而实际只有 **1 次**事件——`backoff` 持续 `backoff_frames`（10）帧，`wedge` 只在**触发那一帧**为真。
   正确做法：找 `backoff` 的连续段，读**段首帧**的 `wedge`。
2. **`heading_err_deg` 是带符号的。** "最小角误差"必须用 `abs()`；原写法 `min(errs)` 拿到的是
   **最负**的那个（-93.2 会被读成"最小"）。
