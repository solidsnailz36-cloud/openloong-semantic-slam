# 项目改进空间评估 · 2026-10-09

> boss 三问：**① 还有哪些改进空间？② 把 YOLO 换成 YOLO-World 有效果么、明显么？③ GitHub 上有什么可借鉴的？**
> 本文按"结论 → 证据 → 建议顺序"写，数字全部取自 `r2slam/out/` 的产物，没有凭印象的值。

---

## 0. 先直接回答第 ② 问

### 0.1 有效果么？**有。**

全量 1427 帧真实数据、同一份 bag、**背靠背跑**（`out/full2_y26n` vs `out/full3_alias51_f32`）：

| | `yolo26n`（COCO-80 @640） | **`yoloworld_alias_320`（自定 51 词 @320）** |
|---|---|---|
| detector boxes | 851 | 706 |
| localised | 630 | **611（−3.0%）** |
| 地图里的类数 | 5 | **6** |
| **`fire extinguisher` 观测 / 实例 / 点** | **0 / 0 / 0** | **25 / 5 / 112** |
| `clock` / `handbag` | 0 / 0 | 3 / 2 |
| `suitcase` / `bottle` | 27 / 6 | **0 / 0** |
| `ms_detect` p50 | 64.6 ms | **61.7 ms** |
| 位姿 / 几何列 | — | **1427 帧逐位相同** |

**"有效果"的那一半**：`fire extinguisher` 是 **COCO 80 里根本没有的类**，它第一次进了交付物。
这是"我们自己定词表"这个能力唯一的、真实的兑现。

### 0.2 明显么？**不明显。**

- 一栋楼里**多标出 1 个类**（而且是观测稀疏的：最稳的实例 18 次观察），代价是**丢 2 个 COCO 类**。
- 实例数 **22 → 20**，localised **−3%**。**按"地图里有多少可信物体标注"算，这是一笔近乎打平的买卖。**
- **当初想要的东西一个都没拿到**：`humanoid robot`、`gym equipment` 仍然 0（见 §1.2）。

⇒ **准确的说法不是"换成 YOLO-World 有效果"，而是：**
> **"我们花了一次换模型的功夫，买到一个'以后可以自己定词表'的接口。这个接口现在兑现率是 1/3。"**

而且要注意：**它不是升级，是换了一种取舍**。新模型 backbone 更强（12.75 M vs ~2.4 M），但分辨率从 640 降到 320，**丢的正是"小且静止"的物体**。这个取舍在设计上是合理的（5 Hz 预算），但**不能当成"更强的检测器"来卖**。

## 1. ★ 今天顺手挖到的两件事（第 ① 问的核心）

### 1.1 ★★ 我们一直喂给 CLIP 的是**光秃秃的名词** —— 而且**整表套模板是净回归**

**本机核查**（`ultralytics 8.4.172`，`.venv/Lib/site-packages/ultralytics/nn/tasks.py:1131`）：

```python
def get_text_pe(self, text, ...):
    text_token = model.tokenize(text)      # ← 我们给什么就编什么，不加任何模板
```

⇒ `YOLOWorld.set_classes(["tv"])` 编的是字符串 `"tv"`，不是 `"a photo of a tv"`。
而 CLIP 原论文的标准做法是**模板集成**（80 条模板取平均），零样本分类**值 3–5 个点**。

**先看它有多大影响**（单类隔离模型，200 帧，`max` = 该类在全帧集上的最高分）：

| prompt | `max` |
|---|---|
| `a photo of a fire extinguisher` | **0.942** |
| `fire extinguisher`（我们一直在用的形式） | 0.563 |
| `a humanoid robot standing in a room` | 0.066 |
| `a photo of a humanoid robot` | 0.017 |
| `a photo of a robot` | 0.012 |
| `a white robot with a round head` | **< 0.010（完全无响应）** |

两条读法：
1. **形式是有效的杠杆**：同一个类，套上模板从 0.563 → **0.942**。所以"我们一直喂裸名词"这件事是真的、是真的有影响的。
2. **描述越具体越糟**：`a white robot with a round head` 完全无响应，而含糊的 `standing in a room` 反而有 0.066。
   这与 GroundingDINO 官方文档的经验一致（抽象/复合描述返回零检出）。

**但是**——把模板**套到全部 51 类**上会怎样？实测（`out/calib_real` 前 200 帧）：

| | 裸名词（现行） | **全部套 "a photo of a {}"** |
|---|---|---|
| 过门框数 | 124 | **386（+211%）** |
| `person` | **115** | **3** ← 碎了 |
| `tv` | 1 | **241** |
| `chair` | 2 | 41 |
| `fire extinguisher` | 6 | 72 |

★ 裁图存证 `out/_templ_check/full_templ51_tv_img_000018_0.93.png`：同一帧里**走廊正中站着一个明显的人**，
而模板模型在这 60 帧里给出的 `person` 框是 **0**，同时每一帧都吐一个 `tv` 框。

**⇒ 这是一个"数字大涨、地图变烂"的标本。** 模板把整条分布往"家具/物件"推、把 `person` 推到了 0.30 门以下，
而 `min_conf = 0.30` 这些门是**针对裸名词标定的**，换形式之后它们不再有意义。

**可用的结论**：形式是个真杠杆，但**不能整表套**；要用它必须**逐类标定门槛**，而逐类标定需要一把尺子（见 §1.3）。

### 1.2 措辞这条路已经走到头（今天封的）

| 试过什么 | 结果 |
|---|---|
| 15 条对象级别名（`treadmill` / `robot` / `service robot` …） | 只有 `stationary bicycle` 响应（`max` 0.187 < 0.30 门），强开门的唯一框是**画面边缘假框** |
| **单类隔离**（只烤 `["robot"]`）@320 **和** @640 | **零响应（`max < 0.010`、0 框）** |
| 阳性对照（只烤 `["person"]`） | `max` **0.816** / 105 框 ⇒ 导出路是通的 |
| 模板化（本节 §1.1） | `a photo of a robot` 0.012；描述句最好也只有 0.066 |

⇒ **不是措辞、不是模板、不是分辨率、不是门、不是被别的类挤掉。是这个模型的文本塔+对齐看不见它。**
在这个模型家族里**没有剩下的路了**。要拿 `humanoid robot`，只能换武器（§3.1 的 YOLOE 视觉提示/免提示）。

### 1.3 ★★ 真正的瓶颈：**我们没有尺子**

上面两节合起来指向同一件事：

- §1.1 里，"框数 124 → 386"看起来是巨大的提升，**实际是把人漏光了**。
- §1.2 里，`gym equipment` / `humanoid robot` 判死，靠的是**单类隔离 + 阳性对照**这套自建仪器，不是任何标准评测。

**真实侧没有真值**（组委会不给），所以：
> **我们所有的"识别率""检出了""改善了"都是自证的。任何一次"看起来更好"都可能是 §1.1 那种。**

这是项目现在**最大的结构性缺口**，而且它比换任何模型都便宜。可行的最小版本：

1. **人工标注 30–50 帧**（不是 1427 帧）：走廊、房间各若干，把画面里每个值得标的物体框出来，
   记下"是什么/大致方位"。半天工作量。
2. 由此得到两把可以辩护的尺子：
   - **每类的 precision/recall**（哪怕样本小，也远好过"看裁图觉得对"）；
   - **物体定位误差的 p50/p90**（用官方 reference pcd 或其他几何线索做对齐）。
3. 之后所有"换词表 / 换模板 / 换检测器"的改动**都先过这把尺子**，再谈闭环。

**没有这一步，§1.1 那种"提升"会一直发生，而且每一次都会先显示为好数字。**

## 2. 改进空间，按性价比排序（第 ① 问）

> 判据：**收益 ÷ 代价**，不是"看起来先进"。

### 第一档 · 不改算法、当天可做

| # | 项 | 为什么 | 代价 |
|---|---|---|---|
| 1 | **修视频叠字**（`putText(note,(8,22))` 与 `banner(origin=(8,8))` 撞位） | 每一帧都有，评委看得见；**已知、一行** | 一行 + 从采集重渲（~5 min） |
| 2 | **把 render 移出关键路径** | 全帧 p50 **222 ms > 5 Hz 的 200 ms 预算**；扣掉 `render`(58.6 ms) 才 ~163 ms。**现在是在超预算跑** | 中（渲染与决策解耦） |
| 3 | **给词表做逐类标定**（只在 §1.3 的尺子就位后） | §1.1 已证形式是杠杆；但整表套是回归 | 小（标定表） |
| 4 | **用上 IMU** | `/odin1/imu` **400 Hz、无 gap**，且**规则明确允许**；现在我们一个字都没用，yaw 全靠"指令积分死推"。真实侧 yaw 虽可观测，但**物体定位要经 `Rz(-yaw)`，yaw 一偏整个框转偏** | 中 |

### 第二档 · 能力缺口（真正决定交付质量）

| # | 项 | 现状 | 为什么值得 |
|---|---|---|---|
| 5 | **实例层判据** | 有实现、行为中性已证，但**精度 35.9%**（64% 是"把建筑当物体"），默认关 | 它是**唯一"不需要新模型就能让地图里出现未命名物体"**的路。目标是"提高落家具上占比 + 保持落空地≈0"，**已明确、未做** |
| 6 | **覆盖率的抽签** | 八次同世界跑里**六次有房间几乎没进** | 复赛**不直接打覆盖率**，但它决定"建图"这一半的观感。现有结论是"配额问题不是排序问题"，而**配额机制没做** |
| 7 | **实时跑一次真机/bag 在线** | 我们一直是 `--npz` 离线复算 | 交付要求写的是"实时"。**从没验证过在线跑**（含 bag 在线播放、话题延迟） |

### 第三档 · 规则要求但未做

| # | 项 | 规则原文 / 现状 |
|---|---|---|
| 8 | **嵌入式适配** | 规则："注意算法的计算效率，**需适配嵌入式计算平台**"。README 已如实披露未做。**Orin 上逐阶段预算至今没量**，所有数字都是 16 核桌面 |
| 9 | **交付形态补面板** | 复赛字面合规，但初赛那句写了"需包括 rviz 等可视化界面"。加一个点云面板成本中、风险低 |

### 第四档 · 建议**不要**做的

- **继续攻 `humanoid robot` 的措辞**（§1.2 已封死）。
- **整表套 CLIP 模板**（§1.1 已实测是净回归）。
- **在主路径上开 B3 拓扑保险丝**（成本把 5 Hz 打崩，已有专文记录）。
- **改地图层阈值 / 重开已判死清单**（`votes<12`、`K=2`、点云层判别器…全部有实测反例）。

## 3. 外部可借鉴（第 ③ 问）

### 3.1 ★★★ YOLOE（清华 THU-MIG，ICCV 2025）—— **最直接、最可落地的一个**

- 仓库：`github.com/THU-MIG/yoloe`；论文：ICCV 2025 "Real-Time Seeing Anything"。
- 相对 YOLO-World v2：LVIS 上 **+3.5 AP**，推理**快 1.4×**，训练成本 1/3。
- **关键**:它有三种提示模式，而且**后两种完全绕开"文本塔看不见我们的词"这个死结**：

| 模式 | 机制 | 治我们的哪个病 |
|---|---|---|
| 文本提示 `get_text_pe` | 比 YOLO-World 多一层 RepRTA 精调文本嵌入，导出时**重参数化进分类头，零推理开销** | 提高现有类的质量 |
| **视觉提示** `get_visual_pe` | 给**参照框/参照图**，不用文字 | **`humanoid robot` / `gym equipment`：我们描述不出来，但可以直接框一个给它** |
| **免提示** `set_vocab` / LRPC | 内置 **4585 类**词表，只对有物体的 anchor 做检索，**不依赖语言模型** | 我们**根本不知道该要哪些类**的场景 |

- **★ 本机已核实可用**：我们的 `ultralytics 8.4.172` **自带 `YOLOE`**（`models/yolo/model.py`），
  `get_text_pe` / `get_visual_pe` / `set_vocab` 三个 API 都在。
  ⇒ **接入成本 ≈ 现在我们换检测器的那条路**（`fetch_yoloworld.py` 换个类名 + 重导 + 走同一个 `detect.py` + 同一个 sidecar）。
- ⚠️ 需要重训吗？**不需要**——`yoloe-11s.pt` 等预训练权重直接可导出 ONNX；
  但**导出后同样要过 `--opset 19` 那条线**（容器 ORT 1.16.3，今天刚踩过）。
- **这是我认为下一步最值得试的一件"换武器"的事。**

### 3.2 开放词汇 3D 建图（了解思路，直接抄的余地有限）

| 项目 | 要点 | 与我们的关系 |
|---|---|---|
| **ConceptGraphs**（`github.com/concept-graphs/concept-graphs`） | 用 Grounded-SAM + CLIP 把 2D 开放词汇分割聚成**3D 场景图**，带节点关系 | 思路最接近"我们想要的语义地图"，**但它假设 RGB-D**；我们是 LiDAR + 单目，没有稠密深度 |
| **OVO**（Open-Vocabulary Online SLAM Mapping, RA-L 2025） | 在 ORB-SLAM3 上做**在线**开放词汇语义建图 | "在线 + 语义"的工程组织方式值得看；Replica 上 IoU 27→35.7% |
| **Octree-Graph**（ICCV 2025, `github.com/yifeisu/OV-Octree-Graph`） | 八叉树+图代替裸点云，显式表达占用与空间关系 | **对我们"地图层平方律膨胀"有参考价值**；"点云不是好的下游表示"这个论点与我们 §2 的预算问题同源 |
| **DovSG**（RA-L 2025） | 动态开放词汇 3D 场景图 + LLM 任务分解，长期语言导航 | 与决赛"语音指令 → 找物体"最像的公开系统 |
| **PointPainting** / **synesthesiaX** | 把 2D 语义"画"到 LiDAR 点云上 | 与我们的投影思路同源；`synesthesiaX` 是 ROS2 现成模块，**它的标定/投影代码可以直接对照我们的 `camera.py`** |

### 3.3 传感器融合（针对 §2 第 4 项"IMU 没用"）

`LVI-SAM` / `R3LIVE` / `FAST-LIVO2` —— LiDAR + 视觉 + **IMU** 紧耦合。
我们手上有一个 **400 Hz、无 gap 的 IMU**（而且是规则允许的输入）却完全没用。
**哪怕只做"IMU 预积分给 yaw 提供观测量"，也是现成的、低风险的增量。**

### 3.4 CLIP 提示工程的公开经验（今天已实测部分）

- 官方论文：**模板集成**（80 条）值 3–5 点 → **我们实测：整表套是净回归**，见 §1.1。
- **CuPL**：用 LLM 为每个类生成**视觉描述**（"golden coat, floppy ears"）再集成。
  ⚠️ 与我们实测冲突：`a white robot with a round head` **完全无响应**。所以**这条路要先在尺子上验，别直接上**。
- GroundingDINO 官方文档的坑清单：**具体名词 ≫ 抽象/复合描述**，与我们的实测一致。

## 4. 我的建议顺序

1. **先造尺子**（§1.3，半天）。没有它，后面每一步都可能是在复制 §1.1 的错误。
2. **修视频叠字 + render 移出关键路径**（§2 第 1、2 项，当天）。
3. **试 YOLOE 的视觉提示**（§3.1）。这是唯一一个能直接打 `humanoid robot` 的现成方案，且接入成本和今天换检测器一样。
4. **回实例层判据**（§2 第 5 项）。它是"地图里出现未命名物体"的唯一零模型路径，判据目标已经写好了。
5. **量 Orin 预算 + 跑一次在线**（§2 第 7、8 项）。这是规则明写、我们一直披露未做的两块。
