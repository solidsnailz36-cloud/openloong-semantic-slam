## 1. 实验设计：两条独立路径 + 三个 Gate

### 两条路径（互为独立校验）

| 路径 | 做法 | 回答什么 |
|---|---|---|
| **单帧反事实**（离线） | 读 baseline 逐帧地图，只把该格从 `obstacle` 拿掉，用 `worldmap` 自己的式子重算 `ground`，再跑 `PathPlanner` | "**同一张图**，就这一格不同，会怎样" |
| **整跑反事实**（真跑） | `--cf-hold-cells killer.json`：每帧 `add()` 之后把该格强制踢出 `obstacle`，重算 `ground` | "**整场**都不让它晋升，会怎样" |

**结果**：frame 1091 上单帧反事实 169.83 m²、整跑反事实 169.82 m²（差 0.01 m² = 1 格）。
两条独立路径给出同一个数 ⇒ 离线的单帧反事实没有引入自己的语义。

### 为什么离线单帧反事实是合法的（不是偷懒）

`WorldMap.add` 的最后一句是

```python
np.logical_and(self.ground_ever, ~self.obstacle, out=self.ground)   # worldmap.py:742
```

`ground` 是 `obstacle` 的**纯函数**。所以"这一格从未晋升"就是：

```text
obstacle[cell] = False
ground         = ground_ever & ~obstacle      # 原式照抄
```

帧内别的东西不用重算 —— 在 replay 里轨迹是**录制的**，没有任何下游量会反作用于图本身。

## 6. 因此 B3 的形状（**还没实现**，只写清约束）

不要做"扣住第 20 票"——已经实测无效。要做的是：

```text
每一次候选障碍准备晋升时
  -> 先"试装"这一格（算一次 reach，不落盘、不改状态）
  -> Δ = reach(不装) - reach(装)
  -> Δ 正常      -> 照原规则晋升
  -> Δ 异常巨大  -> 暂缓晋升，进入"待确认"状态
```

它相对"扣住某几格"的关键差别：**作用在每一次晋升上**。
门口那一簇是**依次**长出来的：4/5/6/7/8 晋升时 Δ 还是 0（门还宽），
只有**恰好完成闭合的那一格** Δ 巨大（f1091 的 (213,297)、f1141 的 (216,297)）。
一次只按"这一格"判断的规则，天然会把完成闭合的那一格扣住；下一帧补位的格子同样会被扣住
—— **这才可能结构性成立**（**推论，尚未实测**；§4.2 只证明了"两格"够了，没证明"逐次拦"够）。

约束（不许违反）：不动 `20`、不动 vote 统计、不动 release / on_path / reach、不动膨胀、
不动 planner、不加第二个启发式。

**验收口径（预先写死，看数字之前）**：
1. 门那一行（y=297）净宽整场不再掉到 <5 格；
2. reach 序列不再出现 >50 m² 的单帧塌陷；
3. 真值墙连通性不被破坏（消融后 reach 增长 ≤5 m²）；
4. `n_frozen_frames` 仍为 0；
5. **必须同时报"被暂缓晋升的格数 / 其中真值有物体的比例"** —— 否则就是把"宁愿漏判障碍"当成绩。
