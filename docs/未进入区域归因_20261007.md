## 0. 结论

**第二个瓶颈找到了，而且不在"候选评分"那一层。**

```
点云 → 地图障碍层 → 门口被判成障碍（观测依赖，非几何）
                        ↓
              passable = ~obstacle 在门口断裂
                        ↓
              lz(房间) != pseed(机器人)          ← explore.py::_masks 的第 2 道闸门
                        ↓
              other = room & (lz == pseed)  ⇒  A0_r4 里 = 0
                        ↓
              linked = reach | other  ⇒  房间从"剩余工作"里彻底消失
                        ↓
        既不在 reach（sweep 看不见）、也不在 other（探针不发）
                        ↓
              **从不成为候选** ⇒ 评分层根本没被咨询
```

**并且**：唯一能救它的机制（`island` 门口探针）**在 12 次跑里有 8 次只持续 2.2 秒**，
每次机器人离目标还有 **3–14 m** 就被 sweep 换掉；`island_probes` 上限 12 用完后就永久返回 `None`。

**⇒ 按 boss 的三分类，这是 A 类（从来没成为候选），不是 B 类。**
断点在 `reachability`（门口判定）+ `doorway`（探针没跑到），**不在 `selection`**。

## 2. ★★ 补救链复算（`out/_rooms.py chain`）

复算 `explore.py::_masks` 的同一条式子。**四个 A0 采集**：

| run | reach | holes | room（厚块） | **other** | room 但 `lz≠pseed` | probe（滩头） |
|---|---|---|---|---|---|---|
| A0_r1 | 169.1 | 74.0 | 24.2 | **24.2** | 0.0 | 10.1 m²（2 个 patch） |
| A0_r2 | 174.9 | 71.0 | 19.4 | **19.4** | 0.0 | 6.4 m²（2 个 patch） |
| A0_r3 | 168.2 | 93.0 | 14.3 | **14.3** | 0.0 | 3.4 m²（1 个 patch） |
| **A0_r4** | **152.8** | **101.0** | 23.7 | **0.0** | **23.7** | **0.0 m²（0 个 patch）** |

（单位 m²。`holes = ground & ~reach`；`room` = 厚到能站人的部分；
`other = room & (lz == pseed)`；`probe = other & reach 膨胀 `island_link_m`(1.5 m)`）

**两件事**：

1. **A0_r4 的 `other = 0`** ⇒ `linked = reach` ⇒ 房间**连探针都不会发**。
   而 A0_r4 正是四次里覆盖最差的一次（`reachable 152.8` 最低、`stranded 101` 最高）——**完全吻合**。
2. r1/r2/r3 的 `other` 是 14–24 m²，但**探针滩头只有 1–2 个 ≥0.5 m² 的 patch**
   （滩头 = `other` 里靠近 reach 的那一圈；`island_min_m2 = 0.5` **逐 patch** 判）——
   这决定了 §4 里"探针一碰就没"。

## 4. ★★ 障碍层的判定是观测依赖的（`out/_rooms.py diff`）

在**同一个房间窗口**（A0_r2 的 room 簇外扩 2.5 m）内逐格比对两跑的 `obstacle` 层：

```
窗口内共 9588 格：都障碍 677 | 都非障碍 8334 | 只 A0_r2 250 | 只 A0_r4 327
⇒ 判定不同 6.0%
```

| 差异 | 格数 | 在另一跑里 ground_ever / seen / on_path | 本跑 obstacle_votes 中位/max | 另一跑 |
|---|---|---|---|---|
| A0_r2 独有 | 250（2.50 m²） | 86% / 88% / 3% | **65 / 735** | 3 / 730 |
| A0_r4 独有 | 327（3.27 m²） | 38% / 41% / 1% | **20 / 669** | 0 / 27 |

**三条读数都要读**：

* 这些差异格**不是低票噪声**（中位 20–65 **帧**的回波，最高 669 帧）⇒ 不是"单帧擦边"。
* **`on_path` 只有 1–3%** ⇒ 不是机器人自己压出来的。
* **同一格在跑 A 是地板、在跑 B 是障碍**（r2 独有格里 86% 在 r4 里是 `ground_ever`）。

**⇒ 障碍层的输出依赖"机器人走到哪、从什么角度看"**。而可达性又决定机器人走到哪 ——
**这是一个正反馈回路**，所以两次同任务跑会分岔到不同的地图上。

> **与 §46 那笔旧账同族**（`rf1r3` 的 `reach` 在 t≈66–69 s 一次性塌掉 143.3 → 12.9 m²）。
> 那次报的是"reach 塌陷"；这次报的是"**塌陷之后被永久锁在门外**"。

**机制侧对上**（`explore.py::_pick_island_probe`，2725–2790 行）——它有三道早退：

```python
if int(probe.sum()) * cell < self.island_min_m2:      # ① 滩头总量 < 0.5 m²
    return None
...

if not cand_labels: return None
...

⚠️ **诚实标注**：§2 的 `chain` 与 §5 的 `island` 是**末帧复算 + 帧级读数**，
它们证明了"滩头很小 + 探针只活 2 秒"。但**具体是哪一道闸门（①/②/③）在每一帧挡住的，
本轮没有逐帧记录** —— 那需要给 `_pick_island_probe` 加一个只读的逐帧计数器。
**这条是推断，不是读数**（见 §8 候选动作 ①）。

## 6. 一处修正：`A0_r2` 那个"目标落在不可达块里 232 次"不是 bug

`_stranded.py` 一开始报"A0_r2 的块 1 被选成目标 232 次"。查清后**那不是缺陷**：

* 块 1 = 右上房间（x[2.60,6.40] y[1.70,6.30]，13.65 m²）；目标 `(6.25,4.75)` 就在里面，
  末帧 `free=True, reach=False`。
* **`linked = reach | other`**（§2）⇒ 判据是"可达的 **或** 看得见但进不去的"，
  所以"目标落在 `free & ~reach`"**正是设计意图**。
* 而且**机器人确实开到了距它 0.71 m**（`target_segs`: 46.2 s 里位移 23.16 m、静止帧仅 5%），
  **轨迹点有 150 个落在块内**。

**⇒ 那一块"中途是通的、末帧不通"** —— 与 §4 的结论一致（可达性会随地图回退）。

**但这一段尾部另有一个独立现象**（记录在案，本轮不归因）：

```

t=216         目标 (5.25,6.25) shadow，d = 0.82（几乎到了）

`turn`/`arc` 全场只占 4–12%（各臂相当）⇒ **这是局部事件**，但"目标换到身后之后转不出去"
值得单开一条（见 §8 候选动作 ③）。

## 9. 本轮的方法论读数（可搬运）

1. **"机制跑了" ≠ "机制起作用"——要问"它占了多少帧/秒"。**
   `island_probes = 12` 看着像"试了 12 次"，实际是"12 × 2.2 秒、离目标 3–14 m"。
   **这是记忆里那条旧规则的又一次兑现**（§13「救援机制'跑了'≠'有用'」）。
   新形态：**"次数计数器"要配一个"时长/位移计数器"。**

2. **`count` 必须配 `rate`（boss 规则①）在本轮又救了一次**：
   探针"12 次"如果只报次数，会写成"机制正常工作"。

3. **内部对照比真值便宜**：同一个房间在两次跑里一次可链接一次被挡（§3），
   **不需要真值栅格、不需要对齐**，就能证明"不是几何"。**优先找这种对照组。**

4. **"可达性会回退"是本项目的地图层性质**：`reach` 可以缩小而 `free` 不变
   （连通性断一格即可）⇒ **`traversable_m2` 单调增长不能用来证明"没有封格"**。
   本轮我先写了"封格 = 0"这个读数，随后发现它证明不了连通性 —— **口径不足要当场承认并换。**
