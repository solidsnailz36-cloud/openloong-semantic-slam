## 3. ② 修正：那格不是"刚被释放"，是"一直被压着"

逐帧探针（`--probe-cells`）给出那格的**完整层历史**——它只有**两个**变化点：

```
  f      votes  obstacle  on_path  seen  ground  ground_after
  f200   2      0         0        1     1       5
  f400   2      0         0        1     1       11
  f600   3      0         0        1     1       0
  f1000  4      0         0        1     1       0
  f1080  19     0         0        1     1       0
  f1089  19     0         0        1     1       0
  f1090  20     1         0        1     0       0        <== 第一次成为障碍
  f1091  20     1         0        1     0       0
  f1200  23     1         0        1     0       3
  f1400  23     0         0        1     1       20

  on_path = 1 的帧数：0 / 1489        seen = 1 的帧数：1400
```

**⇒ 它从 f≈200 起就有 ≥2 票，却直到 f1090 才第一次进 `obstacle` 层。**

`on_path` 全 0 ⇒ 不是路径豁免；`seen` 早就 1；`ground_after` 在 f600 起长期为 0 ⇒ 释放规则也不能解释"1000 帧都被压住"。
排除法只剩一条：**形态学开运算**（`OBSTACLE_OPEN_PX = 3`）的可移除判据：

```python
removable = (obstacle & ~opened & ~unknown_next
             & (self._obs_votes < OBSTACLE_STRONG_VOTES))     # <- 20
```

这一格是**一格厚的碎片**，`~opened` 成立、邻域全 `seen` ⇒ **只要票数 < 20，它每帧都被开运算摘掉**。
**第 20 票在 f1090 落下 ⇒ `votes < 20` 变假 ⇒ 它不再可移除 ⇒ 它第一次作为墙出现 ⇒ 地图被切断。**

> ### 机制 B ＝ **`OBSTACLE_STRONG_VOTES = 20` 处的一个开关**：
> 一格可以在 1000+ 帧里"有票但无害"，然后在某一帧**阶跃**成墙。

**同一层里还有同族的振荡**（探过的旁证，都在 `y = −0.05` 那一排）：

| 格 | 层翻转次数 | 翻转点（决策帧） |
|---|---|---|
| (−5.35, −0.05) | **5** | f899→1, f976→0, f1020→1, f1071→0, f1089→1 |
| (−5.25, −0.05) | **4** | f899→1, f973→0, f980→1, f1073→0, f1089→1 |
| (−5.15, −0.05) | **3** | f899→1, f1073→0, f1091→1 |

⇒ **这一层在"有票/无票"之外，还有第三条不稳定通道：开运算的移除判据。**

## 5. ★ 实测：θ=1 对机制 B 完全无效（而它只动低票格）

同一批 9 格，`cap_A0_r3` 两个臂的**逐帧层历史**对照（`--probe-cells`）：

| 格 | `ratio = 0.0` | `ratio = 1.0` |
|---|---|---|
| **(−8.65, −0.25) 致命** | f1090 → 障碍（**v=20**）… f1224 释放（v=23） | **完全相同**：f1090 → 障碍（v=20）… f1184 释放（v=23） |
| (−8.75, −0.25) | 全程非障碍 | 相同 |
| (−8.55, −0.25) | f49→1(v2), f89→0 | 相同 |
| (−8.65, −0.35) | 全程非障碍 | 相同 |
| (−8.55, 5.35) | f1089→1(v2) | 相同 |
| (−12.65, 0.15) | f1090→1(v20) | 相同 |
| (−5.35, −0.05) | **翻转 5 次**（f899/976/1020/1071/1089） | **全程非障碍** ← 被门限压住 |
| (−5.25, −0.05) | **翻转 4 次** | 只在 f1212→1 / f1385→0 |
| (−5.15, −0.05) | **翻转 3 次** | 推迟到 f1151 之后才动 |

⇒ **门限只动低票格（机制 A 家族），对 20 票的那一格一格都没动。**

这就是"两条规则、两个机制"的**直接实测证据**：`OBSTACLE_GROUND_RATIO` 只管 `MIN_VOTES` 那一层的升格；
机制 B 走的是**开运算的 `OBSTACLE_STRONG_VOTES` 豁免**，门限根本不在那条代码路径上。
（顺带解释了 r3 两臂塌陷量级不同 −136 / −150：门限把周围低票格拿掉了一些，连通分量形状变了，
**但致命格本身没变**。）

## 7. B 项：真值工具已修（**与算法实验分开**）

### 7.1 病因与修法

`out/_truth_geo.py.load_dae` 只 `root.iter(ns + "triangles")`。世界里有 **12 个模型的碰撞网格用
`<polylist>` + `<vcount>`** ⇒ 取不到三角形 ⇒ `parse_world` 里 `continue` **静默跳过**。
**补丁**：新增 `<polylist>` 分支（按 `vcount` 扇形三角化）。

### 7.2 ★ 补丁本身踩了一个坑（已加闸）

补上 polylist 后**真值反而变差**了：`KitchenCabinet_01` 与 `SofaC_01` 的 `*_collision.DAE`
**不是家具壳，是场景级的大平板**——`KitchenCabinet_01` 只有 32 个顶点、48 个三角，
其中一块是 **6.1 × 32.3 × 9.0 m**；按 1:1 画进真值会凭空铺 24 m² 假墙，
把对齐残差从 p50 0.20 m 拉到 **p50 0.82 / p90 10.0 m**。

**⇒ 加了尺寸闸**（只对 mesh 项，`MESH_MAX_EXTENT_M = 6.0`）：超限就**跳过并打印**，不再静默。
（house 的碰撞是 `<box>`，不受此闸影响；世界最大真物体是 2.5 m 的电视柜。）

### 7.4 ★ 但**两处关键格在修好的真值里依然空**

| 位置 | 真值支持（修好后） |
|---|---|
| r2 门口那块 x∈[−1.05, 0.05], y∈[5.95, 6.15]（65 格、票数至 193） | **一格都没有** |
| r3 致命格 (−8.65, −0.25) 及其 5 个邻居 | **一格都没有** |

⇒ **工具 bug 是真的、已修，但它不是这两格的解释。** §62 的"无真值支持"仍然成立（而且现在是在
**更完整的真值**上成立）。**剩下唯一的可能是真值仍不全**（动态物体、truth bake 之外的实体），
或者这两处的回波本来就不对应任何物体。

### 7.5 一个命名陷阱（会影响别人读我们的结论）

真值 npz 里那个键叫 **`wall`**，但它其实是 **`G` ＝ 所有 item 的并集**（墙 + 全部家具）。
所以"离最近真值墙 ≥0.70 m"实际读作"**离最近真值占用 ≥0.70 m**"——结论更强，但命名会误导。
