## 四、重建步骤（拿到任意一台 Ubuntu 20.04 后，照抄）

```bash
# 0) 环境：Ubuntu 20.04 + ROS Noetic + Gazebo Classic 11 + libgazebo11-dev
#    官方仿真包放在 /root/sim/ 下（从 D:\E-Downd\openloong_ex\official\ 上传）

# 1) 模型库（并把联网模型库黑洞化 —— 这一步不做会「世界加载永久卡死、sim_time 恒 0、零报错」）
mkdir -p ~/.gazebo/models && unzip -q /root/sim/gazebo_models.zip -d /tmp/gm
cp -a /tmp/gm/gazebo_models/. ~/.gazebo/models/
#    再上传 vendor/gazebo_models_patch/hokuyo/ -> ~/.gazebo/models/hokuyo/
grep -q models.gazebosim.org /etc/hosts || echo "127.0.0.1 models.gazebosim.org" >> /etc/hosts

# 2) 源码 + catkin 工作区（顶层 CMakeLists.txt 是 0 字节，必须先删，否则「编译成功但零产物」）
mkdir -p /root/sim/catkin_ws/src && unzip -q /root/sim/src.zip -d /root/sim/catkin_ws/
rm -f /root/sim/catkin_ws/src/CMakeLists.txt && (cd /root/sim/catkin_ws/src && catkin_init_workspace)
source /opt/ros/noetic/setup.bash && cd /root/sim/catkin_ws && catkin_make -j4

# 3) 上传 vendor/sim_scripts/（27 个）到 /root/sim/，并上传 r2slam/
#    注意：脚本里一律 set +u（ros_distro.sh 引用未定义的 ROS_DISTRO）；日志用 stdbuf -oL -eL

# 4) 点火并验收（四判据）
bash /root/sim/sim_up.sh false
bash /root/sim/verify_sim.sh      # 期望：/velodyne_points 5.000 Hz / 5,600 点、/state_estimation 200 Hz
bash /root/sim/sim_up.sh false && sleep 5 && bash /root/sim/drive_test.py   # /cmd_vel 能驱车
```

## 五、复赛交付三项：哪些真的需要 T4

| 交付物 | 需要 Gazebo 吗 | 现在能不能做 |
|---|---|---|
| ① 仿真环境运行视频 | **需要** | 需一台 Linux 跑 Gazebo |
| ② **真实数据集**运行视频 | **不需要** | **本机就能做**（onnxruntime + cv2 + `r2slam` 已就位，真实侧感知已跑通） |
| ③ 建图 pcd | 一半 | 真实数据的 pcd **本机可做**；仿真侧 pcd 需 Gazebo |

⇒ **T4 失联最多只能拖住 ①（和仿真侧 ③），② 完全不受影响。** 这一点把风险砍掉一半。

## 六、替代算力（按性价比）

| 方案 | 说明 | 成本 |
|---|---|---|
| **另租一台 Ubuntu 20.04 小实例** | **不需要 GPU**：VLP-16 只有 5,600 点 / 5 Hz，llvmpipe 软渲染就够（上次就是软渲染跑的） | 按量小机器约 ¥1–2/小时 |
| **本机 WSL2 装 Ubuntu 20.04** | 本机已确认有可用 GPU（RTX 2060）+ 16 线程；但 `wsl.exe` 被本机安全策略拦住，需你自己跑一条命令允许 | 0 元 |
| 本机 Windows 直跑 | **不可行**：Gazebo Classic 无 Windows 版 | — |

**本机算力（本次实测）**：`nvidia-smi` 正常，GPU = **RTX 2060**，CPU 16 线程。
（与旧记录里"驱动力损坏的 RTX 5060 工作站"不是同一状态，需要更新那条记忆。）
