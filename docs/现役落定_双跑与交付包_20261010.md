## 2. 出包之前先发现并修掉的两个红测试

boss 的判据是"没啥大问题的话"。**不是没大问题 —— 有两个测试是红的**，都查到了根因。

### 2-1 `test_nav.py` 4 项失败 —— **测试的合成世界不物理**

现象：3 全阻塞走廊必须无路（×2）、有缝的墙必须从缝里过、被墙围住的目标必须 `unreachable`。

排查顺序（每一步都排除了一个嫌疑）：

1. 换 `--footprint square` 跑 → **同样 4 项失败** ⇒ 与圆核无关。
2. 换 `GROUND_COVER_INFORMATIVE=False` 跑 → **7/7 PASS** ⇒ 是它。
3. 在 10-04 基线提交上跑 → PASS。基线 `ground_ever[墙格]=False`，现在 `True`。
4. 机理：`add()` 里 `ground_ever[cyo, cxo] |= g[ok]` 对**重复下标**是"后写覆盖"，
   而测试的点序是"地板在前、墙在后" ⇒ 墙格最后一笔把 True 覆盖成 False。
   **旧测试是"侥幸绿"的**，不是设计如此。

★ **判据**：`GROUND_COVER_INFORMATIVE` 只折叠"见过的回波里没有障碍、没有检测"的格；
`OBSTACLE_GROUND_RATIO=1.0` 又允许地板证据否决同格障碍的晋升 ⇒ **一个格子不能既铺地板又立墙**。
真实 LiDAR 看不到墙脚下的地板，所以修的是**夹具**不是地图：
`corridor()` 新增 `wall_occludes_floor()`，把墙位（±0.12 m = 一格）处的地板样本去掉；
有缝的用例复用同一个构造器（`gap_y`/`gap_half`）。

### 2-2 `test_explore.py` 第 32 项 —— ★ **顺带抓到一个真 bug（在 `explore.py` 里）**

现象 1：`the fixture produced 8 candidates but not two competing regions`。

- 二分定位：`d1339af/0487fc0/c3ee6c6/a86f85f` PASS，**`5fddecf`（2026-10-08）起 FAIL**。
- 探针打印候选元组：**长度已是 24**，而 `c[-1]` 现在是 `4.17 / 4.11`（**分值**）。
- 真身：区域秩在元组里的位置在 10-08 那次大改后从"最后一位"移到了 **`c[22]`**
  （`c[23]` 是新加的 `val`）。代码注释里写着 `# 22 the region's rank`。

现象 2（改对测试下标后浮现）：`the pick fell through to a non-first region`。

- `explore.py` 里有**三处**读者仍然写 `c[-1]`：

  | 位置 | 影响 |
  |---|---|
  | `_plan_first` 交接点 | `n_head_rank_nonzero` |
  | `rfirst` 取点归因 | `n_rfirst_top_used` / `n_rfirst_offrank` |
  | 记录的 `n_reg` | "有几块区域在竞争" |

  `int()` 一个分值永远不等于 0 ⇒ **三个计数器全被钉在"什么都没发生"的值上**。
- 这是**仪表**失效（不改变任何决策），且分支是 `rfirst` 门控（默认关），
  所以流水线上永远看不出来 —— **是测试把它抓出来的**。
- 修法：模块级常量 `CAND_REGION = 22`，四处（三个读者 + 排序键）统一用它，
  下次再往元组尾部追加字段是"改一行"，不会再变成"静默改语义"。

## 5. ★ 分割模型实测：**预算不是门槛**（回答 boss 的提议）

boss：试 Roboflow 的 yolov8-seg / yolo26-seg，或 FastInst-AA / UniPercepNet-S。

先纠正上一轮的口径：§3-4 的"seg 撞预算不落"测的是 **YOLOE-seg @640**（159 / 581 ms），

⇒ 自己导三个小号 seg（opset 19），**同一会话背靠背**实测原始推理：

`tools/bench_seg_head.py --frames r2slam/out/online_real/frames --limit 20 --repeat 2`

| 臂 | 头 | p50 | p90 | 类通道峰值 |
|---|---|---|---|---|
| **现役** `yoloworld_alias_320`（55 通道，检测） | det | **35.78** | 39.10 | 0.0117 |
| `yolo11n-seg` @320（116 通道） | seg | **13.50** | 14.25 | 0.2747 |
| `yolo26n-seg` @320 | seg | **13.55** | 20.59 | 0.8427 |

| `yolo26n-seg` @640 | seg | 45.08 | 49.95 | 0.2800 |

**结论三条**：

1. **320 上的小号 seg 比现役检测器快 2.2–2.6×**（13.5 vs 35.8 ms）⇒ 想上分割，
   **卡的不是算力，是解码与投影**。现役那个是 `yolov8s-worldv2` 骨干（`s` 级 + world 头），
   本身就比 `n` 级慢一倍多。
2. **类通道是活的**（峰值 0.27–0.84，`yolo26n-seg` 最高）—— 这一条是照 YOLOE 那次教训专门查的：
   形状对而通道死，是已经踩过的坑。
3. 代价清单（**未做**，是真要花的工）：
   `detect.py` 现在按 `4+nc` 切通道，**解不了 `4+nc+32` + 原型张量**（会抛 `IndexError`）；
   还要做掩码→三维点归属、以及端到端 `ms_total` 的 A/B。
   掩码解码本身便宜（320 下原型 32×80×80），但**没有测过，不许当成已测**。
4. **取舍**：COCO-80 的 seg 模型**丢掉 51 条自定提示的开放词汇**
   （`gym equipment` / `humanoid robot` 不在 COCO）⇒
   - 换：拿 P1/P2/P3（共 **30 分**）的掩码，丢 M4 的一部分
   - 并跑：35.8 + 13.5 = **49.3 ms** 原始推理，仍在一个 `detect` 预算量级内
   - **这条要 boss 拍**，不是技术上的必然。

### 5-1 FastInst-AA / UniPercepNet-S：**按它们自己报的 GPU 延迟就判死**

## 7. 分割头并跑：实现与实测（boss 拍「可以并跑」）

主文档之外的单独立项，因为它是**新功能**而不是落定。

### 7-1 做了什么

新增 `r2slam/seg.py::OnnxSegDetector`（解 `[1, 4+nc+32, N]` + `[1,32,mh,mw]` 原型）、
`viz.blend_masks()`（半透明填充 + 1 px 轮廓）、`online_pipeline.py` 的
`--seg-model / --seg-conf / --seg-alpha`，`summary.json` 多一个 `segmentation` 块。
**检测器不动**：开放词汇头（51 提示 / 39 类）继续喂 3D 融合与地图；
分割头是 COCO-80 闭集，**只画在相机面板上**。

三个"不猜"的约束（都写进代码注释与自检）：

1. **布局**：`nc` 由张量形状推出来并与声明的类数**对不上就报错**；
   没有原型张量的图在构造时就抛 —— 把 seg 头当 `4+nc` 解会把 32 个掩码系数当类分，
   这正是上一轮 YOLOE 导出被误判"类通道死了"的成因。
2. **门槛**：套用**与检测器同一套**逐类 `LABEL_MIN_CONF` / `LABEL_MIN_BOX_FRAC`，
   并同样统计"置信但叫不出名"的框。否则画面回答的是"哪个模型更宽松"，
   而不是"掩码多带来了什么"。
3. **掩码形态**：返回**裁好的、原型分辨率**的掩码 + 裁剪框的原图像素矩形。
   不放大到 1600×1296：那是一个实例每帧 2 MB，而 3D 侧要的只是
   "这个投影点在不在这个实例里"，由 `mask_cell()` 在裁剪框自己的坐标系里回答。

### 7-2 费用（真实相机帧 1600×1296，14 帧，**同一会话背靠背**）

⚠️ 不是在渲染出来的 `camera | map` 拼图上量的 —— 那是本场犯过的错（在拼图上跑检测器，
找到的是左半幅里那个小场景），`test_seg.py` 现在把这条写成了注释。

| | p50 | p90 |
|---|---|---|
| seg 只跑 session | 22.07 | 25.15 ms |
| **seg 全路径**（预处理 + 解码 + NMS + 逐类门） | **23.96** | 27.86 ms |
| 现役检测器 全路径 `detect_mapped` | 66.42 | 75.47 ms |

⇒ **解码+预处理只占 1.9 ms**；整个分割头约为它所伴随的检测器的三分之一。

   掩码边界就是这个量级的台阶；真实侧确实看到掩码比人体多出一小块背景。
   要更细的边界就得 640（§5：640 上 45–52 ms）。
4. ⚠️ **闭集代价是真的**：真实侧 `clock 74` 次（走廊墙面被误判成钟）、
   `unmapped_boxes 1909`。这不是 bug，是 COCO-80 在这个场景里的表现 —— 也是
   "为什么不能拿它换掉开放词汇头"的直接证据。
