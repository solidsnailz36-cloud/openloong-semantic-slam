## 3. ★ 控制票数之后，时间不提供信息

取与致命格同量级的 band（r3：`nframes ∈ [1,48]`，2749 格；r2：`[1,31]`，2065 格），
比较"真值占用 / 真值空"两组的**时间结构**（真值用**软分类**：距真值占用 ≤0.20 m 记占用、
≥0.35 m 记空，中间 587–649 格丢弃，以吸收 ≤2 格的刚性错位残差）：

| 判据 | r3 AUC | r2 AUC | |
|---|---|---|---|
| `longest consecutive run` | **0.467** | **0.459** | 反向 |
| `vote span (frames)` | **0.470** | **0.481** | 反向 |
| `biggest gap` | **0.470** | **0.361** | 反向 |

⇒ **在同等票数下，时间结构分不开"真"和"假"。** 方向还常常是反的

**★ 两个反例把两个候选判据各打掉一次**：

- **`pts/vote ≈ 1` 不是致命格独有**：r2 的 `(−0.65,6.05)`（48 票）`pts/vote = 1.00`，
  而它紧挨着一块 89 格的真结构。⇒ **每次 1 个点 ≠ 假**（与 §20 K=2 的判死结论同族）。
- **`nbm` 低也不是致命格独有**：r2 门口那 3 格 `nbm = 226–337`，**和真墙一样高**。
  ⇒ `nbm` 抓的是"**孤立**"，不是"**真假**"。机制 A 的假障碍是**贴着真结构边缘**漏出来的，
  机制 B 的才是**孤立细须**。

**同一格跨采集**：`(−8.65,−0.25)` 在 r2 里只有 6 票（`nbm = 11`），在 r3 里 23 票（`nbm = 25`）
—— 它不是 r2 的致命格（r2 的致命格在门口）。⇒ **票数本身逐跑差异极大**，这也解释了
为什么"单跑不能当战果"。

## 6. 如果拿某个量当判据，谁会被误伤

只在"地图真正持有"的格上算（`votes ≥ 2`）：

| 阈值 | **`returns/vote ≥ t`** 拒绝 | 其中真值占用（误伤） | **`nbm ≥ t`** 拒绝 | 其中真值占用（误伤） |
|---|---|---|---|---|
| r2 / 低档 | 0（t=1.0） | 0 | 12（t=4） | **1（8%）** |
| r2 / 中档 | 929（t=1.5） | **494（53%）** | 337（t=32） | 85（25%） |
| r2 / 高档 | 1606（t=2.0） | **827（51%）** | 1473（t=128） | 522（35%） |
| r3 / 中档 | 787（t=1.5） | **416（53%）** | 474（t=32） | 250（53%） |

⇒ **`nbm` 比 `returns/vote` 便宜**（r2 的 `t=4` 只误伤 1 格），但**要抓住 r3 的致命格（`nbm=25`）
必须取 `t > 25`**，那时 r3 的误伤就跳到 250/474 = 53%。**它不免费。**

⚠️ 而且按 §63 的教训：**格数度量很贵不代表连通性度量也贵**。上面只是格数口径，
**真要定判据必须再跑一次"消融后 `reach` 增长"的连通性口径**（§63 里那个数是 +1.99 m²）。

## 7. 副产物：探针里 `obstacle_now` 与 `obs_votes` 对不上（**待查**）

在 `--probe-cells` 的 CSV 上，同一个格：

- `obs_votes` 从 0 涨到 23（**23 次投票事件**）
- 但 `obstacle_now == 1` **只有 10 帧**

代码上两者应由**同一批点**产生：

```python
self.obstacle_now[cyo, cxo] |= o[ok]                    # 逐点置位
...
key = cyo[o[ok]].astype(np.int64) * self.n + cxo[o[ok]]
self._obs_votes[uu // self.n, uu % self.n] += 1          # 同 mask
```

已排除：`OBSTACLE_HOLD = "reset"`（不会 `continue`）、`OBSTACLE_MIN_POINTS = 1`（不筛）、
`cell_of` 返回 `(cx, cy)`、`add()` 每帧只调一次、`explore.py` / `nav.py` **从不出现**
`obstacle_now` 字符串、过滤段只改 `obstacle` 不改 `obstacle_now`。
**其余候选：`add()` 之后到探针读取之间有一处清空。未定位。**

**影响**：`blocked() = obstacle | obstacle_now`，累积层非空 ⇒ **安全层不会因此失效**，
所以这不是一个"会撞墙"的 bug。但它是**仪器可信度**问题，且**票的时间序列本身不受影响**
（`obs_votes` 有两个独立通道复现，见 §8）。

**下一轮的零成本查法**：在 `--probe-cells` 的记录里加一列
`int(wmap.obstacle_now.sum())`；若某帧该格为 0 而全局和也为 0，就是"整帧被清了"，
否则是"该格确实没有障碍点"。**不要靠推理，加一列。**
