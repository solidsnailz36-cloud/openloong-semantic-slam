## 一、左右反：`render()` 把世界 +y 画成了屏幕向下

### 1.1 排除掉的三条路

| 嫌疑 | 怎么排掉的 |
|---|---|
| 相机面板被翻转 | 拼接是 `np.hstack([left, right])`，`left` 是**原始图像 + 框**；全仓 `grep cv2.flip` —— 除本次新增外**一处都没有**，`viz.imwrite` 只做编码 |
| KISS-ICP 里程计"镜像" | 刚性配准**不可能产生镜像**（最多转 180°），所以一致性只能由渲染约定决定 |
| 某个补偿性翻转 | 无。`render()` 里 `py = (cy − y0) * k`，而 `win = img_world[y0:y1, x0:x1]` ⇒ **图像行号直接等于格行号，而图像行号向下增长** |

### 1.2 机理一句话

**世界 +y 被画成屏幕向下 ⇒ 面板是标准俯视图的上下镜像 ⇒ 对读地图的人，机器人的左右被互换 ⇒ 右转画成左转。**

### 1.3 实测（不是推理）

`tools/test_worldmap.py` 新增 §12：铺一条沿 **+x（航向）** 的地面条带、一条沿 **+y（机器人左侧）** 的地面条带，
渲染，然后**从渲染出的像素里把两条带读回来**。不变式按"人怎么读地图"陈述：

> **朝面板右侧的机器人，它的左手边必须在面板上方。**（面朝东时左手边是北。）

| | 机器人所在行 | +y（左侧）条带所在行 | 判读 |
|---|---|---|---|
| 修前 | row 270 | **row 280–434** | 画在了**下方** ⇒ 镜像 |
| 修后 | row 270 | 上方 | ✅ |

### 1.4 ⚠️ 为什么 §11 抓不到它（这一条比 bug 本身值钱）

§11 早就有"叠加层落在它下面的地图上"的断言，**而且在镜像的图上照样全绿**。
原因：§11 的 `pixel_of` 辅助函数是**手写的、模仿渲染器口径的**，它写着
`"+y downwards"` —— **和坏掉的渲染器编码了同一个错约定，于是互相印证**。

**⇒ 一个把实现复述一遍的测试，抓不到实现里的约定错误。**
§11 的辅助函数已改成按**文档口径**写（+x 向右、+y 向上），改后仍全绿。

### 1.5 修法

```python
img = cv2.resize(win, (size, size), interpolation=cv2.INTER_NEAREST)
img = cv2.flip(img, 0)                       # 世界 +y 向上
def to_px(x, y):
    c = self.cell_of(x, y)
    return ((c[0] - x0) * k, ((y1 - y0 - 1) - (c[1] - y0)) * k)
```

**翻转只作用于栅格本身**：图例、5 m 比例尺、机器人圆点都在其后绘制，必须保持正立。
**行为影响：零。** 同一份 bag 重跑，**决策列 md5 逐位相同（`dcc8fd551e32`）**，
`traversable 439.1 m² / seen 68215 / obstacle 178.4 m²` 全部一致。

## 二、绿区灰斑：**画面在说谎，地图是对的**

### 2.1 先量清楚"灰"是什么

`灰 = seen & ~ground`，而 `ground = ground_ever & ~obstacle`。真实侧（`out/_diag_real/grids`）：

```
灰                    243.1 m2
  ├─ 障碍层**拥有**它          178.4 m2   （墙/家具，涂灰是对的）
  └─ 障碍层**没有**拥有它       64.7 m2   <── 却被涂成和墙一模一样的灰
绿区里的灰斑            17.70 m2
  ├─ 真的被晋升为障碍            1.42 m2
  └─ **从未晋升**              16.28 m2   = 92%
```

并且：**绿区里的灰斑是 1006 个连通块，面积中位数 0.01 m²（就是单格），最大 0.15 m²** —— 盐噪声。

### 2.2 逐条排除（每条都用测量，不靠推理）

| 假设 | 测量 | 结论 |
|---|---|---|
| 记账 bug：`ground_ever=False` 却存着地面点 | 与 `map.pcd` 逐格对照，**0 格矛盾** | 否 |
| 死带（`ground_mask` 的 `|h|<tol` 与 `obstacle_mask` 的 `h>0.35` 之间） | 上窗 3/1770 格、下窗 17/1770 格 | 否 |
| 是行人挡出的影子 | 9% 在 person 观测 0.5 m 内，34% 在 2 m 内 | 是**部分**原因，不是主因 |
| 是真实物体 | **回相机看**：机器人当时看向那些位置，画面里是**普通地面**（地面黄色标线、木地板、瓷砖），**没有 0.35–2 m 高的东西** | 否 |

剩下的事实：每个斑格只有 **2–3 个点**，且同一格里还常有**低于地面平面约 1.4 m 的点**（物理上不存在）——
**⇒ 稀疏多径 / 假回波**。而项目此前已经判过：**观测层判别器 AUC 0.638，分不开**
（"观测层信息不足，不是特征不够，别再堆特征"）。

### 2.3 修法（两条，都只动画面）

**（a）四分类着色**：原来 `seen & ~ground` 一律涂成墙灰。现在：

```
绿   = ground
灰   = seen & obstacle        （障碍层拥有它 —— 真的挡住）
暗   = seen & ~ground & ~obstacle（看过，但从未判为障碍）
```

**（b）单格斑点填充**：`seen & ~ground & ~obstacle` 且**八个邻居全是可通行**的格，按可通行绘制。
依据不是我编的：**这些格地图自己就没判它是障碍**（`~obstacle`），而一个有体积的实物不可能 8 个邻居全通。

**⚠️ 这是画面规则，不是地图规则**：`seen / ground / obstacle` 三个数组与 `map.pcd` **一个字节都没改**
⇒ 规划器、覆盖口径、replay、反事实全部不受影响。
（`seen` 不能动：`explore.py` 的前沿逻辑 `~wmap.seen` 在读它。）
开关 `worldmap.RENDER_FILL_LONE_SEEN`（默认开，可关）。

### 2.4 验收

`tools/test_worldmap.py` §13/§14：晋升格与未晋升格**必须不同色**；单格且八邻可通行**必须被填**；
成簇的未晋升格**不许填**；单个被晋升的障碍格**一律不许填**。**59 checks / 0 failed。**

**★ 落在真实画面上的效果**（同一份 bag、同一帧 `001400`，只数地图面板的像素）：

| 面板 | 绿色像素 | 灰（墙色）像素 | 其中**落在绿区里**的 | 新的“看得到但未判障碍”类 |
|---|---|---|---|---|
| BEFORE | 37,473 | 20,317 | **2,982** | 0（原来与墙同色，分不出来） |
| AFTER | 37,600 | 15,089 | **663** | 5,270 |

**⇒ 绿区里的灰色像素 2982 → 663（−78%），而绿色面积只涨 0.3%** ——
改善来自“不再把非障碍画成障碍”，不是靠把可通行区灌水。

## 三、顺带抓到第三个缺陷：视频里有帧尺寸不一致

排查面板裁剪位置时发现：真实 bag 的 **1427 帧里有 2 帧（第 1200、1201）拼图宽度是 1080，其余是 1206**，
编码器把那两帧**压进了固定尺寸** ⇒ 视频里会看到一闪的形变。

根因：`camera_panel` 按**该帧图像自身的长宽比**缩放，而 bag 里有 2 帧图像尺寸不同。
修：`online_pipeline.py` 用**第一帧渲染出的面板宽度钉死**后续所有帧（不一致时 resize）。
代价是那 2 帧被重采样；收益是每一张拼图同形——本来就是视频文件的前提。
（自检：重跑后应 1427/1427 同宽。）

### 5.1 灰按「地图自己的判决」拆开

真实侧最终栅格（`out/_diag_real/grids`，与 `online_real_v6` 同决策 `dcc8fd551e32`）：

再看这 64.7 m² 的**票数**（`obstacle_votes` = 有多少帧往障碍高度带 0.35–2.00 m 里放过回波）：

### 5.2 ★ 形态：为什么上一轮的单格填充没抓住它

`seen & ~ground & ~obstacle` 这类灰在绿区里的形态是**薄长条**（2–3 格宽、断续），不是孤立单格 ——
`_gray_v2.py` 的「闸门」扫描（灰带两侧都是绿）找到 12 处，其中 **8 处真障碍 0 格**：

```

gate#3  (12.5, 22.8)  0.40 x 2.40 m   32 格   真障碍 0/32
gate#7  (13.7, 25.3)  0.20 x 1.80 m   22 格   真障碍 0/22
gate#8  (12.7, 26.1)  0.30 x 1.40 m   20 格   真障碍 0/20
gate#5  (12.9, 39.3)  2.20 x 0.30 m   25 格   真障碍 0/25
gate#4  (18.9, 33.7)  1.40 x 0.40 m   26 格   真障碍 0/26
```

**「0.2–0.4 m 厚、1.4–2.4 m 长的薄带，一格真障碍都没有」** ——
这就是「形状不规则」＋「把入口几乎拦起来」的实体。物理上也不成立：一面墙不会只有 20 cm 厚还断续。

### 5.3 修法：**渲染相信障碍层的判决**

`obstacle` 是地图对「这里是否被挡住」的**唯一判决** ——
`blocked()` 就是 `obstacle | obstacle_now`，规划器的 `ground` 也已经是 `ground_ever & ~obstacle`。
一个「收到过回波但从未被晋升」的格，按地图自己的定义**不是障碍**；把它画成障碍色是在**发明一面墙**。

```python
# worldmap.RENDER_TRUST_OBSTACLE_LAYER（默认 True）
cls[self.seen & ~self.obstacle] = 1        # 只有 obstacle 才画灰
```

**仍然是画面规则**：`seen` / `ground` / `obstacle` / pcd **一个字节没动**
⇒ 规划器、覆盖口径、replay、反事实全不受影响（`seen` 也不能动：`explore.py` 的前沿逻辑在读 `~wmap.seen`）。

## 六、★ 渲染与规划必须一致（boss 指出：「这个问题很严重，要认真对待」）

### 6.1 上一轮我修错了地方

上一轮我在**渲染层**打了个补丁：`cls[seen & ~obstacle] = 1`，让画面好看。
那在工程上是错的 —— **画面和规划各算一套判据**。画面说能走、规划器说不走，
或者反过来，**两条判据迟早漂移**，而且漂移的方向没人能保证。boss 一句「很严重」是对的。

### 6.2 工程根因：同一个问题有五六处各自重算

```
nav.free_space          free = wmap.ground.copy()          <- 规划器读的
explore.py:1357         free = wmap.ground & ~wmap.obstacle
explore.py:1498         raw  = wmap.ground
explore.py:1522         passable = ~wmap.obstacle          <- 有意不同（判"是否已知挡路"）
explore.py:4950         grid = wmap.ground
worldmap.render         cls[seen & ~obstacle] = 1          <- 上一轮我加的补丁
```

**没有一个"官方答案"。** 只要渲染能自己算，它就一定会和规划不一致。

### 6.3 真正的问题：那些格为什么既不是地面也不是障碍

在线管线的判据（`tools/online_pipeline.py`）：

```
ground_ever  <-  |h| < tol                 tol = 0.10 + 0.035 * range
obstacle     <-  h in (0.35, 2.00]
seen         <-  h in [-0.60, 2.00]
```

⇒ 两条**死带**：上侧 `tol <= h <= 0.35`、下侧 `-0.60 <= h <= -tol`。
落在里面的回波让格 `seen`，却**不给地面、也不给障碍票**。

**先测死带（`out/_deadband.py`，把 `map.pcd` 的每个回波按高度分档）—— 假设被否：**

```
该格收到的 17445 个回波里：
  tol <= h <= 0.35     （上侧死带）        8  ( 0.0%)
  -0.60 <= h <= -tol   （下侧死带）      211  ( 1.2%)
  |h| < tol                                1654  ( 9.5%)
  h > 0.35             （障碍高度带）     11328  (64.9%)   <- 主体
  h < -0.60            （非"有信息"）     4691  (26.9%)
```

**真实原因**：这些格确实收到了障碍高度带的回波，但每格只有 2–3 个点、
**落在的帧数不够 `OBSTACLE_MIN_VOTES = 2`**，所以障碍层不晋升它们；
而它们的回波又不在 `|h| < tol` 里，所以 `ground_ever` 也不成立。

**回相机（`out/_deadband_look.py`，按位姿+bearing 找"当时正看着那里"的帧）：
五处最密的格，画面里全部是空旷走廊地面** —— 没有桌腿、没有柱子。

⇒ 这是地图的一个**空的第三类**：看到了、没有障碍证据、也没测到地面。

### 6.4 修法：让分类**完备**，渲染不再有自己的一套

`worldmap.GROUND_COVER_INFORMATIVE`（新，A/B 开关）：在 `add()` 里

```python
ground_ever |= seen & ~obstacle & ~object
```

语义一句话：**有信息、没有障碍证据、不是检测到的物体 ⇒ 它是地面。**
物体点必须排除 —— 障碍层对检测到的物体**故意不投票**，若从这道门放进来，
**每一个被检测器命名的椅子都会把自己的格子变成可通行**。

渲染侧同时**删掉两个画面补丁**（`RENDER_FILL_LONE_SEEN`、`RENDER_TRUST_OBSTACLE_LAYER`）：

```python
cls = zeros; cls[seen]=3; cls[seen & obstacle]=2; cls[ground]=1
```

**画面现在画的就是 `ground` —— 规划器读的同一个数组。没有任何中间层可以漂移。**

### 6.7 ⚠️ 代价：性能

`ms_map` p50 **64.3 → 93.7 ms（+46%）**、`ms_total` p50 **229 → 354 ms（+55%）**。
原因：`ground` 大了 11%，而 `free_space` 每帧要对 1200×1200 做一次腐蚀，代价跟着面积走。
真实侧不受影响（bag 驱动）；**仿真侧由探索算法驱动，帧率掉就是单位时间探索少** ⇒ 待测。
